파일 이름에 박힌 토큰(프레임 구간 `_f0105_0429`, 번호, 언어 코드 …)을 파싱해 **데이터를 생성하는 기본 경로**로 쓰지 않는다.
이름은 출력 파일 이름을 정하거나 표에 보여 주는 데만 쓴다. 값이 필요하면 UI 의 공통 설정 + 항목별 수정(표 · 매니페스트) 으로 받는다.

**Why:** A00560_JaliBatch 계획에서 예시 자료의 `_f0105_0429` 를 시작 프레임으로 읽는 Filename 모드를 기본으로 잡았더니 사용자가 정정했다
(2026-10-23): "지금 본 파일만 이런 상태다. 프레임이 이름에 없는 파일이 일반적일 수 있다. 파일 이름에 의존해서 데이터를 생성하는 것은 피해야 한다."
이름 규칙은 폴더마다 다르고, 규칙이 바뀌면 조용히 틀린 데이터가 나온다.

**How to apply:** 입력 폴더의 이름 패턴이 아무리 규칙적으로 보여도 그걸 기본 동작의 근거로 삼지 않는다. 패턴에서 값을 "제안" 하는 보조 기능이
필요하면 명시적 옵션(기본 OFF)으로 두고 사용자에게 먼저 묻는다. 계획서에 이름 파싱이 들어가면 이 메모를 근거로 다시 본다.
