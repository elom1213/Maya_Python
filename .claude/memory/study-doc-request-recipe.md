사용자가 **"공부용 문서"**, **"공부용 md 문서"**, **"공부 문서"**, **"공부 자료 정리해줘"** 라고 하면
아래 형식으로 md 를 만들어 달라는 뜻이다. 단순 요약이 아니라 **논문을 직접 찾아 쓴 학습 노트**를 원한다.

## 위치 · 번호
- **`JUN_Study` 저장소**에 만든다 (Maya_Python 아님). 도메인 대역 번호 → [[study-docs-number-prefix]]
- 파일명 `01000_영문주제.md`, 주제가 가장 가까운 문서 옆 번호로. 루트 README 목록 표에 등록.
- 주제가 크면 **문서를 쪼개고 번호를 인접**시킨다 (예: 이론 `07000` / 사례 `07100` + 상호 링크).

## 반드시 담을 것
1. **한 줄 정의** — 사용자의 실무(리깅/애니/그래픽) 언어로 번역해서 다시 한 번.
2. **용어 해부** — 단어를 낱개로 쪼개 왜 그렇게 부르는지.
3. **원리** — 수식을 피하지 말 것. Obsidian `$$` 블록 사용. 각 항이 **왜 필요한지**까지.
4. **역사** — 연표. **원논문의 저자·연도·학술지/학회·페이지**를 명시하고, 어느 분야에서 태어났는지.
5. **적용 사례** — 게임·필름·DCC 툴에서 실제로 쓰인 사례. 제품/플러그인 이름까지 구체적으로.
6. **흔한 오해** — 이름이 비슷한 다른 개념과의 구분.
7. **함께 공부하면 좋은 주제** — 표로. 각 항목에 **왜 같이 보는지** + 논문/자료 **링크**.
8. **참고문헌** — 원문 링크(PDF 직링크 우선).
9. **실무 교훈 요약** — 사용자가 바로 써먹을 수 있는 형태로.

## 조사 방법
- **WebSearch 로 실제로 찾는다. 기억으로 인용하지 않는다.**
- 가능하면 **원문 PDF 를 받아 `pdftotext -layout` 로 직독**한다(WebFetch 는 PDF 본문을 못 읽는다).
  1차 자료에서 뽑은 수식·수치·결론이 이 문서의 값어치다.
- 확신 없는 건 단정하지 말고 그렇게 표시한다. (예: Gollum 이 블렌드셰이프인 건 사실이지만 RBF 사례는 아님)

## 문체
- 본문 **한글**, 식별자·함수명·논문 제목은 **영어 원문**. → [[explain-in-korean]]
- 표를 적극 활용. 중요한 것은 굵게. 사용자의 현재 작업과 연결되는 지점은 인용 블록으로 짚어 준다.

**Why:** 2026-08-21 RBF 를 요청하며 "논문을 찾아서 / 역사·원리 / 게임·필름 적용 사례 /
함께 공부할 주제의 논문·자료 링크"를 명시했고, 앞으로 공부 문서 요청은 전부 이 규칙이라고 지정했다.
용어를 "엄밀하게" 알고 싶다는 것이 동기이므로, 개론 요약이 아니라 **1차 자료 기반**이어야 한다.

**How to apply:** 작성 후 JUN_Study 루트 README 표에 한 줄 등록하고 로컬 링크를 전수 검증한다.
푸시는 그 턴에 요청이 있을 때만 → [[push-only-when-asked]]
