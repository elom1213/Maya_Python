A00275_skinTool_V01 **Weights > Copy Weights 탭** (v01.16→**01.17**, 2026-09-07).
같은 메시 M 의 버텍스 집합을 `Copy` 로 저장해 두고, 나중에 M 의 다른 버텍스를 골라 `PASTE` 하면
그 웨이트가 실린다. 코어는 `app/core/weight_copy_manager.py`.

**"그대로" 의 정의를 먼저 못박았다.** 목표마다 **가장 가까운 소스 버텍스 하나**의 **웨이트 행
전체**를 통째로 베낀다. 섞거나 보간하지 않고 `normalize=False` 로 쓴다 — 여기서 다시 정규화하면
그것은 이미 "그대로" 가 아니다. 인플루언스가 몇 개든, 행의 합이 1 이 아니든 값이 완전히 같다.

**인플루언스를 새로 넣지 않는다** — 소스와 목표가 같은 skinCluster 라 열 구성이 이미 같다.
그래서 **한 메시 안에서만** 동작하고, 다른 메시면 어디서 복사했는지 적어 거절한다.

**★ 탐색 범위를 Expand Bind 에서 그대로 베끼면 아무 데도 못 간다**

`expand_bind_manager` 는 인접(`adjacency`)을 **저장한 집합 안으로** 가둔다 — falloff 가 영역 밖으로
새면 안 되기 때문이다(윗입술이 아랫입술로 번지는 사고 방지). 여기서는 **소스와 목표가 떨어져
있는 것이 정상**이라 같은 걸 하면 이웃이 통째로 끊긴다. 인접은 **메시 전체**로 만든다.

**세 모드(Surface / Topology / Volume)는 실제로 다른 답을 낸다**

열 간격이 넓고 세로 간격이 좁은 격자에서 같은 목표를 두고 — Surface·Volume 은 가까운 쪽,
**Topology 는 홉 수가 적은 먼 쪽**. "셋 다 가깝다" 가 아니라 재는 자가 다르다(실측).
Surface/Topology 는 메시를 걸어가므로 **떨어진 조각에는 못 닿는다** → 그 버텍스는 손대지 않고
개수를 로그에, 하나도 못 닿으면 **아무것도 쓰지 않고** Volume 을 쓰라고 알린다(조용히 모드를
바꾸면 사용자는 자기가 고른 모드의 결과로 읽는다).

**★ volume 최근접은 전수 비교를 하면 안 된다**

목표마다 소스를 전부 재면 `목표 × 소스` 다 — 22,500 정점에서 소스 5,000 / 목표 15,000 이면
순수 파이썬 **약 20초**. 소스를 **균일 격자**(셀당 소스 ~1개)에 담고 목표 주변 셀을 **한 겹씩**
넓혀 보되, **`(겹수 × 셀크기)² >= 지금까지의 최단거리²`** 가 되면 멈춘다 — 안 본 셀에는 더 가까운
점이 있을 수 없으므로 **근사가 아니라 전수 비교와 같은 답**이다(소스 3/70/400/1599 · 목표 200개
에서 거리 차 `0.0e+00`, 목표가 소스 bbox 바깥인 경우 포함). **1.00초 = 20배.**
소스가 64개 미만이면 격자 만드는 비용이 더 커서 그냥 전수 비교한다.
겹을 훑을 때 **껍질만** 본다(안쪽은 이전 겹에서 봤다). 목표가 격자 밖이어도 끝나도록
`max_ring` 을 목표 셀 기준으로 잡는다.

**재사용**: `expand_bind_manager._dijkstra_multi` 를 **공개(`dijkstra_multi`)** 로 올렸다 —
"여러 시작점에서 퍼뜨려 버텍스마다 anchor 를 얻는다" 는 같은 계산이다.
Expand Bind 동작이 안 바뀐 것을 43항목 회귀로 확인([[wip-a00275-expand-bind]]).

UI 는 [[wip-a00275-tab-reorg]] 의 `WEIGHTS_PAGES` 표에 줄 하나. 버텍스 집합은 **리스트 위젯으로
펼치지 않는다**(사용자 요청이기도 하고, Expand Bind 와 같은 이유 — 수천 개면 창이 느려진다).
검증 30항목([[mayapy-headless-verify]]). 셰이프 확정은 공용 헬퍼로([[extendtoshape-picks-wrong-shape]]),
웨이트 인덱스는 물리 인덱스로([[skincluster-weight-index-physical]]).

## Blend (v01.18, 2026-09-08)

`PASTE` 위에 `Blend` 스핀박스(0~1, 기본 **1.0**). 목표의 **원래 웨이트와 소스 웨이트 사이의
자리**다 — `새 = (1 - Blend) x 원래 + Blend x 소스`. 0.5 면 절반만 실리고 0 이면 무변화.

- **★ Blend 는 정규화를 깨지 않는다.** 합이 1 인 두 행의 **볼록결합**은 다시 합이 1 이라,
  둘 다 정규화돼 있었다면 결과도 정규화돼 있다 — `normalize=False` 를 그대로 둘 수 있다
  (여기서 마야에게 정규화를 맡기면 이미 "그대로 복사" 가 아니다).
- **Blend 가 1 이면 목표의 현재 웨이트를 아예 안 읽는다.** 전부 덮어쓸 거라 읽는 비용
  (버텍스 x 인플루언스)이 낭비다 — 기본값 경로는 v01.17 과 **값도 비용도 동일**.
- 읽는 컴포넌트를 **쓸 때와 같은 것**으로 둔다. 다르게 만들면 행 순서가 어긋나 조용히 틀린다.
- 스핀박스는 `setKeyboardTracking(False)` ([[qdoublespinbox-keyboard-tracking]]).
- 검증: blend 1.0/0.5/0.25/0.0 이 식과 **1e-12 이내** 일치 · 목표 행 합 전부 1.0 ·
  목표 밖 버텍스 무변화 · 범위 밖 클램프 · 기본값이 소스 행과 완전 동일 · UI 스모크.
