**`A00130_ControlRig_V02` 의 IK 축 맞추기** (v02.14, 2026-08-31) —
2조인트 IK 체인에서 **시작 조인트의 정해진 축이 폴 타깃을 보도록** 맞춘다.
`app/core/ik_axis_manager.py` · `ik_axis_map.json`. **Match 버튼**을 누르면 매칭 뒤에 돈다.

**★ `twist` 여야 한다** (실측으로 셋을 비교했다)

| 방법 | 결과 |
|---|---|
| `jointOrient` 를 돌린다 | **안 바뀐다** — RP 솔버가 월드 방향을 맞추려 `rotate` 로 보정해서, 어느 로컬 축이 폴을 보는지가 그대로다 |
| `rotate` 에 쓴다 | **쓰면 안 된다** — 솔버가 매 평가마다 덮어쓴다 |
| **`twist`** | `0`→`-Y`, `90`→`+Z`, `180`→`+Y`, `-90`→`-Z` 로 **정확히 돈다** |

**★ 레퍼런스에서 유지된다** — `twist` 는 핸들의 평범한 어트리뷰트라 파일에 저장된다.
**원본·레퍼런스·임포트·재오픈 넷 다 같은 축**이고 `jnt_01.rotate` 도 같다.
`rotate` 로 고쳤다면 바로 이 조건이 깨진다(솔버가 다시 풀면서 덮어쓴다).

**기준축을 가정하지 않는다** — 기본이 `-Y` 라는 것은 실측이지만, "그러니 `+Z` 로 가려면
90 을 더한다" 로 짜면 체인 방향이나 마야 버전이 달라질 때 **조용히 틀어진다.**
대신 **지금 각도를 재서 더하고, 다시 재서 남은 오차를 보고한다.** 부호가 반대면 반대로
한 번 더 시도한다. 스스로 맞춰 가므로 기준이 무엇이든 상관없다.

**IK 세션이 끝난 뒤에** 돈다 — 그때라야 핸들과 폴 벡터가 새 체인에 맞춰져 있어 잰 각도가
뜻을 갖는다([[wip-a00130-ik-session]]).

**세트는 목록**이다(`ik_axis_map.json`). 지금은 `D02_IK_handle_axiesUpadate : +Z` 하나뿐이지만
코드는 개수를 모르고 **세트마다 다른 축**을 준다. 회귀에 세트 2개짜리를 넣어 뒀다.
