A00170_driverTool **`Seal` 탭** (v01.15→**01.21**, 2026-08-13). 계획서: `docs/plans/A00170_Seal_plan.md`.
AttachCrv > Edge Loop 로 만든 위/아래 입술 리그를 **지퍼처럼** 다문다.

**구조** (v01.20): 다물리는 자리는 **빌드 시점 포즈(rest)** 다. 널마다 rest 를 `Reference`
(머리 조인트, 비우면 널의 부모) 공간에 상수 행렬로 저장하고, 위/아래 **쌍을 통째로** 만남점까지
평행이동한다 — `목표_i = rest_i + (lerp(아래,위,sealBias)_live − 같은 lerp_rest)`, 회전은 rest 그대로.
조인트별 가중치 `w = clamp01( ramp(sealR - u(1-band)) + ramp(sealL - (1-u)(1-band)) )` 를
**기존 `decomposeMatrix → null.translate` 사이에 끼운 `pairBlend`** 의 weight 로 쓴다.
`sealR`/`sealL` 이 독립이라 양 끝에서 중앙으로 동시에 닫힌다.
`sealMerge` 0 = rest 간격(입술 두께) 유지(기본) / 1 = 위·아래가 **정확히 한 점**(v01.19 동작).
`recapture_rest()`(UI **Update Rest Pose**) = sealR/sealL 을 잠깐 0 으로 내려 지금 포즈를 다시 rest 로.

**설계 판단**
- 조인트를 건드리지 않고 **널 단계**에서 해결한다 — 조인트는 널을 따라가므로 스킨까지 그대로 온다.
- `pairBlend` 를 쓴 이유: translate/rotate 를 한 노드에서 가중 블렌드하고, **끼웠다 빼기가 쉽다**
  (Remove 가 in1 의 소스를 다시 널에 이어 준다). 2023 에도 있다([[maya-2023-compat]]).
- band 를 라이브로 두려고 `1-band` 를 한 번만 만들어 모든 쌍이 공유한다.
- 생성 노드를 `<prefix>_seal_SET` 에 담아 Remove 가 정확히 되돌린다.

**입력은 아무거나 받는다** (v01.17): 널 / `_con`·`_ctl`·`_tgt` / 조인트 / `null_grp` 그룹 /
**어태치 커브**. `_ctl` 을 담았을 때 0개로 나오던 게 실제 버그였다 — DAG **조상**을 안 봤다.
커브에서 찾을 때 POCI 바로 아래는 transform 이 아니라 fourByFourMatrix 라 `listHistory(future=True)`
로 하류 전체를 훑어야 한다.

**짝짓기** (v01.17): 위/아래 위치가 같을 필요 없다. **전역 1:1 배정**(가까운 후보부터, 쓰인 노드는
건너뜀) + 척도 선택(커브 파라미터 |Δu| / 월드 거리) + `tolerance` 초과 시 미짝 보고.

**회전** (v01.18 도입 → v01.20 교체): `pairBlend.inRotate1/2` + `rotInterpolation=1`(쿼터니언)은
그대로지만, **목표 회전이 그 널 자신의 rest 회전**이다 — "다물린 후 회전 = 다물리기 전 회전".
회전을 구동받지 않는 널(Orient 없이 만든 Edge Loop)은 이미 유지되므로 건너뛰고 개수를 로그로 보고.

**두 널을 같은 행렬에 붙이면 안 된다** (v01.19 까지의 실제 버그, 사용자 보고):
`blendMatrix` 로 위/아래 어태치 행렬을 섞어 **양쪽이 같은 목표**를 쓰면 ① 위치가 완전히 겹치고
② 위/아래 커브 프레임이 **반대**일 때(한 바퀴 감는 커브에서 흔함) 중간 회전이 **90° 틀어진다** —
실측 `x=(1,0,0)` / `x=(-1,0,0)` → 섞으면 `x≈(0,0,1)`(월드 x 를 보던 널이 월드 z 를 봄).
쌍의 **차이(rest 오프셋)를 보존**하고 **이동량만 공유**하면 둘 다 사라진다.

**커브 하나가 입술을 한 바퀴 감을 때** (v01.19): 위/아래가 **같은 커브**를 쓰면 각 입술이 차지한
**원형 구간**을 찾아 그 안에서 u 를 다시 0~1 로 편다. 구간 찾기 = **"가장 큰 빈틈 다음이 시작"**
(씸이 입술 한가운데여도 한 덩어리). 두 구간 사이 **빈틈 = 입꼬리**라 절반씩 늘려 u=0/1 을 입꼬리에 둔다.

**함정**
- **커브 전체 기준 u 는 닫힌 커브에서 지퍼를 죽인다.** 실측(널 16개 링): 윗입술 u 가
  `0.81 0.87 0.94 | 0.0 0.06 0.12 0.19` 로 갈라지고 지퍼 위치가 왼쪽 전부 0.25 · 오른쪽 전부 0.75 로
  뭉쳐 **동시에** 닫혔다. 씸을 입꼬리로 오인해 입술 중앙 널이 스킵되기도 했다.
- **같은 널이 Upper·Lower 양쪽에 있으면 자기 자신과 짝이 되어 `pairBlend` 가 두 번 끼워지고 사이클**.
  닫힌 커브의 입꼬리에서 흔하니 양쪽에 있는 노드는 코너로 보고 빼낸다.
- **다물리는 자리를 널의 `worldMatrix` 로 만들면 사이클**이다(그 널을 다시 구동하므로).
  널보다 **상류**인 어태치 `fourByFourMatrix.output` 을 쓴다.
- **`u` 를 생성 순서로 잡으면 지퍼가 뒤집힌다.** Edge Loop 가 만든 `up_null_01..09` 의 커브
  파라미터가 이름 순서와 **역순**이었다(실측). POCI `.parameter` 를 `minValue/maxValue` 로 정규화하고,
  위/아래 커브 방향이 반대면 월드 축 기준으로 뒤집어 맞춘다.
- `blendColors` 의 출력 성분은 **`outputR/G/B`** 다(X/Y/Z 아님).
- 코너(입 끝)는 두 입술이 공유하므로 기본 제외.
- **머리 회전/이동 대응은 저장 공간이 결정한다.** rest 를 월드로 저장하면 머리를 돌릴 때 얼굴을
  안 따라간다. 기준 공간에 담고, 이동량도 **머리에 붙은 두 점의 차**로 만들면 따로 회전시킬 필요가 없다.
  기준 공간이 틀려도 **커브가 끌고 가는 만큼은 움직여서** 완전히 멈추지 않는다 — "안 움직이면 버그"가
  아니라 **정답 자리와 다르면** 버그다(실측: 머리 30° 에서 `(-0.26,-0.05)` vs 정답 `(-0.310,-0.063)`).
- **선택 입력은 "언제 채워야 하는지" 툴이 말해야 한다** (v01.21): 커브를 움직이는 것(스킨 인플루언스 /
  컨스트레인트 타깃)을 찾아 널들이 그 DAG 밑에 없으면 그 조인트 이름까지 넣어 경고. 막지는 않는다.
- Update Rest Pose 는 **전부 읽은 뒤에 쓴다** — 하나 쓰면 그 널이 바로 움직인다([[setkeyframe-insert-needs-existing-curve]] 와 같은 결).
  rest 노드↔널은 `message` 표식(`sealRestNull`/`sealRestRef`, 세트엔 `sealController`)으로 되찾는다.
