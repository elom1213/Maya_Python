# Changelog — A00410_SecondaryMotion

## v01.01 (2026-07-29)

- **[Fix] FK 컨트롤러 체인에서 원래 포즈가 보존되지 않던 문제** — 회전 재구성이 각 노드의 DAG 부모를
  **바로 앞 체인 노드라고 가정**하고 있었다. 조인트 체인은 맞지만 FK 리그는 보통
  `ctl_01 > ctl_01_offset > ctl_02` 처럼 **중간에 오프셋 그룹**이 껴 있어서, 그 그룹의 회전이
  컨트롤러 로컬값에 그대로 구워졌다. 그 결과 스윙이 0 인 **첫 프레임부터** `ctl_02` 이하의 원래 포즈가
  깨지고 하위 컨트롤러가 통째로 어긋났다.
  - 이제 각 노드의 **실제 DAG 부모** 월드 회전을 프레임마다 샘플링하고
    (`ChainSample.parent_quats` 를 노드별로 확장), 앞 체인 노드의 월드 델타를 물려준
    `parent_orig[i] * q_swing[i-1]` 를 부모로 삼는다. 부모가 곧 앞 체인 노드인 경우
    (조인트 체인)에는 기존과 완전히 같은 결과라 **무회귀**다.
  - 재현/검증: 오프셋 그룹(회전 11,-7,23)이 낀 3단 FK 체인에서 첫 프레임 기록값이
    `[11,-7,23]` → **원본 `[0,0,0]` 로 교정**, 하위 자식까지 `blend=0` 오차 5.8e-15,
    시작 프레임 위치 오차 0.
- **[Add] 마지막 노드도 회전 — `Rotate last node (dummy bone)`** (기본 켜짐) — 팁은 자식이 없어
  방향을 정의할 수 없다는 이유로 v01.00 에서 제외했었다. 이제 KawaiiPhysics 의 dummy bone 처럼
  **마지막 뼈를 같은 방향/길이로 한 번 더 연장한 가상 점**을 붙여 팁도 회전하고 키를 받는다.
  끄면 v01.00 동작(팁 제외)으로 돌아간다.
  - 가상 점이 체인 길이에 포함되므로 falloff 분모가 `n` 으로 바뀐다 → 같은 파라미터라도
    v01.00 과 결과가 미세하게 다르다(의도된 변경).
  - 검증: 빠른 구동에서 팁 `ctl_03` 이 f16 에 17.55° 회전(중간 노드 1.89°), 끄면 기존처럼 제외.
- **[Add] 셸프 아이콘** `icon/A00410_SecondaryMotion.svg` → `dev/build_icons.py` 로 32x32 PNG.
  휘어지며 팁이 되감기는 **구슬 체인**(루트만 채운 원 = 부모에 100% 구동). 32px 가독성을 위해
  요소를 2개로 줄였다 — 점선 고스트는 스페클로 깨지고, 세로 rest 선은 루트 구슬에 붙어 '핀/손잡이'로
  읽혀서 뺐다(이웃 아이콘들과 굵기·톤 비교 후 결정).

> 알려진 수치 오차: 빠른 구동 + `Substeps=3` 케이스에서 솔버 위치 대비 실제 씬 위치의 왕복 오차가
> **4.7e-05**(리그 스케일 대비 약 3ppm) 관측된다. 느린 구동은 4.7e-12, 조인트 체인은 6.2e-08 이라
> 구조적 오류는 아니며, 키 기록 경로(addKeys/setValue) 양쪽이 동일한 값이라 기록 문제도 아니다.
> **원인은 특정하지 못했다.** 실사용에서 보이는 수준이 아니다.

## v01.00 (2026-07-29)

신규 툴. FK 로 애니메이션된 **컨트롤러/조인트 체인**에 언리얼 KawaiiPhysics 식 **관성(2차 모션,
찰랑임)** 을 얹어 **키 애니메이션으로** 굽는다. 마야의 시뮬레이션 솔버(nucleus 계열)를 쓰지 않는다.

- **[Add] 경량 위치기반 스프링 솔버** (`app/core/chain_solver.py`, **maya 비의존 순수 파이썬**)
  - 베를레 속도 + 감쇠 → 원본(강체 FK) 위치로 당기는 스프링 → **길이 구속** → **각도 제한** 순.
  - **Falloff** 가 관성 다이얼: `stiffness_i = stiffness * (1 - falloff * i/(n-1))` 로
    **루트에서 먼 노드일수록 덜 따라가** 뒤처진다.
  - 구간 시작에서 항상 정지 상태로 출발하는 **결정적** 솔버 — 스크럽/되감기와 무관하게 같은 결과.
  - fps 보정(`1-(1-x)^(24/fps)`)으로 24/30/60fps 에서 체감을 맞춘다.
- **[Add] 회전 재구성** (`app/core/pose_builder.py`) — 점 시뮬 결과를 각 노드의 로컬 회전 키로 되돌린다.
  - `q_swing = MQuaternion(rest_dir, sim_dir)` 이 **순수 스윙**이라 원본의 **트위스트(롤)가 보존**된다.
  - 솔버가 길이를 구속했으므로 부모를 회전시키면 자식이 **정확히** 시뮬 위치에 놓인다(체인이 안 벌어짐).
  - 프레임마다 독립적으로 뽑은 오일러를 **언랩**해 ±180 경계에서 커브가 튀지 않게 한다.
- **[Add] Controller / Joint(direct) 대상 타입** — 마야 검증 규칙에 따라 로컬 회전을 정확히 되돌린다.
  - joint: `local = R * JO` → `R = L * JO⁻¹` (**jointOrient 를 벗겨내야** 조인트 모드가 맞는다)
  - transform: `local = RA * R` → `R = RA⁻¹ * L`, 공통 `world = local * parentWorld`
  - 노드별 **rotateOrder** 를 존중한다. 계층 탐색도 타입에 맞춰 제한(joint / transform).
- **[Add] List order / Hierarchy 체인 해석** — 리스트 순서를 그대로 체인으로 보거나, 각 항목을 루트로
  보고 자손을 따라간다. 분기가 있으면 루트→말단 경로마다 체인으로 쪼개고 **가장 긴 체인이 공유 노드를
  소유**한다(중복 기록 방지, 로그로 안내).
- **[Add] Live Preview** — 파라미터가 바뀌면 **구간 전체를 다시 풀어** 프리뷰 override 애님 레이어
  (`SM_preview_LYR`)에 통째로 다시 기록한다(40ms 디바운스). 재생은 그냥 커브 재생이라 **실시간**이고,
  런타임 시뮬이 없어 스크럽·역재생이 자유롭다.
- **[Add] 출력 2종**
  - **Override Layer**(기본): 절대 회전값을 override 애님 레이어에 기록 → 원본 애니 보존,
    **레이어 weight 로 강도 조절**, 레이어만 지우면 원상복구. 프리뷰 레이어를 그대로 최종 레이어로
    **승격(rename)** 하므로 Apply 시 재계산이 없다.
  - **Bake Keys**: 구간의 기존 키를 지우고 노드 커브에 직접 굽는다(undo 가능한 `cmds.setKeyframe` 경로).
- **[Perf] 샘플링은 한 번, 솔브는 매번** — 프레임별 원본 포즈를 한 번만 읽어 캐시하고, 이후 파라미터
  변경은 캐시로부터 솔브+기록만 한다. 프리뷰 갱신에 `MFnAnimCurve` 벌크 API 를 쓴다.

### 검증 (mayapy 헤드리스 22항목 전부 통과)

- 길이 구속 오차 `2.2e-15`, 루트는 드라이버 그대로, 각도 제한 준수.
- **관성**: 팁으로 갈수록 원본 대비 편차가 단조 증가(0.59→1.04), 즉발 회전 입력에서 응답 지연이
  루트 0 → 팁 2프레임으로 증가.
- **조인트 모드 왕복** — 비자명 jointOrient + rotateOrder 6종 혼합 체인에서, 기록된 회전으로 계산된
  실제 씬 위치가 솔버 결과와 오차 **9.7e-13** 으로 일치.
- **컨트롤러 모드 왕복**(비자명 rotateAxis 포함) 오차 **5.4e-12**.
- `Blend=0` 이면 씬이 원본과 완전히 동일(무회귀), 프리뷰 제거 시 원본 복귀.
- 레이어 승격 / weight 강도 조절 / 키 굽기 정상.

> **마야 실기(UI) 테스트는 대기 중.** mayapy 안에서는 `maya.standalone` 이 `QGuiApplication` 을
> 선점해 `QWidget` 을 만들 수 없어 UI 는 헤드리스로 띄울 수 없다(코어는 위와 같이 전부 검증됨).
