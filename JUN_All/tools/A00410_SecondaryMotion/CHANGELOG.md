## v01.05 (2026-09-09)

- **[Add] `Stiffness` · `Damping` · `World Damp` 옆 `Graph` 버튼** — 값을 **체인 위치에 따라**
  조절하는 커브 팝업이 뜬다.
  - 커브의 **가로축 = 체인 루트(왼쪽) -> 팁(오른쪽)**, **세로축 = 그 자리에서 값에 곱할 배수**.
    기본은 처음부터 끝까지 **1.0** 이라 아무것도 바뀌지 않는다.
  - 예: `Stiffness 0.5` + 커브 왼쪽 1.0 / 오른쪽 0.1(선형) → 체인 시작은 뻣뻣하고 끝으로
    갈수록 뻣뻣함이 사라진다. 실측(6본): 팁 쪽 흔들림이 **14.4배**, 루트 쪽은 3.8배로
    **끝으로 갈수록 효과가 커진다**.
  - 팝업은 **비모달**이라 띄워 둔 채 슬라이더를 만질 수 있고, `Live Preview` 가 켜져 있으면
    커브를 드래그하는 동안 결과가 바로 갱신된다. `Reset` 으로 평평한 1.0 복귀.
  - 커브가 걸린 파라미터는 버튼이 **`Graph *`** 로 바뀐다 — 창을 닫아도 걸려 있는 것이 보인다.
  - `Interpolation`(None/Linear/Smooth/Spline)과 `Curve presets`(Linear/Smooth/Ease In/
    Ease Out/Spike/Solid)는 `A00275_skinTool_V01` Expand Bind 의 것을 **그대로** 쓴다.
- **[Change] 커브 UI 를 Framework 공용 위젯으로 승격** —
  `Framework/qt/MOD_falloffCurve_qt_v01.py`(`JUN_mod_falloffCurve_qt`) +
  모델 `Framework/core/falloff_curve.py`. `A00275_skinTool_V01` 도 이 공용 위젯을 쓰도록 옮겼다
  (`app/core/falloff.py` · `app/ui/falloff_curve_widget.py` 삭제).
- **[Change] `SolverParams.stiffness_curve` / `damping_curve` / `world_curve`** — 각각
  `(points, interp)` 또는 `None`. 계산은 `stiffness_i = stiffness * curve(u) * (1 - falloff*u)`,
  `damping_i = damping * curve(u)`, `world_i = world_damping * curve(u)` (u = i/(n-1)).
  - **fps 보정은 커브를 곱하기 전 기본값에** 건다 — 계산 순서를 예전 그대로 두어야 커브가
    평평할 때 24fps 아닌 씬에서도 결과가 안 바뀐다.
  - 커브는 **노드마다 한 번만** 평가해 배열로 들고 간다(솔버 안쪽은 프레임 x 노드 x 서브스텝
    이라 거기서 커브를 부르면 비싸다).
  - UI 는 커브가 평평하면 `None` 을 넘긴다 — "커브를 안 건드린 상태 = 예전과 같은 계산".

## v01.04 (2026-09-09)

- **[Add] `Loop (cycle the range)` 체크박스** — 켜면 결과가 **루프**가 된다. 구간의 마지막 프레임이
  첫 프레임으로 **이음매 없이** 이어지므로, 사이클 애니메이션(걷기 · 대기 · 깃발)에 2차 모션을 얹어도
  루프가 깨지지 않는다.
  - **방법**: 같은 구간을 여러 바퀴 이어 붙여 미리 돌리고(pre-roll) **마지막 한 바퀴만** 쓴다.
    스프링의 과도응답이 바퀴마다 기하급수로 줄어 **정상상태(limit cycle)** 가 되므로, 첫 프레임과
    마지막 프레임의 흔들림 상태가 같아진다.
  - **이어 붙이는 방식이 요점**: `targets[:-1] * (n-1) + targets` — 마지막 바퀴의 목표열이 원본과
    **정확히 같아야** 잘라낸 구간의 f 번째가 원본 f 번째 프레임과 1:1 로 맞는다.
  - 몇 바퀴가 필요한지는 감쇠에 따라 다르므로 **이음매 오차를 재서 닫힐 때까지** 2 -> 4 -> 8 -> 16
    으로 늘린다. 닫히면 로그에 `Loop: cycled after 2 pre-roll pass(es), seam error 0.000000.`
  - **전제**: 원본 애니메이션 자체가 순환해야 한다(첫 프레임 포즈 == 마지막 프레임 포즈).
    아니면 경고한다 — `Loop: the first and last frame of the range are NOT the same pose (off by ...)`.
  - **첫 프레임은 더 이상 원본과 같지 않다.** 정지 상태로 출발하지 않고 이미 흔들려 있는 상태에서
    시작하기 때문이며, 그것이 루프가 되는 조건이다(회전이 0 이던 컨트롤러가 0 이 아니게 된다).
- **[Change] 이음매 허용 오차를 체인 길이의 1e-6 로** (처음엔 1e-4) — **위치 오차는 회전 오차보다
  관대해 보인다.** 1e-4 에서는 위치 이음매가 허용 오차 안이었는데도 회전 키가 **0.05deg** 벌어졌다
  (체인을 내려가며 부모의 스윙 델타가 누적된다). 한 바퀴 더 도는 비용이 싸므로 애초에 조였다.
- **[Change] `SolverParams.loop`** 추가. `solve()` 는 `loop=True` 면 `solve_loop()` 로 넘긴다
  (본체는 `_solve_once`) — 호출부는 루프 여부를 몰라도 된다.
- **[Add] `SecondaryMotionSession.loop_report()`** — 체인별 `LoopInfo` 를 **가장 나쁜 값 기준 한 줄**로
  모아 UI 로그에 낸다(체인마다 줄이 늘면 로그가 안 읽힌다).

### 성능 (mayapy, Maya 2024, 20본 x 300프레임)

| 단계 | Loop OFF | Loop ON |
|------|----------|---------|
| solve | 0.034 s | 0.048 s (2바퀴) |
| 프리뷰 1회(솔브+회전+키 기록) | 0.043 s | 0.054 s |

루프를 켜도 **프리뷰는 그대로 실시간**이다. 수렴이 늦은 설정에서만 바퀴 수가 늘어난다.

### 검증 (mayapy 헤드리스, Maya 2024 — 25개 항목 전부 통과)

- 조인트 체인 6본 x 0~100f(순환 애니): **회전 키 0f == 100f (차 0.000000deg)**, Loop OFF 는 1.484deg.
- Bake Keys 후 **씬 실측** 0f vs 100f — 월드 위치 차 0.000000, 월드 회전 차 **0.000002deg**.
- 컨트롤러(오프셋 그룹 낀 계층) + Override Layer 경로도 씬 실측 **0.000003deg**.
- 길이 구속이 루프에서도 유지된다(회전 재구성의 전제) · `solve(loop=True)` 가 `solve_loop` 로 디스패치.
- 순환하지 않는 입력 → 경고. `damping=0` 처럼 **과도응답이 사라지지 않는 설정** → 16바퀴까지 돌고
  닫히지 않았음을 정직하게 알린다(결과는 최선의 시도로 기록).
- **Loop OFF 무회귀**: 기본값이 False, 결과가 예전과 동일, 첫 프레임 = 원본 로컬 회전.

## v01.02 (2026-07-30)

- **[Add] `Bone Chain` / `Bone Root` 모드** — `A00390_WindTool` 과 같은 어휘/개념으로 정리했다.
  기존 `Chain From: List order / Hierarchy` 를 `Mode: Bone Chain / Bone Root` 로 바꿨다.
  - **Bone Chain**(기본): 리스트업한 노드들이 **하나의 체인**(리스트 순서 = 루트→팁). 기존 동작.
  - **Bone Root**: 리스트업한 **각 노드를 임의의 체인의 최상위 부모**로 보고, 그 자손을 따라
    루트마다 체인을 만든다 → **여러 체인을 한 번에** 처리한다. 분기는 루트→말단 경로마다 체인이 되고
    공유 구간은 가장 긴 체인이 소유한다.
  - core 상수 `MODE_LIST` → **`MODE_CHAIN`**(예전 이름은 별칭으로 남겨 호환).
- **[Fix] Bone Root + Controller 에서 오프셋 그룹이 체인에 섞이던 문제** — 계층 탐색이 transform 을
  전부 담아서 `[ctl_01, ctl_02_offset, ctl_02, ctl_03_offset, ctl_03]` 처럼 잡혔다. 그룹에 키가 찍히고
  체인 길이가 배로 늘어 **falloff 도 어긋났다**.
  - 이제 그룹은 **지나가되 담지 않는다** — 셰이프를 가진 노드(=컨트롤)만 체인 노드가 된다
    (`_is_control`, nurbsCurve/로케이터/메시 컨트롤 모두 인식). 검증: `[ctl_01..ctl_04]` 만 잡힘.

## v01.00 (2026-07-29)

신규 툴. FK 로 애니메이션된 **컨트롤러/조인트 체인**에 언리얼 KawaiiPhysics 식 **관성(2차 모션,
찰랑임)** 을 얹어 **키 애니메이션으로** 굽는다. 마야의 시뮬레이션 솔버(nucleus 계열)를 쓰지 않는다.

- **[Add] 경량 위치기반 스프링 솔버** (`app/core/chain_solver.py`, **maya 비의존 순수 파이썬**)
  - 베를레 속도 + 감쇠 → 원본(강체 FK) 위치로 당기는 스프링 → **길이 구속** → **각도 제한** 순.
  - **Falloff** 가 관성 다이얼: `stiffness_i = stiffness * (1 - falloff * i/(n-1))` 로
    **루트에서 먼 노드일수록 덜 따라가** 뒤처진다.
  - 구간 시작에서 항상 정지 상태로 출발하는 **결정적** 솔버 — 스크럽/되감기와 무관하게 같은 결과.
  - fps 보정(`1-(1-x)^(24/fps)`)으로 24/30/60fps 에서 체감을 맞춘다.
- **[Add] 회전 재구성** (`app/core/pose_builder.py`) — 점 시뮬 결과를 각 노드의 로컬 회전 키로 되돌린다.
  - `q_swing = MQuaternion(rest_dir, sim_dir)` 이 **순수 스윙**이라 원본의 **트위스트(롤)가 보존**된다.
  - 솔버가 길이를 구속했으므로 부모를 회전시키면 자식이 **정확히** 시뮬 위치에 놓인다(체인이 안 벌어짐).
  - 프레임마다 독립적으로 뽑은 오일러를 **언랩**해 ±180 경계에서 커브가 튀지 않게 한다.
- **[Add] Controller / Joint(direct) 대상 타입** — 마야 검증 규칙에 따라 로컬 회전을 정확히 되돌린다.
  - joint: `local = R * JO` → `R = L * JO⁻¹` (**jointOrient 를 벗겨내야** 조인트 모드가 맞는다)
  - transform: `local = RA * R` → `R = RA⁻¹ * L`, 공통 `world = local * parentWorld`
  - 노드별 **rotateOrder** 를 존중한다. 계층 탐색도 타입에 맞춰 제한(joint / transform).
- **[Add] List order / Hierarchy 체인 해석** — 리스트 순서를 그대로 체인으로 보거나, 각 항목을 루트로
  보고 자손을 따라간다. 분기가 있으면 루트→말단 경로마다 체인으로 쪼개고 **가장 긴 체인이 공유 노드를
  소유**한다(중복 기록 방지, 로그로 안내).
- **[Add] Live Preview** — 파라미터가 바뀌면 **구간 전체를 다시 풀어** 프리뷰 override 애님 레이어
  (`SM_preview_LYR`)에 통째로 다시 기록한다(40ms 디바운스). 재생은 그냥 커브 재생이라 **실시간**이고,
  런타임 시뮬이 없어 스크럽·역재생이 자유롭다.
- **[Add] 출력 2종**
  - **Override Layer**(기본): 절대 회전값을 override 애님 레이어에 기록 → 원본 애니 보존,
    **레이어 weight 로 강도 조절**, 레이어만 지우면 원상복구. 프리뷰 레이어를 그대로 최종 레이어로
    **승격(rename)** 하므로 Apply 시 재계산이 없다.
  - **Bake Keys**: 구간의 기존 키를 지우고 노드 커브에 직접 굽는다(undo 가능한 `cmds.setKeyframe` 경로).
