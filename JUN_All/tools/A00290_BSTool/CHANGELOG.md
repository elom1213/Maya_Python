## v01.17 (2026-08-06)
**Mix Targets 탭 신규** — 소스 타겟 몇 개를 원하는 비율로 섞은 만큼, 체크한 다른 타겟들
(과 원하면 최종 메시까지)을 한꺼번에 변형한다.

- **[Add] Mix Targets 탭** — 예) 소스 `[a x1.0, b x0.5, c x0.8]` → 체크한 타겟들이 그 셋을 그
  비율로 섞은 모양만큼 변형된다. `new_delta = old_delta + Σ(amount × delta(source))`.
  - **Mix Sources**(왼쪽): 체크 + 배율. 목록에서 고르고 `Set to Selected` 로 배율을 찍으면
    체크되고 이름 옆에 `x0.5` 로 표시된다. **Use Scene Weights** 로 씬의 현재 weight 를 그대로
    배율에 채울 수 있다(마야에서 눈으로 맞춘 상태를 그대로 굽기).
  - **Targets to Modify**(오른쪽): 체크박스 목록 + **`Check All (visible)` 체크박스 하나**로
    지금 보이는 행 전부 켜기/끄기(부분 체크는 부분 표시).
  - 소스로 체크한 타겟은 오른쪽에서 **회색으로 잠긴다** — 소스는 절대 수정되지 않는다.
  - 목록마다 공용 Filter. **이 탭만 "체크된 것이 작업 대상"** (다른 탭의 "보이는 것이 작업 대상"과

  - `Leave it alone`(기본) : 베이스는 그대로, 체크한 타겟만 변형.

## v01.16 (2026-08-06)
Base Shape 탭 — **Apply 가 일부 정점만 반대로 스케일하던 문제** 수정.

- **[Fix] 값 0.5 를 넣었는데 어떤 정점은 절반, 어떤 정점은 1.5 를 넣은 것처럼 커지던 문제**
  — live 타겟(타겟 메시가 씬에 남아 연결된 경우)에서 델타를 **잘못된 공간**으로 적용했다.
  - **원인** (mayapy 실측): 델타가 어느 공간에 있느냐는 blendShape 의 **`origin`** 이 정한다.
    `origin=1`(local) 이면 타겟 오브젝트 공간이지만, **`origin=0`(world) 이면 베이스 오브젝트
    공간**이다. v01.15 까지는 항상 오브젝트 공간이라고 보고 델타를 그대로 이동량으로 썼다.
    그래서 타겟과 베이스의 transform 이 다르면(좌우 대칭 타겟의 `scaleX = -1`, FBX 임포트의
    `rotateX -90`, 프리즈된 복제본 …) **어긋난 축의 정점만 반대로** 움직였다. 미러라면 X 로
    움직인 정점만 뒤집히고 Y/Z 정점은 멀쩡해, 정점마다 되기도 하고 안 되기도 한 것처럼 보였다.
  - **해결**: `origin=world` 면 델타를 `base.worldMatrix × target.worldMatrix⁻¹` (3×3 부분)로
    **타겟 오브젝트 공간으로 되돌린 뒤** 이동한다. `origin=local` 은 종전대로 그대로 쓴다.
  - **[Add] 적용 후 자체 검증 + 자가 보정** — 옮긴 뒤 델타가 정말 X 배가 됐는지 **정점 번호로**
    대조한다(스케일 후 걷어내진 델타에 속지 않게). 어긋나면 되돌리고, 타겟 정점을 x/y/z 로 한 번씩
    밀어 **응답 행렬을 직접 재서** 다시 시도한다. 그래도 안 맞으면 **타겟 메시를 원상복구**하고
    로그에 이유를 남긴다 — 조용히 틀린 모양을 만들지 않는다.
  - baked 타겟(델타만 노드에 굽힌 경우)은 벡터를 그대로 X 배 하므로 공간과 무관하다 — 영향 없음.
- **[Verify]** mayapy 2024 실측 —
  - 공간 조합 11종: 타겟 rotZ90 / scale(2,1,1) / **scaleX -1(미러)** / translate / 베이스 rotZ90 /
    베이스·타겟 모두 임의 변환 / origin=local ± 회전 / 인비트윈 / 히스토리 있는 타겟
    → 수정 전 **6종 실패**(미러는 정확히 ratio +1.5 = 사용자 증상), 수정 후 **전부 통과**.
  - 스킨 걸린 리깅 메시 6종(스킨 베이스, 스킨 타겟, skin→blendShape 순서, 회전 그룹 밑 베이스,
    프리즈된 타겟) 전부 통과. 흩어진 40정점 · 압축된 컴포넌트 목록(`vtx[23:25]` …)의 인덱스 매핑도 확인.
  - 안전망: 계산 행렬을 일부러 틀리게 줘도 **폴백이 결과를 맞추고**, 검증을 강제로 실패시키면
    **델타·정점이 모두 원상복구**되고 done=0 + 사유가 보고된다.

## v01.15 (2026-08-06)
Shape Editor 탭 — **weight 값을 숫자로 타이핑할 때 0 이 자동으로 채워지던 문제** 수정.

- **[Fix] 타이핑 도중 값이 확정되며 입력이 잘리던 문제** — `0.123` 을 치려고 `0.1` 까지만 쳐도
  칸이 `0.100` 으로 다시 써져 뒤 자릿수를 이어 칠 수 없었다. `0.` 만 쳐도 `0.000` 이 됐다.
  이제 **친 그대로 남고**, **Enter 또는 포커스 아웃(다른 곳 클릭)에서 한 번만 확정**된다.
  - **원인** (PySide2 실측): `QDoubleSpinBox` 는 기본이 keyboard tracking **ON** 이라 키를 누를
    때마다 값을 확정하고, 확정할 때마다 편집 중인 텍스트를 **소수점 자릿수에 맞춰 다시 쓰며
    커서를 옮긴다**(`interpretText` → `updateEdit`). 우리 `valueChanged` 핸들러가 되부르는
    `_show_weight` 의 `setValue` 도 같은 일을 한 번 더 한다.
  - **해결**: 타겟 행 스핀박스에 `setKeyboardTracking(False)` — **확정은 Enter/포커스 아웃에서
    한 번만**. 더해서 `_show_weight` 가 **포커스를 가진(= 지금 타이핑 중인) 스핀박스는 건너뛴다**
    — 다중 편집이나 120ms 폴링이 끼어들어도 편집 중인 칸을 덮어쓰지 않는다.
  - 슬라이더 드래그, 다중 선택 동시 편집, 화살표/휠 스텝은 종전과 동일하게 즉시 반영된다.
  - **[Verify]** mayapy 2024 / PySide2 offscreen 실측 — `"0.123"` 타이핑 시
    tracking ON = 텍스트 `'0.100'` · 값 `0.1`(증상 재현, `_show_weight` 가드만으로는 그대로),
    tracking OFF = 텍스트 `'0.123'` · 값 `0.123` · `valueChanged` **1회**(Enter 시).
    `"0."` 까지만 친 상태에서는 텍스트 `'0.'` 유지 · 시그널 없음.

## v01.14 (2026-08-06)
Shape Editor 탭 — **키가 걸린 타겟의 슬라이더가 실제로 먹지 않던 문제** 수정.

- **[Fix] 키(animCurve)가 걸린 타겟을 슬라이더/스핀박스로 조절해도 아무 일도 일어나지 않던 문제**
  — 값이 표시만 되고 메시는 꿈쩍하지 않았고, 손을 떼면 슬라이더가 애니메이션 값으로 튕겨
  돌아왔다. 이제 **키가 걸려 있어도 바로 조절**되고, **Auto Keyframe 이 켜져 있으면 조절한 값이
  그대로 현재 프레임의 키**가 된다(이미 키가 있으면 그 키를 갱신).
  - **원인** (mayapy 실측): v01.07 의 키 타겟 경로는 Auto Key 가 켜져 있으면 `setKeyframe`
    **하나만** 냈는데, `setKeyframe` 은 커브에 키를 넣을 뿐 **그 자리에서 plug 값을 갱신하지
    않는다**(시간이 다시 흐르거나 강제 재평가가 있어야 반영). 그래서 드래그하는 동안 뷰포트가
    변하지 않고, 120ms 폴링이 옛 값을 되읽어 위젯을 되돌렸다.
  - **해결**: 키를 찍은 뒤 **`setAttr` 로 값을 즉시 반영**한다. 키 걸린 plug 에 대한 `setAttr` 은
    (연결돼 있어도) 에러 없이 값을 바꿔 주며, 두 값이 같으므로 서로 싸우지 않는다.
    Evaluation Manager(parallel) 에서도 동일하게 동작하는 것을 확인했다.
  - Auto Keyframe 이 **꺼져 있으면** 종전 설명대로 **미리보기**다 — 값과 메시가 즉시 바뀌고,
    시간을 이동하면 커브 값으로 되돌아간다(마야 채널박스와 같은 감각). 예전에는 이쪽도 화면만
    바뀌고 메시는 안 움직였다.
- **[Fix] 애니메이션 레이어에 들어간 타겟이 통째로 비활성이던 문제** — 레이어에 넣는 순간
  weight 의 직접 소스가 `animCurve` → `animBlendNode*` 로 바뀌어 `driven`(조절 불가)으로
  분류됐다. `layered` 상태를 새로 두어 **키가 걸린 타겟과 똑같이 조절**된다(키는 활성 레이어에
  찍힌다). weight 상태는 이제 `free / keyed / layered / driven / locked` 다섯 가지다.
- **[Keep] 제스처 하나 = Ctrl+Z 하나** — 드래그 중에는 미리보기만 하고 놓을 때 키를 찍는 방식도
  검토했지만 **더 나빴다**: Auto Key 가 켜져 있으면 **마야가 `setAttr` 마다 자체 키를 찍는데**
  그 키가 우리 undo 청크 **밖에** 별도 항목으로 쌓여 Ctrl+Z 가 두 번 필요해진다. 키를 우리가
  먼저 찍어 두면 뒤따르는 `setAttr` 이 같은 값이라 마야의 자동 키가 개입하지 않아 제스처 하나가
  undo 하나로 남는다(실측: setAttr 만 = undo 2회, 키+setAttr = undo 1회).
- **[Verify]** mayapy 실측 54항목 —
  core 30항목(free/keyed/layered/driven/locked 분류, autokey ON/OFF 각각의 값·키·스크럽 후
  유지, 같은 프레임 재조절 시 키 갱신, 레이어 키가 베이스 커브를 건드리지 않음, 청크 undo),
  UI 24항목(PySide2 실제 위젯으로 드래그/스핀박스/다중 선택/레이어/undo 1회, 키 타겟 슬라이더
