# Changelog — A00130_ControlRig_V02

## v02.15 (2026-08-31)
**[Change] 템플릿 폴 타깃 4개에 `poleDistance` — 실시간으로 거리를 맞춘다.**

v02.13 은 위치를 **한 번 계산해 넣었다.** 이제 `pointConstraint` 로 **살아 있게 물린다** —
각 조인트에 keyable `poleDistance` 가 붙어 뷰포트에서 값을 바꾸면 **바로 따라 움직이고**,
팔·다리를 옮겨도 따라온다. 배선은 `A00060` 의 `pole_target_manager.ensure()` 를 쓴다.

**★ 다시 눌러도 맞춰 둔 거리가 안 날아간다** — `orient_map.json` 의 `distance` 는
**처음 어트리뷰트를 만들 때만** 쓴다. 실행할 때마다 되돌리면 실시간 조절이 무의미해진다.
되돌리려면 새로 둔 `reset_distance` 를 켠다. 컨스트레인트도 다시 쌓이지 않는다.

**[Fix] 두 번째 실행부터 폴 타깃이 전부 걸러지던 것** — `ensure()` 앞에 "translate 가
구동되나" 사전 검사가 있었는데, 두 번째 실행에서는 **우리가 건 컨스트레인트**가 몰고 있어
4개 전부 `skipped` 가 됐다(`0 pole target(s) wired`). 남의 컨스트레인트인지 우리 것인지는
`ensure()` 가 가르므로 사전 검사를 뺐다.

`restore_positions` 도 **translate 가 구동되는 노드는 건너뛴다** — 되돌릴 수 없고 되돌릴
필요도 없다.

**검증**(mayapy headless, **576항목 전부 통과**): 어트리뷰트가 붙는가 · **값을 바꾸면 바로
움직이는가** · 팔다리를 옮기면 따라오는가 · **다시 눌러도 값이 유지되는가** ·
**컨스트레인트가 안 쌓이는가** · `reset_distance` 가 되돌리는가 · 회전은 여전히 월드 0 인가.

## v02.14 (2026-08-31)
**[Feature] IK 축 맞추기 — 정해진 축이 폴 타깃을 보도록 `twist` 를 고친다.**

`ik_axis_map.json` 의 `D02_IK_handle_axiesUpadate : +Z`. **`Match` 버튼을 누르면 매칭이
끝난 뒤에** 자동으로 돈다. 목록이라 **세트가 늘어나면 줄만 더하면 되고**, 세트마다 다른
축을 줄 수 있다.

**왜 필요한가** — 2조인트 체인에 ikHandle 과 폴 벡터를 걸면 **어느 축이 폴을 보는지는
마야가 정한다.** 실측하면 기본은 `-Y` 다.

**★ `twist` 여야 한다** (실측으로 갈렸다)

| 방법 | 결과 |
|---|---|
| `jointOrient` | **안 바뀐다** — 솔버가 `rotate` 로 보정해 축이 그대로다 |
| `rotate` | **쓰면 안 된다** — 솔버가 매 평가마다 덮어쓴다 |
| **`twist`** | 정확히 돈다 — `0`→`-Y`, `90`→`+Z`, `180`→`+Y`, `-90`→`-Z` |

**★ 레퍼런스에서 유지된다** (사용자의 조건). `twist` 는 파일에 저장되므로:

```
원본 twist=90 -> +Z      레퍼런스 -> +Z      임포트 -> +Z      다시 열기 -> +Z
```

`jnt_01.rotate` 도 원본과 레퍼런스가 같다. `rotate` 로 고쳤다면 이게 깨진다.

**기준축을 가정하지 않는다** — "기본이 `-Y` 이니 90 을 더한다" 로 짜면 체인 방향이 달라질
때 조용히 틀어진다. **지금 각도를 재서 더하고, 다시 재서 남은 오차를 보고한다.**
부호가 반대였으면 반대로 한 번 더 시도한다. 폴을 어느 방향에 두든 맞는 것을 확인했다.

**IK 세션이 끝난 뒤에** 돈다 — 그때라야 핸들과 폴 벡터가 새 체인에 맞춰져 있어 잰 각도가
뜻을 갖는다.

**검증**(mayapy headless, **IK축 44 + Pole 54 + Orient 98 + A00130 118 + Pair 70 +
Length 127 + IK 57 = 568항목 전부 통과**): 기본이 `+Z` 가 아닌 것 · 맞추면 `+Z` 인 것 ·
**`rotate` 는 솔버 몫으로 남는가** · **저장→레퍼런스/임포트/재오픈 넷 다 같은 축인가** ·
핸들 여러 개 · **세트 두 개(각자 다른 축)** · 폴 방향 4가지 · 없는 세트 · 폴 없음 ·
`twist` 잠김 · 핸들 아닌 멤버 · **두 번 눌러도 안 흔들리는가** · undo 한 스텝 ·
네임스페이스 · **Match 버튼 경로**.

## v02.13 (2026-08-31)
**[Feature] 템플릿 폴 타깃 4개를 팔·다리에서 자동 배치.**

`helper_polTgt_arm_l/r` · `helper_polTgt_leg_l/r` 을 더는 손으로 놓지 않는다.
각자의 팔·다리에서 계산한다:

```
A = (첫 조인트 + 끝 조인트)/2      v = 가운데 - A      폴 타깃 = A + distance*v
```

계산은 **`A00060_jointTool_V03` 의 `pole_target_manager` 와 같은 것**을 쓴다 —
그 툴로 만든 살아 있는 폴 타깃과 여기서 놓는 템플릿 조인트가 **같은 자리**여야 한다.

**여기서는 컨스트레인트를 걸지 않고 위치만 넣는다.** 템플릿 조인트는 사람이 놓고 버튼을
다시 누르는 것이 이 툴의 갱신 방식이라, 노드를 남기면 오히려 방해가 된다.

**★ 단계가 둘로 갈린다** — 위치는 **일찍**, 회전 0 은 **늦게**.
A2 가 폴 타깃 위치를 읽어 롤을 정하므로 위치는 미러 직후에 놓아야 한다. 그런데 폴 타깃은
`upperarm` · `thigh` 의 **자식**이라, 그때 회전을 0 으로 만들어도 **뒤이어 A2 가 부모를
돌리면 월드 회전이 따라 움직인다**(실측 `[170.27, 13.49, -2.29]`).

```
미러 → 폴 타깃 위치 → A1 → A2 → 손가락 → 늦은 미러 → 위치 전용 → 폴 타깃 회전 0 → Place
```

`mirror.position_only` 에서 폴 타깃 2쌍이 빠졌다(7쌍 → **5쌍**). 위치가 계산으로 나오므로
좌우 미러가 필요 없다. 발 보조 5쌍은 그대로다.

`distance` 는 `orient_map.json` 에 있고 **기본 2.0** 이다 — 1.0 이면 무릎/팔꿈치 위라
폴로 쓸 수 없어 한 번 더 밀어냈다. **시작값이니 표를 보고 맞추면 된다.**

요약에서 **폴 타깃과 Place 를 따로 센다** — 둘 다 "위치를 놓는" 일이지만 성격이 달라
한 칸에 담으면 어느 쪽이 몇 개인지 알 수 없다.

**검증**(mayapy headless, **A00130 118 + Orient 98 + Pole 54 + Pair 70 + Length 127 +
IK 57 = 524항목 전부 통과**): 네 폴 타깃이 **제 팔·다리에서 계산된 자리**에 있는가 ·
**회전이 월드 0 인가**(늦은 단계가 도는가) · **템플릿에 컨스트레인트가 안 남는가** ·
손으로 옮겨도 **다시 계산되는가** · 거리를 바꾸면 롤이 도는가.

**[Feature] `Constrain` 탭 — `Con` 이 가리키는 노드가 포즈 오브젝트를 몬다 (Pair 뒤).**

`C04_pose_obects` 세트의 원소마다 `Con` 어트리뷰트를 보고, 연결된 노드가 그 오브젝트를
drive 하도록 `parentConstraint` 를 건다. `Con` 이 `message` 든 일반 어트리뷰트든 된다.

**★ 이미 걸린 것은 건드리지 않는다** — 실측하면 같은 드라이버로 다시 걸면 멱등인데
**드라이버가 다르면 조용히 타깃이 2개로 늘어난다.** `Con` 을 바꾼 뒤 다시 돌리면
**두 노드가 반씩 끌어당기는** 리그가 된다. 그래서 기존 컨스트레인트가 있으면 건너뛰고,
"드라이버가 바뀌었으면 먼저 지우라" 고 적는다.

`maintain_offset` 은 json 에 있고 기본 **off**(마야 명령 기본값). 드라이버와 오브젝트가
떨어져 있으면 **거리를 로그에 적는다** — 그때만 결과가 갈리기 때문이다.

**탭 순서**: `Orient & Place` · `Length` · `Match` · **`Pair`** · **`Constrain`**.

**검증**(mayapy headless, **Pair/Constrain 69 + Orient 96 + Match 115 + Length 127 +
IK 57 = 464항목 전부 통과**): 짝 24개 로드 · 중복 세트 검사 · 원소가 0/1/2 일 때 ·
없는 세트 · 잠긴 채널 · **undo 한 스텝** · `Con` 두 타입 · **재실행이 타깃을 안 늘리는가** ·
**`Con` 을 바꿔도 안 늘리는가** · 오프셋 경고 · `maintain offset` 켠 경우 · 네임스페이스 ·
UI 경로.

## v02.09 (2026-08-28)
**[Feature] 손가락 회전 규칙 — 왼손은 aim, 오른손은 늦은 Behavior 미러.**

| 손 | 규칙 |
|---|---|
| **왼손** (`helper_hand_l` 하위 19개) | forward `+X` 가 제 자식을, `+Y` 가 월드 `+Y` 쪽 |
| **오른손** (19개) | **왼손을 Behavior 미러**한 결과 |

**`aim_subtrees`** 규칙을 새로 뒀다 — 조인트 이름을 하나하나 적는 대신 **뿌리 하나**
(`helper_hand_l`)만 적으면 그 아래 전부에 적용된다. 손가락 마디가 늘거나 줄어도 json 은
그대로다. **끝마디는 부모 방향을 물려받는다**(aim 할 자식이 없다).

**★ 순서** — 오른손 미러는 **왼손을 정렬한 뒤에** 돌아야 한다. 팔 전체를 미러하는 이른
단계는 **아직 손대지 않은 왼손가락**을 복사하므로, 사용자가 놓아 둔 방향이 그대로
오른쪽에 박힌다. 그래서 손 미러에 **`"stage": "late"`** 를 뒀다:

```
미러(이른) → A1 → A2 → 손가락 정렬 → 미러(늦은) → 위치 전용 → Place
```

**규칙 없는 조인트가 40 → 2 로 줄었다** (`helper_root` · `helper_clavicle_l`).

**[Fix] 검증 씬이 실행마다 달라지던 것** — 손가락을 `hash()` 로 놓고 있어서, 어쩌다
손가락이 월드 `+Y` 와 평행해지면 up 힌트를 못 써 폴백이 돌고 테스트가 들쭉날쭉했다.
**결정적 배치**로 바꾸고, **퇴화 케이스(전방 ∥ up 힌트)** 를 별도 항목으로 뺐다.

**검증**(mayapy headless, **Orient 96 + Match 115 + Length 127 + IK 57 = 395항목 전부 통과**,
두 번 돌려 같은 결과): 왼손 `+X` 가 자식을 보는가 · `+Y` 가 월드 `+Y` 직교화인가 ·
끝마디가 부모를 물려받는가 · **오른손이 왼손의 Behavior 미러와 행렬 단위로 같은가** ·
**이른 단계로 되돌리면 깨지는가**(순서가 진짜 필요하다는 증거) · 규칙 없는 조인트가 2개인가.

```

```

**순서가 강제된다** — A2 는 오른쪽 **폴 타깃 위치를 읽는데**, 그걸 놓는 게 미러다.

**끝 조인트** — IK 솔버는 끝 조인트를 회전시키지 않는다(실측). 그래서

`preserved`(정해진 것)와 `no rule`(미결)을 **표에서 가른다** — 같은 칸에 담으면
확인해야 할 빈칸이 결정된 항목에 묻힌다.

**실측으로 갈린 설계**
- **월드 회전 0** 은 `rotate=0` 으로도 `jointOrient=0` 으로도 안 된다.
  `xform -ws -ro 0` 뒤 값을 `jointOrient` 로 옮기고 `rotate` 를 0 으로 두는 방법만 된다.
- **Behavior 미러는 축을 `diag(1,-1,-1)` 로 보낸다** — forward 가 월드에서 같은 쪽을 보게

  같은지** 여러 방향에서 검증했다.
- **`preserve` 는 로컬 값 기준** — 마야 IK 도 로컬을 지키고 월드는 부모를 따라간다.

- **forward 를 정확히 맞추면 up 은 그만큼 기운다**(직교화). 체인이 기울면 둘은 동시에
  만족될 수 없다. **forward 를 우선**하고 **기운 각도를 로그에 적는다.**

**아직 규칙이 없는 40개**(`helper_root` · `clavicle_l` · 손가락 38)는 **건드리지 않고**

의존하지 않게 된다.** 짝은 손으로 담는 TSL 대신 `length_map.json` 이 갖는다.

**어트리뷰트 12개 — 하나도 빼지 않는다**

부위(팔 좌우·다리 좌우)마다 세 개씩이다. `_up`/`_low` 는 `total` 만큼 필수다.
`Arm_L` ↔ **`Arm_r`** 처럼 좌우 표기가 깨져 있어(대문자 vs 소문자)
**대칭으로 유도하지 않고 json 에 전부 적었다** — 유도하면 한쪽이 조용히 틀린다.
V01 툴과 아카이브(`01_Modules` · `03_Modules_Test`) 전 버전을 훑어 **12개가 전부이고
그 밖에 없다**는 것을 확인했다.

**들어 있는 것**
- `Length` 탭 — `Measure`(씬 불변) → 표로 값 확인 → `Write Values`(undo 한 스텝)
- `Total` 콤보 — `straight`(V01 과 동일, 기본) / `sum`(완전히 폈을 때)
- 옵션 컨트롤러를 **3단계로** 찾는다 — 수동 지정 > 정확한 이름 > 이름 부분 매칭.
  **후보가 여럿이면 고르지 않고 멈춘다**(V01 은 첫 개를 골랐다).
- **`Get Selected` / `Auto` 버튼 + 이름 필드** — 자동으로 못 찾아도 손으로 지정할 수 있다.
  셰이프를 골라도 트랜스폼으로 올려 준다. 리그 이름 규칙은 프로젝트마다 다르므로
  **자동은 편의, 수동이 보장이다.**
- 씬 선형 단위 표시 (`Measured in cm`)

**실측으로 갈린 설계**
- **`total` 은 `up + low` 가 아니라 직선 거리다.** 30° 굽으면 **3.4 % 짧다**.
  IK 스트레치 기준이면 보통 합이 맞지만 **조용히 바꾸지 않고** 기본값은 V01 그대로 두고
  **두 값의 차이를 표에 드러내** 고르게 했다.
- **`min`/`max` 는 자르지 않고 예외를 낸다.** 그래서 범위 밖이면 **잘라 쓰지 않고 거부**한다 —
  잘린 길이는 틀린 리그를 조용히 만든다.
- **거리는 씬 선형 단위를 탄다** (같은 두 점이 cm 10 · m 0.1 · mm 100).
  단위를 **바꾸지 않고 표시만** 한다.
- **`cmds.ls("*토큰*")` 은 네임스페이스를 넘지 않는다.** 노드가 `CAGE:...` 면 **빈 목록**이
  온다 — `recursive=True` 라야 한다. 게다가 **셰이프까지 잡아**(컨트롤러는 커브다)
  후보가 2개로 보인다 — `type="transform"` 이 필요하다.
  이 둘이 겹쳐 옵션 컨트롤러를 못 찾았다.
- **V01 의 `TKN_OPTION_CTL` 은 전체 이름이 아니라 토큰이었다.** 실제 이름은
  `CH_n_OptionAll_xx_ctl` 이고 V01 은 `in` 으로 부분 매칭했다. **상수를 옮길 때는
  그 상수가 어떻게 쓰이는지 함께 옮겨야 한다.**
- **없는 어트리뷰트에 `setAttr` 은 `RuntimeError` 를 낸다.** V01 은 그 자리를 감싸지 않아
  **Match 전체가 멈췄다.** 여기서는 쓰기 전에 존재·잠금·연결·범위를 **전부 미리 보고**
  막힌 것만 건너뛴다.

**부위를 더하려면** `length_map.json` 에 줄을 더한다 — **코드는 안 고친다.**
스파인·손가락은 V01 에도 측정이 없어 넣지 않았다.

**[Refactor]** `scene_utils._plug_writable` → **`plug_writable`** 공개.
Match(트랜스폼 채널)와 Length(옵션 컨트롤러) 두 곳이 쓰므로 내부 헬퍼가 아니다.

**검증**(mayapy headless, **Length 126 + Match 88 = 214항목 전부 통과**):
**12개가 하나도 안 빠지고 실리는지 개수로 센다** · 굽은 체인에서 직선≠합과 표식 ·
`sum` 모드 · **케이지를 임포트/레퍼런스한 두 경우** · 어트리뷰트 하나가 없어도
**나머지 11개가 써지는가**(V01 은 여기서 멈췄다) · 잠김/연결/범위 밖을 건너뛰는가 ·
**범위 밖을 자르지 않는가** · **네임스페이스를 넘는 토큰 검색** · **셰이프가 후보를 부풀리지 않는가** ·
후보가 둘이면 멈추는가 · **수동 지정이 이기는가** · `Get Selected` 가 셰이프를 트랜스폼으로
올리는가 · 전부 0 이면 경고하는가 ·
단위 변경 · `Measure` 가 씬을 안 바꾸는가 · **undo 한 스텝** · UI 버튼 경로.
**변이 테스트로 검증을 검증했다** — `length_map.json` 에서 `_up`/`_low` 8개를 빼면

## v02.00 (2026-08-28)
**[Feature] 신규 — Phase 1 (최소 기능 : Match).**

컨트롤러(cage) 세팅의 "사람이 판단하는 자리" 를 **템플릿 조인트**로 옮긴다.
사람은 조인트를 눈으로 놓고, 나머지는 버튼이 한다.

**들어 있는 것**

- **`Create Template Joints`** — 매핑 표의 이름·부모 관계대로 조인트 생성(전부 원점).
  배치는 사람 몫이다. 이미 있는 조인트는 안 건드린다(멱등).
- **`Check`** — 없는 템플릿 조인트 / 없는 케이지 세트를 보고. **씬 불변.**
- **`Match`** — 각 케이지 세트의 원소를 짝인 조인트 자리로. **undo 한 스텝.**
- **`Cage namespace` 콤보** — 씬의 네임스페이스에서 고른다(규칙으로 정하지 않는다).

**데이터는 json 이다** — `app/data/mapping/v001/template_map.json`.
조인트 **80** · 짝 **74** · 매칭 대상 없는 구조용 조인트 **10** · 위치 전용 세트 **6**.
짝이 늘거나 줄면 이 파일만 고치면 되고, 케이지 버전이 갈리면 폴더를 늘리면 콤보에 뜬다.

**설계에서 짚은 것**

- **값이 언제나 목록이다.** 원본 표에서 한 조인트가 세트 둘을 갖는 모양이 두 가지였다 —
  `helper_foot_l` 은 한 줄에 둘, **`helper_ball_l` 은 줄이 둘로 나뉘어** 있었다.
  `{조인트: 세트}` 로 만들면 **한쪽이 조용히 사라진다.**
- **하위 세트는 통째로 무시**하고 재귀하지 않는다. 몇 개를 무시했는지 알린다.
- **없는 짝은 로그만 남기고 계속 간다** — 한 짝이 없다고 전체가 멈추지 않는다.
- **잠기거나 구동되는 오브젝트는 반쯤 옮기지 않는다.** `matchTransform` 은 **잠긴 채널을
  조용히 건너뛴다**(실측: `translateX` 만 잠근 오브젝트가 X 만 안 움직이고 에러도 없었다).
  그래서 미리 잠금·입력 연결을 보고 막혀 있으면 **그 오브젝트를 통째로 건너뛴다.**
- **이름은 정해 두지 않고 찾아본다** — `Cage namespace` 를 고르면 조인트든 세트든
  `CAGE:helper_pelvis` 를 먼저 보고, 없으면 `helper_pelvis` 를 본다. 그래서 케이지를
  **레퍼런스**해도, **임포트**해도, 조인트만 로컬로 만들어 둬도 전부 된다.
  둘 다 있으면 `ambiguous ...` 로, 못 찾으면 `looked for CAGE:x and x` 로 **알린다**.
  `Create Template Joints` 도 같은 판정을 써서 **레퍼런스가 이미 준 조인트를 하나 더
  만들지 않는다.**

  > 처음에는 "템플릿 조인트는 로컬, 세트만 레퍼런스" 로 보고 **세트에만** 붙였다.
  > 실제 케이지 파일에는 **조인트도 같이 들어 있어서** 레퍼런스하면 `Check` 가 전부
  > `joint missing` 이 됐다(임포트는 멀쩡했다). 사용자가 그 증상을 보고했고 mayapy 로
  > 재현해 고쳤다. **이름 해석은 정하지 말고 찾아보는 편이 맞다.**

**V01 에서 가져오지 않은 것**: `MayaScene.match_transforms` 는 팔로워의 `rotateOrder` 를
타깃 것으로 잠깐 바꿨다 되돌리는데, **`xform -rotateOrder` 는 방향을 보존하지 않는다**
(실측: `rotate 30/40/50` 인 노드의 rotateOrder 만 바꾸면 월드 회전이 달라진다).
V02 는 마야 내장 **`matchTransform`** 을 쓴다.

**아직 없는 것**: Mirror · IK 세션(`D01_IK_handle`) · Orient · Validate · 길이 수치.
**orient 규칙은 아직 안 받았다** — 매핑 json 의 `orient` 필드는 자리만 잡아 두고 아무도
읽지 않으며, `Match` 는 orient 가 돌았는지에 의존하지 않는다. 탭은 `main_window.py` 의
`STEPS` 표에 줄을 넣으면 붙는다.

**검증**(mayapy headless, **88항목 전부 통과**): 매핑 파일(개수·병합·위치 전용·구조 전용) ·
