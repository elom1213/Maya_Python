## v02.07 (2026-08-28)
**[Feature] 템플릿 조인트 4개 추가 + `Place` 규칙. 단계 이름을 `Orient & Place` 로.**

사용자가 `joints_structure.json` 으로 갱신된 템플릿 구조를 줬다. 기존 매핑과 대조하니
**추가 4개, 삭제 0, 부모 이동 0** 이었다:

| 새 조인트 | 부모 |
|---|---|
| `helper_polTgt_foot_l` | `helper_foot_l` |
| `helper_polTgt_toe_l` | `helper_ball_l` |
| `helper_polTgt_foot_r` | `helper_foot_r` |
| `helper_polTgt_toe_r` | `helper_ball_r` |

`template_map.json` 에 넣었다(총 **84개**). 케이지 세트 짝은 아직 없어 구조/배치용이다.

**`Place` 규칙** — 방향이 전부 정해진 **뒤에** 이 넷의 `translate` 가 `(0, 0, 10)` 이 된다.
부모 자리에서 **자기 축 `+Z`** 로 10. 실측하면 `setAttr .translate` · `xform -os -t` ·
`move -r -os` 가 **모두 같은 결과**다 — 오브젝트 공간 이동은 곧 `translate` 어트리뷰트다.
방향 단계 뒤에 도는 이유는 **자기 축이 확정돼야 `+Z` 가 어디인지 정해지기** 때문이다.

**[Change] 이름** — 이 단계가 방향만이 아니라 **위치까지** 다루게 됐으므로
탭과 버튼을 **`Orient & Place`** 로 바꿨다. 표에는 **`placed`** 상태를 따로 두고,
`Check` 는 로그에 `N joint(s) will be MOVED, not just rotated` 를 먼저 적는다 —
**회전만 될 거라 생각하고 눌렀다가 위치가 바뀌는 일이 없도록.**

**[Change] 탭 순서** — `Orient & Place` · `Length` · `Match` (사용자 지정).

축과 거리는 `orient_map.json` 의 `place` 에 있다 — **코드는 안 고친다.**

**검증**(mayapy headless, **Orient 83 + Match 112 + Length 127 + IK 57 = 379항목 전부 통과**):
구조 파일과 `template_map` 이 맞는가 · 조인트 84개 · 네 조인트의 `translate` 가 정확히
`(0,0,10)` 인가 · **엉뚱한 곳에 둬도 덮어쓰는가** · 부모에서 정확히 10 떨어지는가 ·
`placed` 가 `ok` 와 다른 상태인가 · **방향 행 뒤에 오는가** · 잠긴 translate 를 건너뛰고
알리는가 · 탭 이름과 순서.

## v02.06 (2026-08-28)
**[Fix] Match — 세트에 없는 **중첩 IK 핸들** 때문에 조인트 회전이 틀어지던 문제.**

사용자 보고: 이런 구조에서 Match 를 하면 `CH_r_UpperArmDrv_xx_ikjnt` 의 **위치는 맞는데
회전이 부모와 어긋난다.**

```
CH_r_UpperArm_xx_ikjnt
└── CH_r_UpperArmDrv_xx_ikjnt      <- 이 체인에도 제 ikHandle 이 있다
    └── CH_r_LowerArmDrv_xx_ikjnt
```

**원인** — `D01_IK_handle` 에 **Drv 체인의 핸들이 없었다.** 그러면 그 IK 는 매칭 중에도
계속 풀려서, 부모 체인이 움직이는 동안 솔버가 Drv 조인트를 다시 잡는다. 재현:

| Drv 핸들이 세트에 | `UpperArmDrv` 의 부모 대비 회전 |
|---|---|
| 있을 때 | **0.000°** |
| 없을 때 | **7.643°** |

`LowerArmDrv` 가 멀쩡해 보이는 건 **끝 조인트라 솔버가 안 돌리기** 때문이다 —
겉보기엔 한 조인트만 틀어진 것처럼 보인다.

**고침** — 세트를 믿되 **그것만 믿지 않는다.** 매칭 대상(과 그 하위)을 체인에 포함하는
ikHandle 을 **씬에서 찾아 함께 끄고**, 무엇을 더 껐는지 **로그에 적는다**:

```
[Warning] 1 ikHandle(s) drive joints being matched but are NOT in the handle set -
turning them off too, otherwise their solver would fight the match and leave the
joints rotated: drvHandle. Consider adding them to the set.
```

관계없는 체인은 건드리지 않는다. `Match` 탭 체크박스를 끄면 이것도 함께 꺼진다
(체크박스 = "매칭 중 IK 를 다룬다").

> **손으로 채우는 목록은 언젠가 빠진다.** 목록을 없애는 대신 **목록 + 실측 검사**로 갔다 —
> 리거의 의도(세트)는 그대로 두고, 놓친 것은 툴이 찾아 알린다.

**검증**(mayapy headless, **IK 57 + Match 110 + Length 126 + Orient 68 = 361항목 전부 통과**):
Drv 핸들이 세트에 **있을 때와 없을 때 결과가 같은가** · 빠진 핸들을 찾아 **알리는가** ·
**관계없는 체인은 안 건드리는가** · 이미 세트에 있는 핸들을 중복으로 세지 않는가 ·
끝난 뒤 그 핸들의 `ikBlend` 가 복원되는가 · **`auto_ik` 를 끄면 증상이 되돌아오는가**
(고친 것이 진짜 원인이라는 증거).

## v02.04 (2026-08-28)
**[Feature] `Orient` 단계 — 템플릿 조인트의 방향을 규칙대로 잡는다 (A1 · A2 · A3).**

사용자가 조인트를 손으로 놓은 뒤 `Orient` 한 번이면 방향이 정해진다.
**위치는 안 바뀐다**(미러로 채우는 오른쪽만 예외).

```
미러  ->  A1(척추)  ->  A2(팔·다리 + tail/preserve)  ->  위치 전용(월드 회전 0)
```

**순서가 강제된다** — A2 는 오른쪽 **폴 타깃 위치를 읽는데**, 그걸 놓는 게 미러다.
미러를 끄면 그 사실을 경고한다.

**규칙 셋이 결국 한 계산이다** — "forward 를 다음 조인트로 aim 하고 up 을 힌트 쪽으로".
다른 것은 힌트가 **폴 타깃**(A2)이냐 **월드 축**(A1 · tail)이냐뿐이다.

**끝 조인트** — IK 솔버는 끝 조인트를 회전시키지 않는다(실측). 그래서
다리는 **`tail`**(`foot→ball→ballEnd`, `+Z`→월드 `+Y`), 팔은 **`preserve`**(손대지 않음).
`preserved`(정해진 것)와 `no rule`(미결)을 **표에서 가른다** — 같은 칸에 담으면
확인해야 할 빈칸이 결정된 항목에 묻힌다.

**실측으로 갈린 설계**
- **월드 회전 0** 은 `rotate=0` 으로도 `jointOrient=0` 으로도 안 된다.
  `xform -ws -ro 0` 뒤 값을 `jointOrient` 로 옮기고 `rotate` 를 0 으로 두는 방법만 된다.
- **Behavior 미러는 축을 `diag(1,-1,-1)` 로 보낸다** — forward 가 월드에서 같은 쪽을 보게
  되어 **오른팔의 forward 가 로컬 `-X`** 가 된다. `cmds.mirrorJoint` 와 **행렬 단위로
  같은지** 여러 방향에서 검증했다.
- **`preserve` 는 로컬 값 기준** — 마야 IK 도 로컬을 지키고 월드는 부모를 따라간다.

**구현하며 드러난 함정 둘** (계획서에 없던 것)
- **부모를 돌리면 후손이 전부 딸려 움직인다.** 척추에서 오차가 조인트마다 **90도씩
  누적**됐다. **직접 자식만 되돌리면 모자라** 손자가 끌려간 채 남는다
  (`c` 가 `(0,120,0)` → `(-10,110,0)`). → **모든 후손**을 부모부터 되돌린다.
- **forward 를 정확히 맞추면 up 은 그만큼 기운다**(직교화). 체인이 기울면 둘은 동시에
  만족될 수 없다. **forward 를 우선**하고 **기운 각도를 로그에 적는다.**

**아직 규칙이 없는 40개**(`helper_root` · `clavicle_l` · 손가락 38)는 **건드리지 않고**
표에 `no rule - untouched` 로 남긴다. 규칙이 오면 `orient_map.json` 에 줄만 더한다.

**검증**(mayapy headless, **Orient 67 + Match 110 + Length 126 + IK 44 = 347항목 전부 통과**):
A1 두 모드 · `head` 가 앞 조인트를 물려받는가 · A2 forward(팔 L=+X, **R=−X**) ·
**폴을 옮기면 롤이 도는가** · **`hand` 의 로컬이 한 톨도 안 바뀌는가** ·
tail 이 직교화 결과와 같은가 · **미러가 `cmds.mirrorJoint` 와 행렬 단위로 같은가** ·
손가락까지 미러되는가 · 위치 전용 14개가 월드 0 인가 · **미러를 끄면 경고하는가** ·
규칙 없는 40개가 안 움직이는가 · **`Check` 가 씬 불변** · **undo 한 스텝** ·
네임스페이스 케이지 · UI 경로.

## v02.03 (2026-08-28)
**[Feature] Match 가 앞뒤로 **IK 편집 세션**을 연다 (계획서 Phase 4).**

`D01_IK_handle` 세트의 ikHandle 이 구동하는 조인트가 **매칭되지 않던 것**을 고쳤다
(사용자 보고). Match 는 이제 이 순서로 돈다:

```
IK 끄기  ->  매칭  ->  핸들 스냅 + 폴 벡터 역산  ->  IK 켜기
```

**진단 — 조용한 거짓 성공이었다**

IK 는 어트리뷰트 연결이 아니라 **솔버로** 쓴다. 그래서
`connectionInfo("jnt_mid.rotateZ", isDestination=True)` 가 **False** 이고
`channel_group_state` 도 `free` 로 본다. `matchTransform` 은 **성공하고**, 다음 평가에서
IK 가 도로 가져간다 — 로그에는 `[OK] matched` 가 찍히는데 씬은 그대로다.

`ikBlend` 를 껐다 켜는 것만으로도 부족하다. 되켜면 조인트가 **원위치**로 간다.
**핸들 스냅 + 폴 벡터 역산**까지 해야 편집이 남는다 —
`A00060_jointTool_V03` 의 IK Edit(`begin_edit`/`end_edit`/`cancel_edit`)을 **불러서** 쓴다.

**들어 있는 것** (`app/core/ik_session.py` 신규)
- `template_map.json` 의 `ik_handle_set` 으로 세트를 찾는다 — 조인트·세트·옵션 컨트롤러와
  **같은 이름 해석**(네임스페이스 먼저, 없으면 이름 그대로). 레퍼런스 케이지 지원.
- Match 탭 체크박스로 켜고 끈다 (기본 켬) + 세트/핸들 개수 표시
- 세트가 없으면 **조용히 세션 없이** 매칭한다(예전 동작)
- 핸들이 아닌 멤버는 무시하되 **몇 개인지 알린다**
- 매칭 중 예외가 나면 **체인을 시작 상태로 되돌리고** IK 를 켠 뒤 예외를 올린다 —
  반쯤 매칭된 체인에 IK 가 다시 붙는 것이 제일 나쁘다
- 지난 실행이 끊겨 **편집 모드에 남은 핸들**을 알아채서 표시한다

**`ikBlend` 는 이 리그에서 쓰이지 않는다** (사용자 확인). 그래서 계획서 7-4 가
"최대 기술 리스크" 로 꼽았던 **씬 전역 IK 정지**로 물러설 일이 없다 — 핸들별로 끈다.
다만 **가정하지 않고 확인한다**: `preflight()` 가 `ikBlend` 가 구동되는 핸들을 찾으면
**크게 알린다**(전제가 깨졌다는 뜻이고, 그대로 두면 씬 전체 IK 가 꺼진 채 매칭이 돈다).

## v02.02 (2026-08-28)
**[Fix] Match — 막힌 채널을 **그룹 단위**로 가른다. 일부만 막혀도 나머지는 매칭한다.**

`A01_Arm_L_01_UpperArm` 처럼 **`pointConstraint` 가 걸린 오브젝트**는 위치가 리그에
묶여 매칭이 안 되는데, 그때 **회전까지 매칭 안 된 채 방치**됐다(사용자 보고).
채널 하나라도 막히면 **그 오브젝트를 통째로 건너뛰었기** 때문이다.

**실측 — 컨스트레인트는 그룹을 통째로 막는다**

| 걸린 것 | translate | rotate | 지금 하는 일 |
|---|---|---|---|
| `pointConstraint` | 3/3 | 0/3 | **회전만 매칭** |
| `orientConstraint` · `aimConstraint` | 0/3 | 3/3 | **위치만 매칭** |
| `parentConstraint` | 3/3 | 3/3 | 통째로 건너뛴다 |
| `translateX` 만 잠금 | 1/3 | 0/3 | 위치는 손대지 않고 회전만 + 경고 |

→ **그룹(translate / rotate) 단위 all-or-nothing.**

- **그룹이 통째로 막혔으면** 그 그룹만 건너뛰고 나머지는 매칭한다 —
  `matched rotation only - position is driven by the rig`.
- **축이 일부만 막혔으면 그 그룹은 건드리지 않는다.** `translateX` 만 잠근 채 위치를
  맞추면 `t = [90, 2, 3]` 처럼 **반쪽**이 된다(실측). 크게 경고한다.
- **양쪽 다 막혔으면** 건너뛰고 이유를 적는다.

무엇을 넣고 무엇을 뺐는지 **오브젝트마다 적고**, 마지막에 부분 매칭 수와
반쪽 그룹 수를 요약한다. `apply()` 결과에 `partial` · `driven_t` · `driven_r` · `half` 추가.

**[Refactor]** `scene_utils.channel_group_state(node, group)` 신설 —
`free` / `driven`(전부 막힘) / `partial`(일부만 막힘) 을 가른다.

> 원래 규칙("반쯤 옮겨진 상태가 제일 나쁘다 - 통째로 건너뛴다")은 **틀리지 않았지만
> 범위가 과했다.** 반쪽이 나쁜 것은 **그룹 안에서** 갈릴 때지, translate 와 rotate
> 사이에서가 아니다. 컨스트레인트가 그룹을 통째로 막는다는 것을 재고 나서 갈렸다.

**검증**(mayapy headless, **Match 110 + Length 126 = 236항목 전부 통과**):
`pointConstraint` 에서 **회전이 매칭되는가**(예전에는 건너뛰었다) ·
`orientConstraint` 에서 위치가 매칭되는가 · `parentConstraint` 는 통째로 건너뛰는가 ·

## v02.00 (2026-08-28)
**[Feature] 신규 — Phase 1 (최소 기능 : Match).**

컨트롤러(cage) 세팅의 "사람이 판단하는 자리" 를 **템플릿 조인트**로 옮긴다.
사람은 조인트를 눈으로 놓고, 나머지는 버튼이 한다.

**들어 있는 것**

- **`Create Template Joints`** — 매핑 표의 이름·부모 관계대로 조인트 생성(전부 원점).
  배치는 사람 몫이다. 이미 있는 조인트는 안 건드린다(멱등).
- **`Check`** — 없는 템플릿 조인트 / 없는 케이지 세트를 보고. **씬 불변.**
- **`Match`** — 각 케이지 세트의 원소를 짝인 조인트 자리로. **undo 한 스텝.**
- **`Cage namespace` 콤보** — 씬의 네임스페이스에서 고른다(규칙으로 정하지 않는다).

**데이터는 json 이다** — `app/data/mapping/v001/template_map.json`.
조인트 **80** · 짝 **74** · 매칭 대상 없는 구조용 조인트 **10** · 위치 전용 세트 **6**.
짝이 늘거나 줄면 이 파일만 고치면 되고, 케이지 버전이 갈리면 폴더를 늘리면 콤보에 뜬다.

**설계에서 짚은 것**

- **값이 언제나 목록이다.** 원본 표에서 한 조인트가 세트 둘을 갖는 모양이 두 가지였다 —
  `helper_foot_l` 은 한 줄에 둘, **`helper_ball_l` 은 줄이 둘로 나뉘어** 있었다.
  `{조인트: 세트}` 로 만들면 **한쪽이 조용히 사라진다.**
- **하위 세트는 통째로 무시**하고 재귀하지 않는다. 몇 개를 무시했는지 알린다.
- **없는 짝은 로그만 남기고 계속 간다** — 한 짝이 없다고 전체가 멈추지 않는다.
- **잠기거나 구동되는 오브젝트는 반쯤 옮기지 않는다.** `matchTransform` 은 **잠긴 채널을
  조용히 건너뛴다**(실측: `translateX` 만 잠근 오브젝트가 X 만 안 움직이고 에러도 없었다).
  그래서 미리 잠금·입력 연결을 보고 막혀 있으면 **그 오브젝트를 통째로 건너뛴다.**
- **이름은 정해 두지 않고 찾아본다** — `Cage namespace` 를 고르면 조인트든 세트든
  `CAGE:helper_pelvis` 를 먼저 보고, 없으면 `helper_pelvis` 를 본다. 그래서 케이지를
  **레퍼런스**해도, **임포트**해도, 조인트만 로컬로 만들어 둬도 전부 된다.
  둘 다 있으면 `ambiguous ...` 로, 못 찾으면 `looked for CAGE:x and x` 로 **알린다**.
  `Create Template Joints` 도 같은 판정을 써서 **레퍼런스가 이미 준 조인트를 하나 더
  만들지 않는다.**

  > 처음에는 "템플릿 조인트는 로컬, 세트만 레퍼런스" 로 보고 **세트에만** 붙였다.
  > 실제 케이지 파일에는 **조인트도 같이 들어 있어서** 레퍼런스하면 `Check` 가 전부
  > `joint missing` 이 됐다(임포트는 멀쩡했다). 사용자가 그 증상을 보고했고 mayapy 로
  > 재현해 고쳤다. **이름 해석은 정하지 말고 찾아보는 편이 맞다.**

**V01 에서 가져오지 않은 것**: `MayaScene.match_transforms` 는 팔로워의 `rotateOrder` 를
타깃 것으로 잠깐 바꿨다 되돌리는데, **`xform -rotateOrder` 는 방향을 보존하지 않는다**
(실측: `rotate 30/40/50` 인 노드의 rotateOrder 만 바꾸면 월드 회전이 달라진다).
V02 는 마야 내장 **`matchTransform`** 을 쓴다.

**아직 없는 것**: Mirror · IK 세션(`D01_IK_handle`) · Orient · Validate · 길이 수치.
**orient 규칙은 아직 안 받았다** — 매핑 json 의 `orient` 필드는 자리만 잡아 두고 아무도
읽지 않으며, `Match` 는 orient 가 돌았는지에 의존하지 않는다. 탭은 `main_window.py` 의
`STEPS` 표에 줄을 넣으면 붙는다.

**검증**(mayapy headless, **88항목 전부 통과**): 매핑 파일(개수·병합·위치 전용·구조 전용) ·
