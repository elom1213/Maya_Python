# A00290_BSTool

레거시 `JUN_PY_BSTool_V01_01`(maya.cmds) 을 **PySide(Qt)** 로 재작성한 blendShape 작업 툴.
기존 툴의 **Connect BS 탭은 제외**하고 **Edit BS 탭만** 이식했으며, **Base Shape 탭** ·
**Shape Editor 탭** · **Mix Targets 탭** · **Bake Delete 탭**을 신규 추가했다.

- **아키텍처**: (B) Standalone/Qt — PySide, Maya 내 실행 (`A00270_skinMigrate` 클론, green_dark 테마)
- **버전**: `app/config/version.py`
- **설치**: `__dragDrop_A00290.py` 를 Maya 뷰포트로 드래그&드롭 → 셸프 버튼 생성 → `tools.A00290_BSTool.run(True)`

---

## 탭 1 — Shape Editor  (v01.02~, Maya 기본 Shape Editor 대체)

Maya 의 Shape Editor 는 가끔 원하는 타겟을 트리에 노출하지 않아 **Edit 버튼조차 없어** 수정을 못 한다.
이 탭은 blendShape 노드의 별칭(`aliasAttr`)에서 타겟을 **직접** 읽으므로 항상 전부 보이고,
타겟마다 Edit 토글이 생긴다.

### 사용 흐름
1. 씬에서 blendShape 노드(또는 그 메시)를 선택 → **`Select BlendShape Nodes`**.
   리스트가 바뀌는 즉시 아래에 타겟 행이 채워진다. (여러 노드를 담으면 노드별 헤더로 구분)
2. 원하는 타겟의 **`Edit`** 버튼 ON → 베이스 메시가 선택되고 그 타겟 모양이 보인다.
3. 뷰포트에서 메시를 조각(버텍스 이동, 스컬프트 브러시 등).
4. **`Edit`** 버튼 OFF → 수정된 메시 상태가 **그대로 타겟 모양으로 확정**된다.

| 요소 | 동작 |
|------|------|
| **행(칸) 선택** (v01.08~) | 타겟 **행을 클릭하면 선택**(배경 강조). **Shift+클릭 = 범위 선택**(v01.09~), **Ctrl+클릭 = 개별 토글**. 선택된 행들은 아무 슬라이더/스핀박스로 **전부 동시 조절** |
| **Edit** (토글) | 그 타겟의 sculpt 모드 ON/OFF. 노드당 **한 타겟만** 가능(Maya 와 동일) — 다른 타겟을 켜면 이전 것이 자동 해제 |
| weight 슬라이더 (v01.04~) | **중앙 0**, 오른쪽 끝 `+1`, 왼쪽 끝 `-1`. 드래그로 weight 조절 (가로 홈 표시는 v01.06~) |
| weight 스핀박스 | 타겟 weight 직접 입력(`-10~10`). 슬라이더와 양방향 동기화. **타이핑은 Enter(또는 다른 곳 클릭)에서 확정**(v01.15~, 아래 참고) — 화살표/휠 스텝은 즉시 반영 |
| (공통) | 편집 중에는 1.0 으로 고정(비활성). **키(animCurve)·애니메이션 레이어가 걸려도 조절 가능**(v01.07~, 실제 동작은 v01.14~, 아래 참고), 잠금/다른 노드 구동 weight 만 비활성. **씬에서 값이 바뀌면 실시간으로 따라온다**(v01.03~) |
| **Select All / Clear** (v01.08~) | 현재 **필터로 보이는** 행을 모두 선택 / 선택 해제 |
| **Filter** | 타겟 이름 검색 (MetaHuman 처럼 타겟이 수백 개일 때). v01.13~ 공용 위젯 — `Clear` 버튼 · 여러 단어 AND · `Number: 보이는수 / 전체수` |
| **Refresh** | 리스트의 노드에서 타겟/weight/편집 상태를 다시 읽는다 |
| **Expand** (v01.05~) | 타겟 목록을 **별도의 큰 창**으로 띄운다. 닫으면 탭의 제자리로 돌아온다 |
| **Exit Edit Mode (all blendShapes)** | 씬의 모든 blendShape 편집 모드를 해제 |

### 다중 편집 — 행(칸) 선택 (v01.08~)

타겟 **행을 클릭하면 그 행만 선택**되고 배경이 accent 색으로 강조된다.

- **Shift+클릭** (v01.09~) — 기준점(직전 클릭 행)부터 클릭한 행까지 **화면상 사이의 (보이는) 타겟을
  모두 선택**한다(표준 리스트 범위 선택). Shift 로 다시 클릭해 구간을 늘리거나 줄일 수 있다(역방향도).
- **Ctrl+클릭** (v01.09~) — 개별 토글. 떨어져 있는 타겟을 골라 담을 때.
- **그냥 클릭** — 이전 선택을 모두 풀고 그 행만 선택(기준점도 이 행으로 갱신).

선택된 행 중 **아무 슬라이더/스핀박스**를 조절하거나 값을 입력하면 **선택된 모든 타겟에 같은 값**이
실시간 적용된다.

- 조작한 행이 선택에 **없으면** 그 행 하나만 바뀐다(단일 편집은 그대로).
- 슬라이더 **드래그는 선택을 바꾸지 않는다** → "여러 개 선택 → 한 슬라이더로 동시 조절" 이 자연스럽다.
- 다중 선택에 잠금/구동 타겟이 섞여 있으면 그 타겟만 조용히 건너뛴다.
- **Undo(Ctrl+Z)는 제스처 단위**(v01.10~) — 슬라이더 드래그 한 번(잡고~놓기) 또는 스핀박스 한 번의
  변경이 통째로 원복된다. 다중 선택·키(setKeyframe) 타겟이어도 **한 번에 모든 타겟이 원복**된다.
  (슬라이더 `press~release` 를 하나의 undo 청크로 묶는다. 안 묶으면 매 틱 `setAttr` 이 별도 undo 라
  Ctrl+Z 가 마지막 한 틱 한 타겟만 되돌린다.)
- 구현: 행을 `TargetRow(QFrame)` 로 만들어 `mousePressEvent` 에서 선택을 처리(`_on_se_row_clicked`).
  슬라이더/스핀박스/Edit 버튼은 자기 클릭을 소비하고, QLabel 은 클릭을 무시해 부모 행으로 전달되므로
  **이름 칸을 클릭해도 선택**된다. `on_se_weight_changed` 는 `_co_edit_rows`(선택된 행)로 대상을 정하고,
  위젯 `setValue` 재귀는 `_se_applying` 플래그 + `blockSignals` 로 막는다.

> v01.07 은 체크박스 방식이었고, v01.08 에서 행 클릭 선택으로 바꿨다(사용자 요청).

### 스핀박스에 숫자를 직접 입력할 때 (v01.15~)

**친 그대로 남고, `Enter` 또는 포커스 아웃(다른 곳 클릭)에서 한 번만 확정**된다.
슬라이더 드래그와 화살표/휠 스텝은 종전대로 즉시 반영된다.

> [!bug] v01.14 까지 — 입력 도중 0 이 자동으로 채워지던 문제
> `0.123` 을 치려고 `0.1` 까지만 쳐도 칸이 `0.100` 으로 다시 써져 뒤 자릿수를 이어 칠 수 없었다.
> `0.` 만 쳐도 `0.000` 이 됐다.
> **원인** (PySide2 실측) — `QDoubleSpinBox` 는 기본이 keyboard tracking **ON** 이라 **키를 누를
> 때마다 값을 확정**하고, 확정할 때마다 편집 중인 텍스트를 소수점 자릿수에 맞춰 **다시 쓰며 커서를
> 옮긴다**(`interpretText` → `updateEdit`). 우리 `valueChanged` 핸들러가 되부르는 `_show_weight`
> 의 `setValue` 도 같은 일을 한 번 더 한다.
> **해결** — 타겟 행 스핀박스에 `setKeyboardTracking(False)`(확정은 Enter/포커스 아웃에서 한 번만).
> 더해서 `_show_weight` 가 **포커스를 가진(= 지금 타이핑 중인) 스핀박스는 건너뛴다** — 다중 편집이나
> 120ms 폴링(`_sync_se_weights`)이 끼어들어도 편집 중인 칸을 덮어쓰지 않는다.
>
> **실측** (mayapy 2024 / PySide2 offscreen, `QTest.keyClicks`): `"0.123"` 타이핑 →
> tracking **ON** 은 텍스트 `'0.100'` · 값 `0.1`(가드만 넣어도 그대로 — Qt 자체 재포맷이라),
> tracking **OFF** 는 텍스트 `'0.123'` · 값 `0.123` · `valueChanged` 1회. `"0."` 까지만 친
> 상태에서는 텍스트 `'0.'` 그대로에 시그널 없음.

### 애니메이션이 걸린 타겟 조절 (v01.07~, v01.14 에서 실제로 동작)

weight 를 상태별로 분류(`weight_state`)해 편집 가능 범위를 넓혔다.

| 상태 | 의미 | 슬라이더/스핀박스 |
|------|------|------------------|
| **free** | 연결·잠금 없음 | `setAttr` 로 조절 |
| **keyed** | animCurve 로만 구동(키프레임) | **조절 가능** (아래) |
| **layered** (v01.14~) | 애니메이션 레이어의 블렌드 노드(`animBlendNode*`)로 구동 | **조절 가능** (keyed 와 동일, 키는 활성 레이어에) |
| **driven** | 위에 해당하지 않는 노드로 구동(SDK·expression·직접 연결) | 비활성 |
| **locked** | 어트리뷰트 잠김 | 비활성 |

**keyed / layered** 타겟을 조절하면:

- 값과 메시가 **그 자리에서 바로 바뀐다**.
- 마야 **Auto Keyframe 이 켜져 있으면** → 조절한 값이 **현재 프레임의 키**가 된다. 이미 그 프레임에
  키가 있으면 그 키가 **갱신**된다. 다중 선택이면 선택한 모든 타겟에 한 번에 찍힌다.
- **꺼져 있으면** → **미리보기**다. 값·메시는 바뀌지만 시간을 이동(재평가)하면 커브 값으로
  되돌아간다. 마야 채널박스에서 키 걸린 값을 autokey 없이 만지는 것과 같다.

> **v01.14 fix — 키 타겟 슬라이더가 먹지 않던 이유** (mayapy 실측):
> `setKeyframe` 은 커브에 키를 넣을 뿐 **그 자리에서 plug 값을 갱신하지 않는다**(시간이 다시
> 흐르거나 강제 재평가가 있어야 반영). v01.07~v01.13 은 Auto Key 가 켜져 있을 때 이것만 냈기
> 때문에 드래그해도 메시가 꿈쩍하지 않았고, 120ms 폴링이 옛 값을 되읽어 슬라이더가 튕겨
> 돌아왔다. 그래서 **키를 찍은 뒤 `setAttr` 로 값을 즉시 반영**한다 — 키 걸린 plug 에 대한
> `setAttr` 은 (연결돼 있어도) 에러 없이 값을 바꿔 주며, 두 값이 같아 서로 싸우지 않는다.
> Evaluation Manager(parallel) 에서도 같다.
>
> **undo 가 한 번인 이유**: Auto Key 가 켜져 있으면 **마야가 `setAttr` 마다 자체 키를 찍는데**,
> 그 키는 우리 undo 청크 **밖에** 별도 항목으로 쌓인다(= Ctrl+Z 2회). 키를 우리가 먼저 찍어 두면
> 뒤따르는 `setAttr` 이 같은 값이라 마야의 자동 키가 개입하지 않는다. 그래서 "드래그 중엔
> 미리보기, 놓을 때 키" 방식은 **일부러 쓰지 않는다**(실측: setAttr 만 = undo 2회, 키+setAttr = 1회).
>
> sculpt **Edit** 진입은 종전대로 **free weight 만** 1.0 으로 올린다(키/구동 타겟에 예기치 않게
> 키가 찍히지 않도록).

### 동작 원리

```python
cmds.sculptTarget(bs, e=True, target=weightIdx, inbetweenWeight=1.0)  # Edit ON
cmds.sculptTarget(bs, e=True, target=-1)                              # Edit OFF (편집 확정)
```

ON 인 동안 베이스 메시에 가한 버텍스 편집은 그 타겟의 델타
(`inputTargetItem[6000].inputPointsTarget`)로 기록된다.

> **주의 — `setAttr` 로는 안 된다.**
> 같은 값을 담는 `<bs>.inputTarget[g].sculptTargetIndex` 어트리뷰트를 `setAttr` 로 직접 써도
> 편집 모드처럼 *보이지만* 실제로는 동작하지 않는다. 디포머가 버텍스 편집을 가로채도록 설정하는
> 일은 `sculptTarget` 커맨드가 하고 `setAttr` 은 값만 바꾸므로, 편집이 그대로 **베이스 shape 의
> tweak(`.pnts`)** 로 들어가 **원본 메시가 수정**된다. (Maya 의 `setSculptTargetIndex.mel` 은 이미
> sculpt 세팅이 끝난 상태에서 인덱스만 옮기는 용도다.)
> 따라서 **읽기는 어트리뷰트로, 쓰기는 반드시 커맨드로** 한다.

부가 동작:

- Edit 진입 시 타겟이 보이도록 **weight 를 1.0** 으로 올리고 이전 값을 저장 → 해제 시 **원복**.
- `envelope` 이 1.0 이 아니면 1.0 으로 맞춘다(편집 결과가 그대로 보이도록).
- weight 가 잠기거나 다른 노드에 구동되면 값을 바꾸지 못하므로 로그로 안내한다(편집 자체는 가능).
- Maya 뷰포트의 편집 HUD(`updateBlendShapeEditHUD`)를 함께 갱신 → 기본 Shape Editor 와 같은 표시.
- **창을 닫으면** 열려 있던 편집 모드를 모두 해제(= 편집 결과 확정)한다.

로직: `core/shape_editor_manager.py` — `ShapeEditorManager.begin_edit / end_edit / exit_all_edits`.

### Expand — 타겟 목록을 별도 창으로 (v01.05~)

탭 안의 `Targets` 영역은 좁다. `Expand` 를 누르면 `BS Tool - Targets` 창(기본 `640x900`, 크기 조절
가능)이 뜨고 타겟 목록이 그쪽으로 옮겨 간다. 창을 닫으면 탭의 **원래 자리**로 돌아온다.

- 타겟 행을 **복제하지 않고 `se_scroll`(스크롤 영역) 자체를 옮긴다**(`TargetsWindow`).
  행 위젯이 그대로이므로 Edit 토글 · 슬라이더 · weight 실시간 폴링이 전부 살아 있고,
  두 벌을 동기화할 일이 없다.
- 옮기는 동안 탭에서는 숨겨 둔 자리 표시자 라벨이 보인다. 되돌릴 때는 저장해 둔
  `se_scroll_index` 로 **원래 인덱스에 다시 끼운다**.
- 확장 창에도 `Filter` 와 개수 표시가 있고 탭 쪽 필터와 양방향 동기화된다.
  (값이 같으면 쓰지 않으므로 `textChanged` 가 서로를 부르며 맴돌지 않는다.)
  v01.13~ 탭 쪽 필터는 공용 위젯이고, 동기화는 위젯의 `filtered` 시그널에서 라벨·입력 칸을
  함께 맞추는 방식으로 유지된다.
- **이 탭의 목록은 `QListWidget` 이 아니라 행 위젯을 쌓은 것**(행마다 Edit 버튼·슬라이더·
  스핀박스)이라, 공용 Filter 는 **`rows_provider` 모드**로 붙는다 —
  `() -> [(이름, 위젯), ...]` 을 넘기면 위젯이 `setVisible()` 로 행을 숨긴다 (v01.13).
- 확장 창이 떠 있으면 **본 창이 가려지거나 다른 탭이어도** 폴링을 계속한다 — 타겟이 화면에 있으니까.
- 본 창을 닫으면 확장 창도 함께 닫아 스크롤 영역을 탭으로 되돌린다(고아 창 방지).

### weight 슬라이더 (v01.04~)

```
[Edit] browLift   |----▮----|  [ 0.500 ]
                 -1    0    +1
```

`QSlider` 는 정수만 다루므로 `WeightSlider` 가 weight 를 **1000배 한 정수**로 담는다(해상도
`0.001`). 양 끝과 중앙에 눈금을 찍어 0 위치를 눈으로 찾는다.

- **가로 홈(groove) 스타일 (v01.06~)**: 어떤 테마 qss 도 `QSlider` 를 스타일링하지 않아, 어두운
  배경에선 Maya 네이티브 홈이 배경에 묻혀 **핸들만 보였다**. `WeightSlider` 가 자체 스타일시트
  (`SLIDER_STYLE`)로 홈·핸들·비활성 상태를 직접 그려, 슬라이더의 시작·끝이 항상 보인다.
  중앙 0 인 양방향이라 방향성 fill 은 0 에서도 절반이 찬 것처럼 오해를 줘서, **좌우 균일한 한 줄**
  홈으로만 그리고 0 위치는 중앙 눈금이 표시한다.

- 슬라이더와 스핀박스는 **같은 weight 의 두 얼굴**이다. 어느 쪽을 움직이든 씬에 쓰고 반대쪽을
  같은 값으로 맞춘다(`_show_weight`). `blockSignals` 로 슬라이더 → 스핀박스 → 슬라이더 되울림을 막는다.
- 슬라이더 범위(`-1 ~ +1`)를 넘는 weight 는 슬라이더가 **끝에 붙고**, 실제 값은 스핀박스(`-10 ~ 10`)가
  보여 준다. 이때 폴링이 클램프된 값(`1.0`)을 씬에 **되쓰지 않는다**.
- 잠금/구동된 weight 를 밀면 씬에 쓰이지 않고, 다음 폴링이 실제 값으로 되돌린다.
  (그래서 폴링의 "값이 같으면 건너뛰기" 판정은 **두 위젯을 모두** 봐야 한다. 스핀박스만 보면
  씬에 못 쓴 슬라이더 조작이 어긋난 채 영영 남는다.)

### weight 실시간 반영 (v01.03~)

씬에서 weight 가 바뀌어도(채널박스, 어트리뷰트 에디터, 애니메이션 재생, 다른 스크립트 등)
Maya 는 Qt 에 알려 주지 않는다. 그래서 `QTimer` 로 `120ms` 마다 `weight` 를 다시 읽어 스핀박스에
반영한다(`main_window._sync_se_weights`).

- 폴링은 **Shape Editor 탭이 보이고 표시할 행이 있을 때만** 돈다. 다른 탭으로 옮기거나 창을
  가리면 멈춘다(`_update_se_timer`, `showEvent` / `hideEvent` / `closeEvent`).
- 스핀박스에 쓸 때는 `blockSignals` 로 `valueChanged` 를 막는다. 막지 않으면 방금 씬에서 읽은 값을
  씬에 **되쓰고**, 잠금/구동된 weight 라면 매 틱 경고 로그가 쌓인다.
- 사용자가 **입력 중인(포커스가 있는)** 스핀박스는 덮어쓰지 않는다.
- 표시 자릿수(`decimals=3`)의 절반(`0.0005`)보다 작은 차이는 화면상 같은 값이라 건너뛴다.
- 방향은 **씬 → UI 단방향**이다. UI → 씬은 기존대로 사용자가 스핀박스를 조작할 때만 일어난다.

여러 blendShape 노드를 리스트에 담고 일괄 처리한다. (레거시 Edit BS 탭 그대로)

| 버튼 | 동작 |

> 선택한 메시**다. `suspend_refresh` 로 빠르게 처리하고 끝나면 **현재 프레임을 원복**한다(전체 단일 undo).
> 로직: `edit_bs_manager.copy_every_frame(meshes, start, end)`.

## 탭 3 — Base Shape  (신규)

선택한 타겟의 **"기본(weight=1.0) 모양"을 다시 정의**한다.

### 사용 흐름
1. 아웃라이너/노드에디터에서 blendShape 노드(또는 그 메시)를 선택하고 **`<- Set`**.
   (메시를 고르면 히스토리에서 blendShape 를 찾아 채운다.)
2. **`List Targets`** → 타겟 이름이 weight 인덱스 순으로 리스트업된다.
3. (타겟이 많으면) **`Filter`** 에 이름 일부를 입력해 원하는 타겟만 남긴다 — 아래 참고.
4. 리스트에서 대상 타겟을 선택(`Select All` / `Clear Selection` 보조).
5. **Value** 에 기준 값을 입력(예: `0.5`, `1.3`).
6. **`Apply (Value -> 1.0)`** → 선택 타겟의 *Value 에서 보이던 모양*이 *weight 1.0 의 기본 모양*이 된다.

### Filter — 이름으로 타겟 찾기 (v01.12, 공용 위젯 이전 v01.13)

타겟 목록 아래의 입력 칸. **이름의 일부만 쳐도 잡힌다.**

| 입력 | 걸리는 타겟 |
|------|-------------|
| `Inner` | `browInnerUp`, `mouthInnerCorner` … |
| `inner` | 위와 동일 (**대소문자 무시**) |
| `eyeBlink` | `eyeBlinkLeft`, `eyeBlinkRight` |
| `brow up` | 여러 단어는 **AND** — `browInnerUp`, `browOuterUpLeft` … (v01.13~) |

- **v01.13 부터 공용 위젯** [`Framework_MOD_filter_qt`](Framework_MOD_filter_qt.md) 를 쓴다.
  Shape Editor 탭과 `A00145_RigConnect` 가 **같은 위젯**이라 검색 동작이 완전히 같다.
- **`Clear`** 버튼으로 필터를 비운다. `List Targets` 로 목록을 다시 채워도 **필터는 유지**된다.
- `Number` 라벨이 필터 중에는 **`보이는 수 / 전체 수`**(예: `Number: 2 / 9`)로 바뀐다.

> **필터가 걸린 동안에는 "보이는 것이 작업 대상"이다.** Qt 는 항목을 숨겨도 선택 상태를 유지하므로
> 그대로 두면 **가려서 안 보이는 타겟까지 Apply 가 먹는다.** 그래서 —
> - **`Select All`** 은 **지금 보이는 타겟만** 선택한다.
> - **`Apply`** 는 **보이면서 선택된** 타겟에만 적용하고, 가려진 선택이 있으면
>   `[Info] N selected target(s) hidden by the filter were skipped.` 로 알린다.
>   선택이 전부 가려져 있으면 아무것도 하지 않고 필터를 지우라고 안내한다.
>
> 여러 필터를 오가며 고른 타겟을 **한 번에** 적용하려면 **필터를 비운 뒤** Apply 하면 된다
> (선택 자체는 지워지지 않는다).

### 동작 원리
blendShape 결과는 `base + weight * delta` 이다(`delta` = 타겟 포인트 오프셋).
weight `X` 에서 보이던 모양을 weight `1.0` 의 모양으로 만들려면 **델타를 `X` 배**하면 된다:

```
new_delta = delta * X
weight 1.0 → base + 1.0*(delta*X) = base + X*delta = 예전 weight X 모양
```

즉 "값 X 의 모양을 1.0 의 기본 모양으로" == 타겟 포인트 델타를 `X` 배 스케일.
in-between 아이템과 다중 출력 지오메트리도 함께 스케일한다. 전체가 **단일 undo 청크**.

- Value `0.5` → 타겟 강도 절반, `1.3` → 과장, 음수 → 반대 방향.
- Value 는 0 이 될 수 없다(0 이면 델타가 사라지므로 경고).

### 델타를 X 배 하는 두 가지 경로 (v01.11)

타겟이 **어떻게 저장돼 있느냐**에 따라 손대는 곳이 다르다. Apply 는 아이템마다 자동 판정한다.

| 타겟 형태 | 판정 | 처리 |
|-----------|------|------|
| **baked** — 타겟 메시가 씬에 없고 델타만 노드에 굽힘 | `inputGeomTarget` 연결 없음 | `inputPointsTarget`(pointArray)을 `X` 배로 setAttr |
| **live** — 타겟 메시가 씬에 남아 연결돼 있음 | `inputGeomTarget` 에 셰이프 연결 | **타겟 메시의 정점을 직접 이동** |

> **왜 나눠야 하는가 (v01.11 에서 고친 버그)**: live 타겟에서 `inputPointsTarget` 은
> **연결된 메시로부터 매번 다시 계산되는 값**이다. 여기에 `setAttr` 을 하면 **에러 없이 조용히**
> 다음 평가에서 원래 값으로 돌아간다. v01.10 까지는 이 경우에도 "적용됨"이라고 보고만 하고
> 실제로는 아무 일도 일어나지 않았다 — 뷰포트가 잠깐 바뀐 것처럼 보이다가 **씬을 저장하거나
> Shape Editor 의 Edit 로 들어가는 순간**(= 재평가) 원래 모양으로 되돌아왔다.
> 이제는 타겟 메시 자체를 고치므로 **Apply 하는 그 순간 기본 모양이 바뀌고**, 저장·Edit 후에도 유지된다.

- **델타의 공간** (v01.16 에서 정정) — blendShape 의 **`origin` 어트리뷰트**가 정한다.

  | `origin` | 델타 | 타겟 정점을 옮길 때 |
  |----------|------|---------------------|
  | `1` = local (`cmds.blendShape` 기본) | `타겟 로컬 − 베이스 로컬` = **타겟 오브젝트 공간** | 그대로 `(X−1)×delta` |
  | `0` = world | `타겟 로컬 × 타겟 worldMatrix × 베이스 worldInverse − 베이스 로컬` = **베이스 오브젝트 공간** | `delta × (base.worldMatrix × target.worldMatrix⁻¹)` 로 되돌린 뒤 이동 |

  즉 world origin 이면서 두 오브젝트의 transform 이 다르면(회전 · 마이너스 스케일 · 비균등 스케일)
  델타는 **타겟 오브젝트 공간이 아니다**. 정점은 자기 오브젝트 공간으로만 옮길 수 있으니 되돌려야 한다.
  (이동량만 필요하므로 행렬의 3×3 부분만 쓴다 — 평행이동은 델타 차이에서 상쇄된다.)
- **이동은 `shape.pnts`(tweak) 구간 setAttr** 로 한다. 메시 데이터(`vrts`)를 건드리지 않아 undo 가
  정확히 맞고, 정점마다 `xform` 을 돌리는 것보다 훨씬 빠르다(19,462 정점 기준 **6.4초 → 0.17초**).
- live 타겟을 고치면 **씬의 타겟 메시가 실제로 움직인다**(그것이 곧 기본 모양이므로 당연한 결과).
  로그가 몇 개가 live 였는지 알려준다.
- 델타가 아예 없는 타겟(한 번도 편집되지 않음)은 건너뛰고 로그에 표시.
- **적용 후 자체 검증 + 자가 보정** (v01.16~) — 정점을 옮긴 뒤 델타가 **정말 `X` 배가 됐는지**
  정점 번호로 대조한다. 어긋나면 되돌리고, 타겟 정점을 x/y/z 로 한 번씩 밀어 **응답 행렬을 직접 재서**
  (선형이라 3번이면 3×3 이 나온다) 다시 시도한다. 그래도 안 맞으면 **타겟 메시를 원상복구**하고
  로그에 이유를 남긴다 — 조용히 틀린 모양을 만들지 않는다.

> [!bug] v01.15 까지 — 일부 정점만 반대로 스케일되던 문제
> 값 `0.5` 를 넣었는데 어떤 정점은 절반이 되고 어떤 정점은 `1.5` 를 넣은 것처럼 커졌다.
> 원인은 위의 **델타 공간**이다. `origin=world` 이고 타겟과 베이스의 transform 이 다르면
> (예: 좌우 대칭 타겟의 `scaleX = -1`, FBX 임포트로 생긴 `rotateX -90`, 프리즈된 복제본)
> 델타는 베이스 공간에 있는데 v01.15 까지는 그것을 그대로 **타겟 오브젝트 공간의 이동량**으로 썼다.
> 미러라면 X 성분만 부호가 뒤집혀 **X 로 움직인 정점만** 반대로 가고 Y/Z 로 움직인 정점은 멀쩡하다
> — 그래서 "정점마다 되기도 하고 반대로 되기도" 하는 것처럼 보였다.

## 탭 4 — Mix Targets  (v01.17~, 신규)

**소스 타겟 몇 개를 원하는 비율로 섞은 만큼, 체크한 다른 타겟들(과 원하면 최종 메시까지)을
한꺼번에 변형한다.**

> 예) 소스 `[a x1.0, b x0.5, c x0.8]` → 체크한 타겟들이 "a 를 100%, b 를 50%, c 를 80% 로
> 섞은 그 모양"만큼 변형된다.

여러 셰이프에 공통으로 들어가야 할 보정을 관련 타겟 전체에 한 번에 반영하거나, 기준 셰이프가
바뀌었을 때 그 차이를 나머지 타겟에 일괄 이식할 때 쓴다.

### 사용 흐름

1. **`<- Set`** — 씬에서 blendShape(또는 그 메시)을 고르고 누르면 노드가 잡히고 목록이 채워진다.
   바로 밑 **Base mesh 라벨**(v01.18~)에 **어떤 메시가 베이스이고 중립이 어디에 있는지** 표시된다:
   `Base mesh: head_geo (neutral: head_geoShapeOrig)`. 중립까지 가는 길에 오프셋을 통과시키지
   못할 디포머가 있으면 주황색으로 `- skinCluster1 in between, 'Deform it too' may not reach it;
   'New mesh' always works` 라고 알려 준다.
2. **Mix Sources**(왼쪽) — 섞을 타겟을 목록에서 고르고(하이라이트) `Amount` 를 정한 뒤
   **`Set to Selected`**. 그 행이 **체크되고 배율이 이름 옆에 표시**된다(`shp_b    x0.5`).
   소스마다 값이 다르면 한 행씩, 같으면 여러 행을 골라 한 번에.
3. **Targets to Modify**(오른쪽) — 변형할 타겟을 체크. **`Check All (visible)`** 체크박스 하나로
   지금 보이는 행을 전부 켜고 끌 수 있다(일부만 체크돼 있으면 부분 표시).
4. **Base mesh** — 최종 메시를 어떻게 할지 고른다(아래).
5. **`Apply Mix`** — 전체가 **단일 undo 청크**라 Ctrl+Z 한 번으로 되돌아간다.

| 요소 | 동작 |
|------|------|
| **Amount** | 그 소스를 얼마나 섞을지. `1.0` = 셰이프 전체, `0.5` = 절반, **음수 = 반대 방향으로 빼기** |
| **Use Scene Weights** | 체크된 소스의 배율을 **씬의 현재 weight 값**으로 채운다. 마야에서 눈으로 맞춘 그 상태를 그대로 굽고 싶을 때 |
| **Uncheck All** | 그 목록의 체크를 모두 해제 |
| **Filter** | 목록마다 따로. 공용 위젯([`Framework_MOD_filter_qt`](Framework_MOD_filter_qt.md)) |
| 소스 잠금 | 소스로 체크한 타겟은 오른쪽 목록에서 **회색으로 잠긴다** — 자기 자신에 자기를 더할 수는 없다 |

> [!note] 이 탭만 "체크된 것이 작업 대상"이다
> 다른 탭은 **"보이는 것이 작업 대상"**(필터에 가려진 선택은 제외)이지만, 여기서는 **가려져 있어도
> 체크된 것은 모두 적용**한다. 체크는 사용자가 명시적으로 남긴 상태이고, 목록이 둘이라 필터를
> 번갈아 쓰다 보면 쉽게 가려지기 때문이다. 대신 `Checked: 3 (1 hidden)` 처럼 **가려진 개수를
> 항상 표시**하고, 적용할 때도 로그로 한 번 더 알린다.

### 동작 원리

blendShape 평가 자체가 `base + Σ(weight × delta)` 다. 즉 **같은 지오메트리의 델타는 서로 같은
공간에 있고 그대로 더할 수 있다** — 마야가 매 프레임 하는 일과 같다. 그래서

```
mix        = Σ(amount × delta(source))
new_delta  = old_delta + mix        (Base mesh = Leave it alone 일 때)
```

손대는 방법은 대상이 어떻게 저장돼 있느냐에 따라 갈린다(Base Shape 탭과 **같은 코어**,
[`delta_utils`](#구조)):

| 대상 형태 | 처리 |
|-----------|------|
| **baked** | `inputPointsTarget` / `inputComponentsTarget` 을 새로 쓴다 (정점 집합이 늘어나므로 컴포넌트 목록도 갱신) |
| **live** | 타겟 메시의 정점을 옮긴다 — 델타 공간을 되돌려 옮기고, 결과를 **검증**한다 |

- **인비트윈**: 타겟의 **완성 모양(weight 1.0)** 만 바꾼다. 중간 단계까지 같은 오프셋을 더하면
  시퀀스가 통째로 어긋나기 때문. 인비트윈이 있는 타겟은 로그로 알린다.
- 델타가 아예 없던 타겟(한 번도 편집되지 않음)도 대상이 되면 완성 모양을 새로 만들어 준다.

### Base mesh — 최종 메시도 함께 변형하기

타겟은 "베이스로부터의 오프셋"으로 저장되므로 **베이스를 옮기면 델타를 그대로 둔 타겟이 따라
움직인다.** 그래서 세 갈래를 명시적으로 고른다. 규칙은 하나다 —
**체크한 것은 믹스만큼 변형되고, 체크하지 않은 것은 모양이 그대로다.**

| 선택 | 하는 일 |
|------|---------|
| **Leave it alone** (기본) | 베이스는 그대로. 체크한 타겟의 델타에 믹스를 더한다 |
| **Deform it too** | **중립(바인드) 셰이프**를 믹스만큼 옮긴다. 체크한 타겟은 델타를 유지해 따라 움직이고(live 타겟은 씬의 메시도 함께 이동), 체크 안 한 타겟은 **델타에서 믹스를 빼 제자리에 남긴다**(보정). 소스도 여기 해당 |
| **New mesh** | 리그는 전혀 건드리지 않고 `'중립 + 믹스'` 모양의 **새 메시**(`<base>_mixed`)를 하나 만든다. 히스토리·인터미디어트 없이 월드에 놓이고(위치는 그대로), 토폴로지·UV 는 베이스 메시에서 온다 |

> [!tip] 스킨이 칠해진 리깅 메시
> blendShape 이 체인 앞(front of chain)이면 입력은 결국 **바인드 셰이프**(`<base>ShapeOrig`)라,
> 그것을 옮기면 된다 — **skinCluster 는 그대로 살아 있고** 그 위에서 계속 동작한다.
> 실측: 바인드 포즈에서는 보이는 메시가 정확히 믹스만큼 움직이고, 포즈된 상태에서는 그 오프셋이
> 스킨을 타고 변형된다(리깅 관점에서 올바른 동작).

### 중립에 닿는 법 (v01.18 에서 고침)

`New mesh` 는 **언제나 만들어진다.** blendShape 입력 플러그가 들고 있는 메시 **데이터**를 직접
읽기 때문이다(`MPlug.asMObject()` → `MFnMesh`) — 상류가 무엇이든 상관없다.

`Deform it too` 는 **옮길 수 있는 셰이프**가 필요하다. 상류를 **한 단계만 보면 안 된다**:

| blendShape 앞 상황 | `input[0].inputGeometry` 상류 |
|---|---|
| 아무것도 없음 | `baseShapeOrig.worldMesh` (mesh) |
| **`tweak` 노드** — 정점을 한 번이라도 건드리면 생긴다 | `tweak1.outputGeometry[0]` |
| skinCluster 가 앞 | `skinCluster1.outputGeometry[0]` |
| 래티스가 앞 | `LAT.outputGeometry[0]` |

geometryFilter 는 모두 `input[N].inputGeometry` 로 거슬러 오를 수 있으므로 **메시가 나올 때까지
따라간다.** `tweak` 은 정점마다 값을 더하기만 하므로 상류에서 옮긴 만큼이 그대로 내려온다 —
그래서 tweak 이 낀 흔한 리그에서도 그대로 동작한다.

옮긴 뒤에는 **blendShape 이 실제로 받는 중립을 다시 읽어** 믹스만큼 움직였는지 검증한다.
사이에 낀 디포머가 오프셋을 바꿔 버리면(포즈된 스킨, 휘어진 래티스 …) **되돌리고** 이유와 함께
`New mesh` 를 안내한다 — 로그의 주장과 실제가 어긋나지 않는다.

> [!bug] v01.17 까지 — 리깅 메시에서 `New mesh` 가 아무것도 만들지 않았다
> 상류가 **메시일 때만** 중립으로 인정해서, `tweak`·스킨·래티스가 앞에 있으면 그대로 실패하고
> `could not reach the base (neutral) mesh ... Use the 'new mesh' option instead` (이미 New mesh 를
> 고른 상태인데도) 만 남겼다. 실측 4종 중 3종에서 못 찾았다.

> [!info] 델타 공간은 왜 신경 쓰지 않아도 되는가
> 베이스 포인트에는 **변환 없이** 그대로 더한다. blendShape 이 `output = base_point + Σ(w×delta)`
> 로 델타를 베이스 포인트에 그대로 더하기 때문에, 정의상 둘은 같은 공간이다.
> (mayapy 실측: 스킨 유무 · `origin` local/world · 베이스 회전 8조합에서, 중립을 `V` 만큼 옮기면
> 안 움직인 live 타겟의 델타가 정확히 `-V` 만큼 변한다.)
> 반면 **타겟 메시**를 옮길 때는 [Base Shape 탭의 델타 공간](#델타를-x-배-하는-두-가지-경로-v0111)
> 규칙이 그대로 적용된다.

## 탭 5 — Bake Delete  (v01.19~, 신규)

리깅된 메시에서 **페이스 · 엣지 · 버텍스를 지우고 나면** 마야는 지우기를 디포머 **뒤에** 붙인다.

```
blendShape  ->  skinCluster  ->  deleteComponent  ->  <보이는 메시>
```

리그는 여전히 **지우기 전 토폴로지**로 돌고, 지우기는 맨 끝에서 결과만 잘라낸다. 그래서
**보이는 메시와 타겟 메시가 서로 다른 메시**가 된다 — Shape Editor 로 타겟을 열거나 Edit BS 로
타겟을 뽑으면 지우기 전 모양이 나오고, 지운 부분을 다시 만난다.

이 탭은 지우기를 **체인 맨 앞(중립 셰이프)으로 옮긴다**. 결과는

```
blendShape  ->  skinCluster  ->  <보이는 메시>
```

이고 **중립 메시와 모든 타겟 메시가 같은 만큼 줄어든다**. **보이는 모양은 바뀌지 않는다** —
끝나면 툴이 직접 재 보고 로그에 편차를 적는다(실측 전 케이스 오차 `0`).

### 사용 흐름

1. 씬에서 **보이는 메시**를 선택 → **`<- Set`** (누르면 곧바로 Analyze 까지 돈다).
2. 리포트에서 무엇을 건드릴지 확인한다 — 히스토리 · 정점/페이스 수 · blendShape 타겟 수
   (live / baked) · skinCluster 인플루언스 · 함께 줄어들 live 타겟 메시 · 경고.
3. **`Bake Delete into the Rig`**.

> [!warning] 되돌리기
> 토폴로지를 갈아 끼우는 작업이라 **Ctrl+Z 로 완전히 돌아오지 않는다**(정점/웨이트 쓰기가
> OpenMaya API 라 undo 스택에 안 남는다). **작업 전에 씬을 저장할 것.**

| 요소 | 동작 |
|------|------|
| **`<- Set`** | 선택에서 대상 메시를 잡고 Analyze 실행 |
| **`Analyze`** | 씬을 **전혀 건드리지 않고** 히스토리만 조사해 리포트를 채운다 |
| 리포트 | 고정폭 글꼴. `Not ready: ...` 로 시작하면 그 이유가 곧 거절 사유다 |
| **`Bake Delete into the Rig`** | 실제 실행. 진행 상황은 창 아래 공용 로그에 한 줄씩 |

### 무엇을 다시 매핑하는가

정점 번호를 쓰는 데이터는 **전부** 새 번호로 옮긴다. 하나라도 빠뜨리면 조용히 엉뚱한 정점에 걸린다.

| 대상 | 내용 |
|------|------|
| 중립 셰이프(`<base>ShapeOrig`) | 줄어든 토폴로지 + 살아남은 정점의 위치로 교체 |
| live 타겟 메시 | 같은 방식으로 함께 줄인다. 자체 히스토리가 있으면 먼저 지운다(안 지우면 상류가 옛 토폴로지로 다시 덮어쓴다) |
| baked 델타 | `inputPointsTarget` / `inputComponentsTarget` 재번호. **인비트윈 아이템도 전부**. 지워진 정점의 델타는 버린다 |
| blendShape 페인트 웨이트 | `baseWeights` · `targetWeights` |
| skinCluster | `weightList` 전체 + `blendWeights`, 범위 밖 찌꺼기 항목 제거 |
| tweak / polyTweak | `vlist[0].vertex` · `tweak` 오프셋 |
| 디포머 멤버십 | `<orig>.componentTags`(마야 2022+) 와 `groupParts.inputComponents` |
| 그 밖의 weightGeometryFilter | `weightList[g].weights` (cluster · deltaMush 등) |

### 동작 원리

**1) 살아남은 정점 찾기.** deleteComponent 의 **입력 메시**(지우기 전)와 **출력 메시**(지운 뒤)를
플러그 데이터로 직접 읽어 위치로 맞춘다. 마야는 컴포넌트를 지울 때 **살아남은 정점의 상대 순서를
보존**하므로(실측), 앞에서부터 한 번만 훑는 greedy 매칭이면 된다(O(N)). 두 메시는 같은 계산
결과라 좌표가 비트 단위로 같아 매칭이 흔들릴 여지가 없다.

**2) 토폴로지로 검증.** 남은 메시의 모든 엣지를 매핑으로 되돌렸을 때, 그 두 정점이 원본에서
**같은 페이스 안에** 있어야 한다. 조건을 "같은 엣지"가 아니라 "같은 페이스"로 잡은 이유:

| 지운 것 | 결과 |
|---------|------|
| 페이스 | 남은 페이스가 원본 그대로 (엣지도 그대로) |
| 버텍스 | 그 정점만 빠지고 페이스가 한 변 줄어든다 → **없던 엣지가 생긴다** |
| 엣지 | 두 페이스가 **하나로 병합**된다 |

세 경우 모두 새로 생기는 엣지의 양 끝은 **원래 한 페이스 안에 있던 정점들**이다. 매핑이 한 칸이라도
밀리면 이 조건이 즉시 깨진다 — 조용히 틀린 리그를 만들지 않는다.

**3) 줄어든 토폴로지를 어디서 가져오는가.** **지금 보이는 메시를 복제**해 도너로 쓴다. 그 자체가
이미 "줄어든 토폴로지 + 올바른 UV/노멀"이다. 메시를 새로 조립하면 **UV 를 잃는다**. 도너의 정점만
대상 메시(중립 · 각 타겟)의 값으로 바꿔 `donor.outMesh -> dst.inMesh` 로 연결 → 평가 → 연결 해제
한다. 해제해도 마지막 데이터가 그대로 남는다(실측).

### 함정 (mayapy 2024 실측)

- **밀어 넣은 셰이프의 `pnts` 를 안 지우면 조용히 틀린다.** `pnts`(트윅) 인덱스는 지우기 전 번호라
  그대로 두면 **엉뚱한 정점에 옛 오프셋이 얹힌다**. 실측에서 live 타겟이 정확히 이것 때문에 깨졌다
  (오프셋이 새 번호 자리에 한 번, 옛 번호 자리에 또 한 번).
- **skinCluster 웨이트는 DAG 셰이프의 정점 수만큼만 읽힌다.** 지우기 뒤 셰이프는 이미 줄어 있어서
  `MFnSkinCluster.getWeights` 가 앞쪽 일부만 준다(25개 중 23개 — 게다가 **에러 없이**). 그래서 읽기
  전에 deleteComponent 를 `nodeState = 1`(HasNoEffect)로 잠깐 꺼 지우기 전 토폴로지로 되돌린다.
- **`baseWeights` / `targetWeights` 는 `setAttr` 로 써도 blendShape 가 더러워지지 않는다.** 값은
  바뀌었는데 화면은 그대로다. 그래서 끝에 `cmds.dgdirty` 로 명시적으로 흔든다.
- **디포머 멤버십은 이제 groupParts 가 아니다.** 마야 2022+ 는 `<orig>.componentTags[i]` 에
  이름 + 컴포넌트 목록으로 저장한다(`cmds.cluster` 가 groupParts 를 **아예 안 만든다**). 태그는
  우리가 지오메트리를 밀어 넣는 중립 셰이프에 **그대로 남으므로** 같이 고쳐 주지 않으면 디포머가
  엉뚱한 정점에 걸린다. 폴리 프리미티브가 기본으로 다는 `front` / `rim` 같은 태그는 아무도 안 쓰면
  경고하지 않는다(디포머의 `componentTagExpression` 이 참조하는 것만 본다).
- **`pnts` 를 정점마다 setAttr 로 지우면 9만 정점에서 40 초가 넘는다.** 연속 구간을 한 번에 쓰는
  `delta_utils.write_tweaks` 로 묶어 **2.5 초**로 줄였다(전체 apply 기준 46s -> 2.5s).

### 거절하는 경우

조용히 잘못된 결과를 내느니 멈추고 이유를 말한다.

| 상황 | 메시지 |
|------|--------|
| deleteComponent 가 없다 | `no deleteComponent after the deformers - this mesh has nothing to bake.` |
| 꼬리에 다른 노드가 있다(예: `polySoftEdge`) | `unsupported node(s) between the deformers and the mesh: ...` |
| polyTweak 이 지우기 **사이에** 끼어 있다 | `... sits between two deleteComponent nodes - its vertex numbers are only half reduced.` |
| 디포머가 없다 | `no deformer in front of the delete - just use Edit > Delete by Type > History instead.` |
| 정점을 못 맞추거나 검증 실패 | `could not match the vertices ...` / `vertex mapping failed validation - ...` |
| skinCluster 가 메시 여러 개를 구동 | `... only handles single-mesh skinClusters.` |

> `polyTweak` 은 지우기보다 **위**에 있으면 번호를 다시 매핑해 주고(정점을 옮긴 뒤 지운 흔한 경우),
> **아래**에 있으면 이미 새 번호라 그대로 둔다(지운 뒤 정점을 옮긴 경우).
