## 0. 결론 (진단 요약)

| 질문 | 답 |
|------|----|
| 원본에 그 기능이 있나 | **있다** — *Speed Graph* (기본 켜짐). 뷰포트 오른쪽 아래 모서리, 타이밍 차트 바로 위에 그려진다 |
| 세로축은 무엇인가 | **속도** = 프레임당 월드 이동 거리 (`speed_per_frame`). 위치값이 아니다. 1차 미분의 **크기**(방향 없음) |
| Smooth 는 무엇을 부드럽게 하나 | **속도(타이밍)** 다. **경로 모양은 그대로**, 키의 프레임도 그대로, 키의 포즈가 경로를 따라 미끄러진다. 정지(hold)는 정지로 남는다 |
| 경로 *모양* 을 부드럽게 하는 기능은 | 별개 도구 — **Smooth (Alt+S)** 의 *Shape* 모드("bumps 를 없애고 arc 와 timing 은 유지") · Smooth 스컬프트 브러시. 그래프와는 무관 |
| 마야에서 그대로 구현 가능한가 | **가능하다.** 필요한 재료(월드 경로 점 · 부모 공간 · 역산 `solve` · 레이어 β · 키 채우기)가 v01.00~v01.03 에 이미 있다. 새로 필요한 것은 ① 그래프 위젯 ② 호 길이 · 시간 왜곡(time warp) 수학 ③ **목표 움직임을 마야 애님 커브 키로 다시 맞추는 refit** (가장 큰 일) |
| 개선할 수 있나 | **있다** — §3. 핵심 셋: ① 그래프를 **툴 창 Qt 패널**로(크기 조절 · 마야 단축키와 충돌 없음 · 헤드리스 시험 가능), ② 그래프 모드에 **위치 X/Y/Z · 가속도** 추가(요청에 말한 "위치값" 도 보이게), ③ 선택 옵션 **Whole Pose** — 같은 시간 왜곡을 회전 · 스케일에도 적용해 위치만 리타임될 때 생기는 포즈 어긋남을 없앤다 |

> **정정할 점**: "그래프를 smooth 하면 경로가 부드럽게 그려진다" 는 원본 동작과 조금 다르다. 원본의 그래프 Smooth 는 **경로 위 프레임 점의 간격**(= 화면에 보이는 점 분포)을 고르게 한다 —
> 선(경로 모양)은 바뀌지 않는다. 경로 선 자체를 매끈하게 하는 것은 Shape Smooth 이고, 이 계획에서는 마지막 단계(G5)에 따로 둔다.

## 1. 원본 기능 확인 (MANUAL "Timing and speed" 요약)

### 1-1. 표시

- 뷰포트 모서리의 어두운 블록. 가로 = 프레임, 세로 = 속도. 키는 **세로선 + 프레임 번호**(선택 키는 주황), 현재 프레임은 초록.
- 범위 모드: *Segment*(선택 키 사이 · 키 하나면 양쪽 구간 · 없으면 현재 프레임 주변 키), *Range*(지정 범위), *Timeline*(씬 범위).
- 바로 아래 **타이밍 차트**: 키 사이 프레임이 어디 있는지 눈금으로(2D 애니메이터의 타이밍 차트). 눈금 드래그 = 프레임 점 드래그와 같다.
- 모서리 · 여백 · 크기 · 색은 환경 설정.

### 1-2. 그래프 위 조작

| 조작 | 결과 |
|------|------|
| 빈 곳 드래그 | 현재 프레임이 마우스를 따른다(스크럽) |
| 키 **세로선** 드래그 | 그 키를 **시간**으로 이동(포즈 전체, Ctrl = 서브프레임) |
| 키 **점** 위 · 아래 드래그 | 그 키에서 빠르게 / 느리게 — 양쪽 구간이 보상 |
| **곡선** 드래그 | 잡은 부분이 올라가면(빠르게) 나머지 구간이 보상. 휠 = *Reach*(퍼지는 범위, 기본 구간의 1/3, 넓히면 키를 넘어 이웃 구간까지) |
| **오른쪽 드래그** | **속도 Smooth 브러시** — 휠 = 반경, Shift+휠 = 세기. 여러 번 칠할 수 있고 Ctrl+Z = 마지막 획, Esc = 전부 취소, Enter / 클릭 = 끝. **세션 전체가 undo 한 번** |

### 1-3. Smooth 의 약속 (설계 조건으로 그대로 가져온다)

1. **경로 모양 유지** — 바뀌는 것은 "언제 경로 위 어디에 있나" 뿐.
2. **키 프레임 유지** — 키는 시간 축에서 움직이지 않고, 포즈가 경로를 따라 미끄러진다.
3. **브러시 밖 움직임 유지** — 브러시 범위 양 끝에서 위치가 원래와 같다(보상).
4. **정지는 정지** — 속도 0 구간을 번지게 하지 않는다.
5. 키 위에서도 막지 않는다 — 키에서 꺾인 속도 계단도 고르게 된다.
6. **필요한 곳에만 키를 추가**한다(원래 키로 목표를 못 따라갈 때).
7. **획마다 세션 시작 상태에서 다시 계산** — 여러 번 칠해도 경로가 흘러가지 않는다(오차 누적 없음).
8. 부모가 움직여 따라갈 수 없는 곳은 그 획에서 원래대로 둔다.

원본 개발 문서의 일반 구조: 구간의 **호 길이-시간 표**(SpaceJob)를 만들고 → 원하는 움직임을 "시간 t 에 원하는 호 길이" 함수로 정하고 →
호 길이를 시간으로 되돌려 `solve` 로 채널 값을 구한 뒤 → **refit**(키 · 핸들을 그 목표에 맞춤). Ease · Space · 이징 프리셋 · 속도 그래프가 전부 이 한 경로를 쓴다.
→ 이 계획도 같은 뼈대를 만들고, 그 위에 Smooth 를 첫 사용자로 올린다. 나중 타이밍 도구(Even · Ease · 이징 프리셋)는 목표 함수만 바꾸면 된다.

## 3. 개선안 (원본 대비)

### 3-1. 그래프를 툴 창 Qt 패널로 (추천, Q1)

- 원본은 뷰포트 모서리에 그린다 — 블렌더에서는 자연스럽지만, 마야에서 같은 것을 하려면 VP2 2D 그리기 + 컨텍스트 히트 테스트가 필요하고 휠 · 키보드는 받지 못한다.
- **Qt `QWidget.paintEvent`** 로 그리면: 크기를 마음대로(넓게 보면 정밀하게 칠할 수 있다), 휠 · 오른쪽 드래그 · 수식키를 그대로 받고, **오프스크린 헤드리스 시험**이 된다(v01.01 의 GUI 전용 버그 같은 일을 줄인다).
- 툴 창 아래에 접을 수 있는 **`Speed Graph`** 영역(공용 expand 위젯) + `Pop Out` 버튼(떠 있는 창으로 떼어 두 모니터에). 뷰포트 HUD 판은 필요하면 나중에.

### 3-2. 그래프 모드 — 요청의 "미분값 혹은 위치값" 둘 다

| 모드 | 세로축 | 쓰임 |
|------|--------|------|
| **Speed** (기본, 원본) | \|dP/df\| (cm/frame, 옵션 cm/s) | 타이밍 판단 · Smooth 대상 |
| Position | 월드 X · Y · Z (또는 Local = translate) 세 줄 | 위치 곡선 확인 — 뷰포트 경로만 보는 툴에서 그래프 에디터를 안 열고 본다. 1차는 **읽기 전용** |
| Acceleration | \|d²P/df²\| | 튐(pop) · 떨림 찾기(원본의 jitter 히트맵 역할을 그래프로). 높은 곳을 Smooth |

- **여러 경로 겹쳐 보기**: 경로마다 색. 예) 왼손 · 오른손 속도 비교. Smooth 는 **활성 경로 하나**(리스트에서 고른 것)에만.
- 원본처럼 키 세로선 + 프레임 번호, 선택 키 주황, 현재 프레임 초록, Smooth 미리보기는 **원래 곡선 회색 + 새 곡선 색**.

### 3-3. Whole Pose 리타임 (옵션, Q3)

- 원본 Smooth 는 경로 채널(위치)만 바꾼다. 손이 경로 위에서 더 일찍 도착해도 **회전은 원래 시간표** → 손목이 늦게 돈다.
- Smooth 결과를 **시간 왜곡 τ(f)** ("새 f 프레임 = 원래 τ(f) 순간의 위치") 로 표현하면, 같은 τ 를 회전 · 스케일 · 커스텀 채널에 `y_new(f) = y_old(τ(f))` 로 적용할 수 있다 → 포즈 전체가 같이 리타임.
  이 계산은 커브 평가뿐이라 싸다. refit 은 위치 채널과 같은 루틴.
- 기본값: **끔(원본과 같게)** 추천 — 위치만 고치고 싶은 경우가 더 흔하다. 체크 하나로 켠다.

### 3-4. 획 중에는 미리보기, 놓을 때 쓰기

- 원본은 칠하는 동안 매 dab 마다 커브에 쓴다. 우리 refit(최소제곱 + 키 추가 반복)은 dab 마다 돌리기엔 무거울 수 있다.
- **드래그 중**: 목표 점만 계산해 **경로 · 프레임 점 · 그래프를 미리보기로** 그린다(커브 안 씀, 수 ms). **획을 놓을 때** refit → 커브에 쓰기 → 오브젝트가 따라온다.
  G0 에서 refit 이 16 ms 안이면 원본처럼 매 dab 쓰기로 바꾼다.

### 3-5. 버튼으로도 — 브러시 없이 범위 Smooth

- `Smooth Speed` 버튼: 그래프 범위(또는 선택 키 사이) 전체를 `Radius` · `Strength` · `Passes` 로 한 번에. 모캡 정리 · 여러 경로 일괄에 편하다(원본 API `smooth_speed` 에 해당).

### 3-6. refit 오차를 보여 준다

- 쓰기 뒤 "max error 0.012 cm at frame 37, keys added 2" 를 로그로. 허용 오차(`Tolerance`)와 키 추가 상한을 옵션으로. 원본은 보고만 하고 조절은 없다.

## 4. 설계 (수학 · 코드)

### 4-1. 조밀한 경로 — 서브프레임 위치 (G0 에서 결정)

시간 왜곡은 "원래 경로의 호 길이 s 지점" 을 찾아야 하므로 정수 프레임 사이 위치가 필요하다.

| 방법 | 내용 | 비용 · 정확도 |
|------|------|---------------|
| **A. 서브프레임 굽기** | 세션 시작 때 그래프 범위만 `PM` 을 h = 0.25 프레임 간격으로 추가로 굽는다. 자기 채널은 커브를 그 시간에 평가 | 정확. 1,000 프레임이면 굽기 3,000 회 추가(v01.00 실측 비례로 약 0.4~0.6 초) — 세션당 한 번 |
| **B. 정수 프레임 스플라인** | 이미 있는 월드 점(정수 프레임 + 키 시간)에 centripetal Catmull-Rom 을 씌워 호 길이 · 위치를 그 위에서 | 굽기 없음. 부모가 프레임 사이에서 빠르게 돌면 오차. 뷰포트 경로도 이 점들을 직선으로 이은 것이라 "보이는 경로" 와는 더 맞다 |

추천: **B 로 시작, G0 에서 A 와의 차이를 잰다**(빠른 팔 스윙 · 회전하는 부모 씬). 차이가 경로 크기의 0.5% 를 넘는 씬이 있으면 A 를 옵션으로.

### 4-2. 속도 · 호 길이

- 조밀 표본 `u_j = a + j·h` (h = 0.25), 위치 `P_j`, 구간 길이 `d_j = |P_{j+1} − P_j|`, 누적 호 길이 `s_j`.
- 그래프의 속도 `v(f)` = 정수 프레임에서 `(s(f+½) − s(f−½))` (= cm/frame). 표시용은 이 값, Smooth 계산은 조밀 표본의 `v_j = d_j / h`.
- 가속도 모드: `|P(f+1) − 2P(f) + P(f−1)|`.

### 4-3. Smooth 한 dab (세션 상태에서 매번 다시)

입력: 중심 프레임 `fc`, 반경 `r`(프레임), 세기 `k`(0.1~1). 세션 상태 = 시작 때 경로(모양 고정) + 지금까지 획이 만든 속도 `v`.

1. 가중치 `w_j = k · falloff(|u_j − fc| / r)` (smooth falloff, 0 밖).
2. 흐린 속도 `v̄ = Gauss_σ * v` (σ ≈ r/3, 반경보다 조금 넓게 본다 — 원본 "the blur sees a little past the brush").
3. 섞기 `v' = (1 − w)·v + w·v̄`.
4. **정지 유지**: 원래 `v < hold_eps`(기본 경로 크기의 1e-4 /frame) 인 표본은 `v' = 0`, 그 바로 옆 표본에서 흐림이 정지로 새어 들어가지 않게 마스크를 흐림 전에도 적용.
5. **보존**(약속 3): 브러시 지지 구간 `[fc − r, fc + r]` 에서 `∫v' = ∫v` 가 되게 차이를 `w·v'` 비례로 되돌려 나눈다 → 양 끝 호 길이가 원래와 같다 → 브러시 밖은 그대로.
6. 새 호 길이 `s'(u) = s(a) + Σ v'·h`, 정수 프레임(+ 키 시간) `f` 마다 `s'(f)`.
7. **시간 왜곡** `τ(f) = s⁻¹(s'(f))` (원래 표에서 역보간), 목표 월드 점 `W(f) = P_orig(τ(f))` — 경로 위 점이라 모양이 유지된다.
8. `solve(row(f), W(f))` → 편집 레이어 값(β, 레이어 v01.03 그대로). 부모가 그 프레임에 그 점에 닿게 못 하는 축(β≈0)은 NaN → 그 프레임은 원래 값(약속 8).
9. Whole Pose 이면 다른 채널도 `y(τ(f))` 로 목표를 만든다.

dab 한 번 = 배열 연산 몇 번. 1,000 프레임 × h 0.25 에서 1 ms 대 예상(G0 측정).

### 4-4. refit — 목표 값 → 마야 애님 커브

목표: 영향 구간의 정수 프레임마다 채널 목표 값 `y*(f)`. 조건: **키 프레임 유지**, 키 수는 가능한 한 그대로.

1. **영향 구간** = 브러시 지지 구간을 덮는 키 구간들(양 끝 바깥 키는 고정 — 값 · 탄젠트 모두 그대로).
2. 안쪽 키의 **값** = 그 키 시간의 목표 값.
3. **기울기 최소제곱**: 마야 비가중 탄젠트의 한 구간은 큐빅 Hermite
   `y(t) = h00·y0 + h10·Δt·m0 + h01·y1 + h11·Δt·m1` — 기울기 `m` 에 **선형**. 구간 안 모든 정수 프레임의 오차 제곱합을 최소로 하는 `m` 을 푼다.
   - 키의 in/out 이 묶여 있으면(unify, 기본) 이웃 구간이 공유 → 전체가 띠 행렬 하나(numpy `lstsq`).
   - 바깥 고정 키 쪽 기울기는 상수로 옮긴다(이음매 연속).
   - 가중 탄젠트: 핸들의 **시간 길이를 고정**하면 각 `t` 의 Bezier 매개변수 `u` 가 고정 → 값은 다시 기울기에 선형. 길이는 원래 값 유지.
4. 탄젠트 타입은 **fixed** 로(마야 auto / spline 은 값이 바뀌면 다시 계산해 버린다 — 상위 계획서 0-5). 바뀐 키만.
5. **오차 검사**: `max |y_fit − y*|` 가 `Tolerance`(기본 0.01 cm, UI 단위 표시)보다 크면 그 프레임에 키를 넣고 3 으로(상한 `Max Added Keys`, 기본 구간당 3).
   **매 프레임 키 커브**(모캡)는 이 단계 없이 값만 쓴다(최소제곱 불필요, 가장 빠름).
6. 쓰기: `MFnAnimCurve.setValue / setTangent / addKey` 를 세션의 `MAnimCurveChange` 하나에. 레이어는 편집 레이어 커브에만(β 역산 결과).
7. 계산식이 마야와 같은지 **골든 시험**: 임의 키 · 탄젠트 커브에서 우리 Hermite 평가 = `MFnAnimCurve.evaluate` (차 < 1e-9, 비가중 · 가중, 시간 단위 24/30/60 fps).

### 4-5. 세션 · undo — `SpeedSession` (`DragSession` 과 같은 모양)

- **시작**(첫 오른쪽 누름): 대상 경로 고정, 조밀 경로 · 호 길이 표 · 원래 커브 스냅샷, `ensure_keys` 는 **처음 실제로 쓸 때 한 번**.
- **획 놓기**: 이전 기록 `change.undoIt()` → 새 `v` 로 처음부터 refit → 새 change. (획마다 커브 상태가 "세션 시작 + 모든 획" 하나로 정확히 정해진다 — 흘러감 없음.)
- **획 되돌리기**(Ctrl+Z / `Undo Stroke` 버튼): 획 스택에서 하나 빼고 다시 계산. **Esc / `Cancel`**: 세션 전체 되돌림.
- **끝**(Enter / `Apply` / 그래프 밖 클릭 / 다른 경로 고르기 / 툴 바꾸기): `junMotionPathSetKeys` 로 **undo 한 번** 등록.
- 세션 중 바깥에서 그 커브가 바뀌면(그래프 에디터 · 다른 툴 — watcher 가 우리 쓰기와 구분) 그 시점에서 **자동 Apply** 하고 끝낸다(상태가 엇갈리지 않게).
- Qt 패널의 Ctrl+Z 는 마야 단축키가 먼저 가져갈 수 있다 → 패널에 포커스가 있을 때만 `QShortcut`(WidgetWithChildrenShortcut) + **버튼으로도 항상 가능**하게. GUI 확인 항목.
