### 1-2. 기능

- **Add Array Chain**: 맞물린 고리 체인 메시(Array 모디파이어).
- **Add Bone Chain**: 메시를 뼈 N개(기본 12)로 리깅. 뼈 사이 선형 웨이트. `CF_Root`(전체 이동) · `CF_Tip`(끝 컨트롤).
- **Secondary Animation**: 뼈마다 `CF_Tip` 을 향하는 **Damped Track** 제약. `Influence` 슬라이더(뿌리 쪽은 더 따라가고 끝은 느슨하게).
- **Wind (실시간)**: Strength · Direction · Speed · Wavelength · Flutter · Cross Sway · Stiffness · Randomness.
- **Presets**: `Slow Flow` · `Breeze` · `Fast Flutter`, 각각 **옵션 2개** + **Mix 슬라이더**(옵션 1 → 2 사이를 섞는다). 지금 값과 일치하는 프리셋 버튼이 눌린 상태로 보인다.
- **Hair**: 머리카락 한 가닥 / 여러 가닥(2~24). 가닥마다 **시간 지연**(기본 14 프레임)이 있어 서로 꼬이듯 흔들리고, `Lock Variation` 이 가닥마다 리듬을 조금씩 다르게.
- **Apply to an object**: 임의 메시에 같은 리그 · 바람.

### 1-3. 운동 모델 (우리 말로 정리)

뼈 `i`(뿌리 0 … 끝 n−1), `u = i/(n−1)`(뿌리 0 → 끝 1), 시각 `T = 프레임 + 가닥 지연`.

1. **두 개의 진행파.** 축 방향 파 `a_i(T)` 와 옆 방향 파 `b_i(T)` — 둘 다 `sin(ωT − 2π·(뼈 위치)/파장)` 꼴로 뿌리에서 끝으로 흘러간다.
   옆 파는 주파수가 조금 낮고 위상이 약 ¼ 주기 늦다 → 끝이 **고리를 그린다**.
   `Randomness` 는 위상을 느리게 흔드는 저주파 사인과 빠른 잔물결 사인을 더해 **불규칙한 리듬 · 돌풍**을 만든다(0 이면 순수 사인).
2. **뼈마다 로컬 회전(누적).**
   - 바람 방향 성분 = `Strength × (0.3 + 0.7u)` (일정한 기울기, 끝으로 갈수록 큼) + `Flutter × u^Stiffness × a_i`
   - 옆 성분 = `CrossSway × Flutter × u^Stiffness × b_i`
   - 둘 다 `× k0 / (1 − 0.7·Influence)` — `k0 = 12/n` 은 **뼈 개수가 달라도 같은 모양**이 되게 하는 정규화,
     `1/(1−0.7q)` 는 끝 따라가기(아래 3)가 깎아 먹는 만큼 키우는 보정.
   - `Direction` 각으로 두 성분을 뼈의 두 수직 축(블렌더 뼈 X · Z)에 나눠 넣는다.
   - **차분이 아니라 각 뼈의 로컬 회전에 그대로** 넣는다 → FK 로 끝까지 누적된다(A00390 Lite 와 다른 점, 3장).
3. **끝 따라가기.** 모든 뼈에 `CF_Tip` 을 향하는 Damped Track, 영향력 = `1 − (1 − min(0.999, Influence·k))^(12/n)` (`k` 는 뿌리 1 → 끝 0.55).
   바람 회전 **위에서** 제약이 섞이므로, 최종 모양은 "누적 회전" 과 "끝을 향한 직선" 의 혼합이다.

> 끝 뼈까지 누적된 기울기를 프리셋 값으로 그냥 더하면 **280~430도**가 나온다(아래 1-4). 실제로 그렇게 말리지 않는 이유가 3번의
> 끝 따라가기다. **프리셋을 같은 그림으로 옮기려면 1 · 2 · 3 을 함께 옮겨야 한다.**

## 2. A00390 V02 와의 비교

A00390 V02 탭: `Sine`(조인트마다 사인 키 / 노드) · `Chain Wave`(커브 + ikSpline) · `Chain Wave Lite`(각도만, 커브 · IK 없음).
가장 가까운 것은 **Lite** 다: `theta_k = swing · ramp_k · sin(2π(s_k/λ − t/period))`, 로컬 회전 `= theta_k − theta_(k−1)`(차분, 한 축).

| 항목 | Waves Gen | A00390 V02 (Lite) | 이식 가치 |
|------|-----------|-------------------|----------|
| 진행파 | ○ | ○ | — |
| 진폭의 뜻 | 뼈마다 **로컬 각도**(누적) | 뼈의 **월드 각도**(차분으로 누적 상쇄) | 모델 차이 — 3장 |
| 일정한 기울기(바람에 눕기) | ○ `Strength` | ✕ | **높음** — 실제 바람은 평균적으로 한쪽으로 눕는다 |
| 바람 방향 | ○ `Direction`(각도, 실시간) | 축 선택(X/Y/Z, 빌드 때) | **높음** — 방향을 키로 돌릴 수 있게 |
| 옆 흔들림(고리) | ○ `Cross Sway` | ✕(한 축) | **높음** — 머리카락 · 리본이 살아 보이는 핵심 |
| 끝으로 갈수록 크게 | `u^Stiffness`(지수) | `Root Ramp`(선형) | 중간 — 지수 하나 추가 |
| 불규칙 · 돌풍 | ○ `Randomness` | ✕ | **높음** — 기계적인 반복 제거 |
| 프리셋 + Mix | ○ 3 × 2 + Mix | ✕ | **높음** — 요청의 핵심 |
| 뼈 개수 정규화 | ○ `k0 = 12/n` | 파장은 거리 기준(Auto Period) | 중간 — 같은 프리셋이 뼈 수와 무관하게 |
| 끝 컨트롤 따라가기 | ○ Damped Track + Influence | ✕ | 중간 — 프리셋 재현에는 필요(1-3), 애니메이터 손맛에도 좋음 |
| 가닥(체인)마다 시간 지연 | ○ Time Offset 14 f | ○ `Node Offset` / `windPhaseOffset` | 이미 있음 |
| 가닥마다 리듬 차이 | ○ `Lock Variation` | ✕ | 중간 — 털 · 풀 다발에 유용 |
| 실시간 속도 변경 | 슬라이더(재생 중 키 X, 바꾸면 위상이 튐) | `windSpeed` 적분(키도 됨, **V02 는 느림 · V03 빠름**) | A00390 이 이미 우위 |
| envelope · 체인 수백 개 | ✕ | ○ `windEnvelope`, Lite 는 가벼움 | A00390 우위 |
| 메시 · 리그 생성 | ○ | ✕(기존 리그에 붙임) | 낮음 — 마야는 리그가 이미 있다 |

**보완점 요약** — 기울기 · 방향(실시간) · 옆 흔들림 · 불규칙성 · 프리셋 + Mix · 뼈 수 정규화 · 끝 따라가기 · 가닥 변주.
**우리 쪽이 나은 점(지킬 것)** — 속도 적분(키로 바꿔도 역행 없음) · envelope · Lite 의 가벼움 · 루트 따라가는 드라이버 · 디버그 커브.

## 3. 프리셋 이식 — 세 가지 수준

| 수준 | 방법 | 결과 | 비용 |
|------|------|------|------|
| **A. 숫자 매핑** | Lite 드라이버에 환산값만 넣는다(주기 · 파장 · 스윙 각도) | **비슷한 느낌**만. 기울기 · 옆 흔들림 · 끝 따라가기가 없어 Breeze 와 Fast Flutter 의 차이가 거의 주기 차이로만 남는다 | 작음 |
| **B. 모델 이식** | Waves Gen 의 운동 모델(1-3 의 1 · 2)을 **새 모드**로 구현 → 프리셋 값을 **같은 뜻으로** 그대로 | 끝 따라가기 없이도 같은 리듬 · 같은 파형 · 같은 비율. 크기는 끝 따라가기 보정만큼 다르다 | 중간 |
| **C. 모델 + 끝 따라가기** | B + 끝 컨트롤을 향한 조준을 영향력으로 섞기(1-3 의 3) | **같은 그림**. 블렌더 기준 데이터와 끝 위치 오차로 대조 | 큼 |

**권장: B 로 시작해 C 까지.** A 는 "프리셋을 그대로" 라는 요청을 만족하지 못한다.
B 만으로도 프리셋 이름에 맞는 움직임(느린 S 곡선 / 산들바람 / 빠른 펄럭임)은 나온다. C 는 "블렌더와 같은 그림" 이 필요할 때.

> **Lite 를 고치지 않고 새 모드로** 만든다. Lite 의 '차분' 모델은 "뼈의 월드 방향이 사인을 그린다" 는 다른 정의이고,
> 기존 씬의 룩이 바뀌면 안 된다. 새 모드 이름(안): **`Flow`** 탭.

## 4. 설계 — `Flow` 탭 (새 모드)

### 4-1. 드라이버 어트리뷰트 (체인마다 로케이터 하나, 전부 키 가능)

| 어트리뷰트 | 뜻 | Waves Gen 대응 | 단위 |
|-----------|----|---------------|------|
| `windLean` | 바람에 눕는 정도 | Strength | 도 (뼈 12개 기준) |
| `windDirection` | 바람 방향(뼈 둘레) | Direction | 도 |
| `windFlutter` | 파동 크기 | Flutter | 도 / 뼈 (12개 기준) |
| `windCross` | 옆 흔들림 비율 | Cross Sway | 0~1 |
| `windSpeed` | 축 방향 파의 주파수 | Speed | **Hz**(초당 주기, fps 무관) |
| `windWavelength` | 체인 위 파동 수의 역수 | Wavelength | 뼈 12개 기준 단위 (체인 위 파동 수 = 12/값) |
| `windStiffness` | 뿌리 고정 정도 | Stiffness | 지수 |
| `windRandom` | 불규칙성 · 돌풍 | Randomness | 0~1 |
| `windFollow` | 끝 따라가기 | Influence | 0~1 (단계 C 에서 의미가 생긴다) |
| `windEnvelope` | 전체 영향력 | (없음) | 0~1 — 기존 A00390 규칙 그대로 |
| `windPhaseOffset` | 체인 시간 지연 | Time Offset | 초 |
| `windVariation` | 체인마다 리듬 차이 | Lock Variation | 0~1 |
| `windPreset` · `windPresetMix` | 프리셋 · 옵션 1→2 | Presets · Mix | enum · 0~1 (5장) |

### 4-2. 뼈마다 노드망 (뼈 k)

```
시간 위상     phi = 2π · windSpeed · (windPhaseTime − windPhaseOffset)           ← 체인 공유, V03 위상 엔진
공간 위상     psi_k = 2π · (k · 12/n) / windWavelength                            ← 체인 공유 상수 × 어트리뷰트
파 a_k        = sinLUT(phi − psi_k + R1(phi)) + windRandom · 0.4 · sinLUT(빠른 잔물결)
파 b_k        = (주파수 · 위상이 다른 같은 꼴)
포락 e_k      = (k/(n−1)) ^ windStiffness                                         ← multiplyDivide power
축 성분       along_k  = (windLean · (0.3 + 0.7u_k) + windFlutter · e_k · a_k) · (12/n) · G
옆 성분       across_k = (windCross · windFlutter · e_k · b_k) · (12/n) · G
방향 분배     rotA_k = along·cos(dir) + across·sin(dir),   rotB_k = along·sin(dir) − across·cos(dir)
→ 뼈 k 의 로컬 회전 두 축(뼈 진행축에 수직인 두 축)에 rest 회전과 더해 연결   × windEnvelope
```

- `G = 1/(1 − 0.7·windFollow)` 는 단계 C(끝 따라가기)가 있을 때만 켠다(B 에서는 1).
- **사인은 기존 A00390 의 `sineLUT`(animCurve)** 를 그대로 쓴다 — 마야 2023 에 sin 노드가 없다([[maya-2023-compat]]).
- `cos(dir)` · `sin(dir)` 은 체인 공유 노드 2개(방향을 키로 돌려도 실시간).
- 뼈 진행축 · 두 수직축은 rest 자세에서 구해 **Lite 의 `Rotate Axis (object)` 처럼 로컬 채널 직결**을 기본으로, 축이 비스듬하면 Lite 의 쿼터니언 경로를 재사용.
- **추정 노드 수**: 뼈당 약 25~30(LUT 4 포함) — 12뼈 체인 약 330. Lite(9조인트 84)보다 무겁다. 단계 1 에서 `windRandom` 항을 끌 수 있게(빌드 옵션 `Randomness terms`)해 뼈당 약 15로 줄이는 판도 둔다.

### 4-3. 끝 따라가기 (단계 C)

- 체인 끝에 `Tip` 컨트롤(로케이터)을 만들고, 뼈마다 **조준 회전**(끝을 향한 방향)을 `aimConstraint` 를 프록시에 걸어 얻는다.
- 바람 회전(4-2)과 조준 회전을 `pairBlend`(쿼터니언 보간)로 섞는다. 가중치 = `1 − (1 − min(0.999, windFollow·k_i))^(12/n)`, `k_i` 뿌리 1 → 끝 0.55.
- 블렌더의 Damped Track 은 "Y 축을 목표로 돌리는 최소 회전" 이라 마야 `aimConstraint`(업 벡터 없음 = `worldUpType none`)와 같은 성질이다 — 기준 데이터로 확인한다.
- 프록시가 생기므로 Lite 의 "프록시 없음" 장점이 사라진다 → **옵션**(`Tip Follow`, 기본 OFF)으로.

## 5. 실시간 속성 변화 설계

### 5-1. 모든 값이 라이브

노드망이므로 드라이버 어트리뷰트를 **채널 박스에서 바꾸면 즉시**, **키를 걸면 재생 중에** 바뀐다. 진폭(`windFlutter`) · 기울기 · 방향 · 옆 흔들림 · 불규칙성 · 파장 · 강성 · envelope 전부.

### 5-2. 프리셋을 라이브로 — 두 가지 방식

| 방식 | 하는 일 | 장점 | 단점 |
|------|---------|------|------|
| **① 값 쓰기**(Waves Gen 과 같음) | 프리셋 버튼 / Mix 슬라이더가 드라이버 어트리뷰트에 **숫자를 써 넣는다** | 단순, 노드 0개, 쓴 뒤 자유롭게 손질 | Mix 를 키로 애니메이션할 수 없다 |
| **② 라이브 프리셋**(마야 전용, 권장 추가) | 드라이버에 `presetA_*` · `presetB_*`(옵션 1 · 2 값)와 `windPresetMix` 를 두고 `blendTwoAttr` 로 섞은 값이 실제 어트리뷰트를 구동 | **Mix 를 키로** — "Slow Flow 옵션 1 → 2 로 3초 동안 거세짐" 이 재생 중에 된다. 프리셋 간(Slow ↔ Fast) 전환도 같은 방식 | 어트리뷰트 · 노드가 늘고, 구동되는 어트리뷰트는 직접 손질할 수 없다(→ `Bake Preset to Values` 버튼으로 ①로 되돌림) |

UI: `Slow Flow` / `Breeze` / `Fast Flutter` 버튼(지금 값과 맞는 것이 눌려 보임) · `Option 1` / `Option 2` · `Mix` 슬라이더 · `Live preset (keyable Mix)` 체크.

### 5-3. 속도를 실시간으로 — 위상 적분 문제

- 위상은 `∫ 속도 dt` 여야 한다. `속도 × 시간` 으로 하면 속도를 낮추는 순간 파동이 **거꾸로 간다**(A00390 v01.04 에서 실측 · 수정한 문제).
- Waves Gen 은 `프레임 × 속도` 라서 슬라이더를 움직이면 **위상이 튄다**(재생 중이면 순간 점프). 우리는 이걸 고친 상태로 이식한다.
- 경로:
  - `windSpeed` 상수 → 노드 3개(V03 기본 경로).
  - `windSpeed` 키 → V03 의 `windPhaseEngine`(씬 표현식 1개, 키 데이터를 직접 적분 — 프레임 번호와 무관한 비용).
  - **라이브 프리셋의 Mix 를 키로 걸 때** 실효 속도 = `lerp(옵션1 속도, 옵션2 속도, Mix(t)) × windSpeed(t)` 이다.
    → 엔진이 `windPresetMix` 의 키도 읽어 **두 커브의 곱을 적분**하도록 넓힌다(Mix 가 선형 보간이면 구간마다 닫힌 식, 아니면 프레임 단위 수치 적분을 키가 바뀔 때만 캐시).
- **V02 에 넣으면** 이 엔진이 없다 — V02 의 표현식은 `getAttr -time` 으로 프레임마다 처음부터 다시 적분해 체인 30개에 16 fps 까지 떨어진다(V03 CHANGELOG 실측). 그래서 8장 결정 1.

### 5-4. fps

Waves Gen 은 프레임 단위라 fps 가 바뀌면 속도가 바뀐다. 마야 쪽은 **초 단위(Hz)** 로 저장한다: `windSpeed(Hz) = 0.13 × Speed × 24 / 2π`. 프리셋 표(1-4)의 '주파수' 열이 그 값이다. 30 fps 씬에서도 같은 초당 리듬.

## 7. 검증

### 7-1. 순수 모델 ↔ 마야 노드망

`flow_model.py` 가 같은 수식으로 뼈마다 로컬 회전을 계산 → mayapy 로 노드망을 만들고 프레임 1 · 7 · 33 · 100 의 rotate 를 비교(Lite · V03 때와 같은 방식, 목표 1e-9).
무작위 파라미터 200세트 + 프리셋 6벌 + 뼈 3 · 12 · 40개 + 키 걸린 Speed / Mix.

### 7-2. 블렌더 기준 데이터 (골든) — **승인 필요**

- 이 PC 에 Blender **4.0.2**(Steam)가 있다. 애드온 매니페스트는 4.2+ 지만 스크립트는 4.0 API 로도 돌 가능성이 높다(확인 필요).
- 방법: `blender -b --factory-startup --python probe.py` — 애드온을 불러 직선 메시에 뼈 12개 리그 → 프리셋 6벌 적용 → 프레임 1~48 의 뼈 월드 행렬을 json 으로 저장.
  측정 스크립트는 이미 써 두었다([`A00390_wavesgen_blender_probe.py`](A00390_wavesgen_blender_probe.py) — 애드온 코드는 수정 · 복사하지 않고 불러 실행만).
  실행: `blender.exe -b --factory-startup --python A00390_wavesgen_blender_probe.py -- <출력.json>`
- **2026-11-05 실행 시도는 자동 권한 검사에서 막혔다**(외부에서 받은 코드 실행). 사용자가 직접 `! "<blender.exe>" -b ...` 로 돌리거나, 실행을 허락하면 단계 1 에서 진행.
- 대조 기준: 단계 B 는 **파형의 리듬 · 위상**(끝 위치의 주파수 · 위상차, 끝 따라가기 보정 G 제외 상태), 단계 C 는 **끝 위치 자체**(목표: 체인 길이의 1% 이내).
- 블렌더 뼈 축(Y 진행, roll 기준 X)과 마야 조인트 축(보통 X 진행) 차이는 비교 스크립트에서 좌표 변환으로 맞춘다.

### 7-3. 실시간

- 채널 박스 값 변경 → 다음 프레임 평가에 반영(mayapy 에서 setAttr 후 getAttr).
- `windSpeed` · `windPresetMix` 에 키 → 위상이 단조 증가(역행 프레임 0).
- 재생 비용: 체인 수별 ms(V03 실측 표와 같은 조건).
