# 폴 타깃 오브젝트(A') 자동 배치 — 툴 제작 계획서

> **한 줄**: 세 오브젝트 `[p1, p2, p3]` 에 대해
> `A = (p1+p3)/2`, `v = p2−A` 일 때 **`A' = A + n·v` 에 늘 붙어 있는 오브젝트**를 만든다.
> IK 의 폴 벡터 타깃으로 쓰고, `A00130_ControlRig_V02` 의 케이지 디테일 세팅에도 쓴다.

---

## 1. 요약 — 결론부터

| 물음 | 답 |
|---|---|
| **지금 툴로 만들 수 있나?** | **없다.** 조각은 있는데 이 조합을 하는 툴이 없다 (2장) |
| **어렵나?** | **아니다.** 수식이 `pointConstraint` **하나로 환원**된다 (3장) |
| **노드가 몇 개 드나?** | **3개** — 컨스트레인트 1 + `plusMinusAverage` 1 + `multiplyDivide` 1 (4장) |
| **어디에 만드나?** | **`A00060_jointTool_V03` 의 `Chain > Pole Target` 하위 탭** (6장) |

**핵심은 수식을 먼저 정리한 것**이다. 노드망을 짜기 전에 전개해 보면:

```
A' = A + n·v = A + n·(p2 − A) = (1−n)·A + n·p2
   = ((1−n)/2)·p1  +  n·p2  +  ((1−n)/2)·p3
```

**세 점의 가중 평균이고 가중치 합이 언제나 1이다** — 이것이 바로 `pointConstraint` 다.
직접 벡터 노드망을 짤 필요가 없다.

---

## 2. 진단 — 기존 툴로 되나

저장소를 훑었다. **조각은 다 있는데 이 조합을 하는 것은 없다.**

| 툴 | 갖고 있는 것 | 왜 이걸론 안 되나 |
|---|---|---|
| **`A00145_RigConnect`** | `pointConstraint` 생성(Parent/Point/Orient/Scale) · `weightAliasList` · `targetWeight` 를 **읽고 다룬다**(타깃 교체·이전) | **가중치를 *지정*하는 기능이 없다.** 만들면 세 타깃 모두 1.0 → 그냥 무게중심이 된다 |
| **`A00060_jointTool_V03`** | 폴 벡터 **수학**(`desired_pole_vector_world`) · 폴 벡터 컨스트레인트 역산 · `Create IK` 가 폴 타깃을 **받는다** | 전부 **일회성 계산**이다. 조인트를 움직이면 안 따라온다. 그리고 폴 타깃을 **받기만** 하지 만들지 않는다 |
| **`A00170_driverTool` · `A00150_remapVal` · `A00160`** | `multiplyDivide` · `plusMinusAverage` 노드망을 짠다 | 도메인이 다르다(커브 부착·리맵·구면 눈). 이 조합은 없다 |
| **`A00130_ControlRig_V02`** | 케이지 세팅 전 단계 | 폴 타깃의 **위치를 매칭**할 뿐, 만들지 않는다 |

> **가장 가까운 것은 `A00145` 다** — 컨스트레인트를 만들고 가중치 플러그까지 이미 안다.
> 빠진 것은 **"가중치를 얼마로 줄지"** 하나뿐이다. 그래서 "새 툴"보다 **작은 기능 하나**다.

## 3. 수학 — `pointConstraint` 하나로 환원된다 ★

```
A  = (p1 + p3)/2
v  = p2 − A
A' = A + n·v
   = (1−n)·A + n·p2
   = ((1−n)/2)·p1 + n·p2 + ((1−n)/2)·p3
```

| n | 가중치 (w1, w2, w3) | A' 이 있는 곳 |
|---|---|---|
| 0 | (0.5, 0, 0.5) | **A** — 두 끝점의 중점 |
| 1 | (0, 1, 0) | **p2** 자리 |
| 2 | (**−0.5**, 2, **−0.5**) | A 에서 v 만큼 두 배 밖 |
| −1 | (1, −1, 1) | 반대쪽 |

**가중치 합 = (1−n)/2 + n + (1−n)/2 = 1** — n 이 무엇이든 항상 1이다.
`pointConstraint` 는 `Σ(wᵢ·pᵢ) / Σ(wᵢ)` 로 계산하므로 **정규화가 결과를 바꾸지 않는다.**

**실측 — 전 범위에서 수식과 정확히 일치한다**

```
n= 0.0  [10.0,  0.0, -1.50]   OK        n= 2.0  [10.0,  8.0,  5.50]   OK
n= 0.5  [10.0,  2.0,  0.25]   OK        n= 3.0  [10.0, 12.0,  9.00]   OK
n= 1.0  [10.0,  4.0,  2.00]   OK        n=-1.0  [10.0, -4.0, -5.00]   OK
n= 1.5  [10.0,  6.0,  3.75]   OK        n=-0.5  [10.0, -2.0, -3.25]   OK
```

조인트를 어느 것을 움직여도 따라오고, **타깃에 회전·이동한 부모가 있어도** 맞는다
(컨스트레인트가 `parentInverseMatrix` 를 알아서 처리한다).
**조인트가 아니라 로케이터 3개여도 된다** — 월드 위치만 쓴다.

---

## 4. 실측으로 갈린 것 ★★

### 4-1. 가중치는 **음수가 될 수 있어야 하는데 `setAttr` 이 막는다**

`n > 1` 이면 양 끝 가중치가 음수다. 그런데:

```
attributeQuery(minExists) : True     min : 0.0
setAttr(w0, -0.25) -> RuntimeError: Cannot set the attribute ... below its minimum
```

**하지만 연결은 최소값을 우회한다:**

```
연결 후 getAttr(w0) = -0.25
결과 = [10.0, 6.0, 3.75]  =  수식(n=1.5)   OK
```

> **→ 가중치는 반드시 `setAttr` 이 아니라 *연결*로 넣는다.**
> ([[addattr-min-max-raises-not-clamps]] 의 뒷면이다 — `setAttr` 은 막히고 **연결은 통과**한다.
> 이걸 모르면 `n>1` 에서 툴이 통째로 막힌다.)

이건 부수 효과가 아니라 **이득**이다. 어차피 연결로 넣을 거라면 `n` 을 **살아 있는
어트리뷰트**로 두는 게 공짜다.

### 4-2. 직접 짠 벡터 노드망은 **틀렸다** (그래서 안 쓴다)

처음에 `plusMinusAverage` 로 `p1+p3` 를 만들어 봤더니 값이 어긋났다.
**`jnt_02.translate` 는 로컬**이기 때문이다 — 체인에서 `jnt_02` 의 translate 는 `jnt_01`
기준이다. 월드로 하려면 `decomposeMatrix` 셋 + 결과를 부모 공간으로 되돌릴 `multMatrix`
까지 **노드가 8개쯤** 필요하다.

**`pointConstraint` 는 그 전부를 공짜로 해 준다.** 월드 위치를 쓰고, 결과를 타깃의
부모 공간으로 되돌린다.

### 4-3. 세 점이 **일직선이면 쓸 수 없다**

`v = 0` 이 되어 **n 이 얼마든 A' 은 A 에 머문다**(실측). 폴 벡터로 못 쓴다.
드문 일이 아니다 — **관절을 아직 굽히지 않은 T 포즈**가 딱 그 상태다.
→ 만들 때와 `Check` 때 **경고**한다.

## 5. 설계

### 5-1. 만드는 것 — 노드 3개

```
poleTgt                      (locator / joint / group - 고를 수 있게)
  └ .poleDistance            = n   (keyable, 기본 1.0)

poleTgt_pointConstraint1     타깃 3개 : p1, p2, p3
poleTgt_oneMinusN            plusMinusAverage (subtract) : 1 − n
poleTgt_side                 multiplyDivide  (divide)    : (1−n)/2

연결
  poleTgt.poleDistance ──────────────► con.p2W1
  poleTgt.poleDistance ──► oneMinusN ──► side ──┬──► con.p1W0
                                                └──► con.p3W2
```

**`n` 을 바꾸면 즉시 따라간다.** 어트리뷰트 하나만 만지면 되므로 리거가 폴 거리를
눈으로 맞출 수 있다.

### 5-2. 왜 `n` 을 어트리뷰트로 빼나

- 4-1 때문에 **어차피 연결해야 한다** — 상수를 넣으나 어트리뷰트를 넣으나 노드 수가 같다
- 나중에 **컨트롤러의 어트리뷰트로 옮기거나** 다른 것이 구동하게 하기 쉽다
- 세 폴 타깃이 같은 값을 쓰게 하려면 한 곳에 연결하면 된다

옵션으로 **`n` 을 다른 노드의 어트리뷰트에 두기**(`Host` 필드)를 둔다 — 기본은 타깃 자신.

### 5-3. 어떤 오브젝트로 만드나

| 종류 | 언제 |
|---|---|
| **locator** (기본) | 폴 타깃은 보이기만 하면 된다. 씬에서 눈에 잘 띈다 |
| `joint` | 케이지가 조인트로 통일돼 있을 때 (`A00130` 의 `helper_polTgt_*` 처럼) |
| `group`(empty transform) | 아무것도 안 보이게 |

**이름**은 `<가운데 오브젝트 이름>_polTgt` 를 기본으로 하고 필드로 고칠 수 있게 한다.

### 5-4. `A00130` 이 부를 수 있게

로직은 **`app/core/pole_target_manager.py`** 에 둔다. UI 를 안 거치고 부를 수 있어야
`A00130_ControlRig_V02` 가 `ik_edit_manager` 를 쓰듯 import 해 쓸 수 있다
(그 툴은 이미 `A00060` 을 그렇게 부른다).

```python
from tools.A00060_jointTool_V03.app.core import pole_target_manager as pt
pt.create(["jnt_01", "jnt_02", "jnt_03"], distance=1.5, kind="joint",
          name="helper_polTgt_arm_l")
```

### 5-5. 이미 있는 것을 다시 만들지 않는다

같은 이름이 있으면 **덮어쓰지 않고** 알린다. 기존 것의 `poleDistance` 만 바꾸고 싶으면
`Update` 로 간다(5-6).

### 5-6. 기능 셋

| 버튼 | 하는 일 |
|---|---|
| **`Create`** | 선택한 3개(또는 TSL 목록)로 폴 타깃을 만든다. **undo 한 스텝** |
| **`Check`** | 무엇이 만들어질지 · 일직선인지 · 이름이 겹치는지. **씬 불변** |
| **`Update`** | 이미 있는 폴 타깃의 `n` 을 바꾼다 (노드는 그대로) |
| **`Bake`** | 컨스트레인트·노드를 지우고 **그 자리에 굳힌다** (살아 있을 필요가 없어졌을 때) |

`Bake` 는 케이지를 넘길 때 쓴다 — 리그에 노드가 남는 걸 원치 않는 경우가 있다.

## 6. 어디에 만드나 — **`A00060_jointTool_V03`**

| 후보 | 판단 |
|---|---|
| **`A00060_jointTool_V03`** ★ | **여기.** `Chain` 카테고리에 `Create IK` · `IK Edit` 이 이미 있고, **`Create IK` 가 폴 타깃을 *받는다*** — 그걸 *만드는* 단계가 바로 앞에 오는 게 자연스럽다. `A00130` 이 이미 이 툴을 import 한다 |
| `A00145_RigConnect` | 컨스트레인트 도메인이라 가깝지만, **폴 벡터는 IK 개념**이다. A00145 는 "임의의 오브젝트를 잇는" 툴이고 이건 특정 리깅 관용구다 |
| `A00130_ControlRig_V02` | 소비자지 주인이 아니다. 케이지 밖에서도 쓸 기능이다 |
| 새 툴 `A004xx` | **과하다.** 노드 3개짜리 기능에 툴 하나는 무겁고, 아이콘·드롭파일·런처까지 딸려온다 |

**위치**: `A00060_jointTool_V03` → `Chain` 카테고리 → **`Pole Target`** 하위 탭
(`Create IK` **왼쪽**에 둔다 — 만들고 나서 IK 에 물리는 순서다).

```
Chain ─┬─ Pole Target   ← 신규
       ├─ Create IK
       └─ IK Edit
```

## 7. 리스크

| # | 리스크 | 대응 |
|---|---|---|
| 7-1 | **`setAttr` 로 가중치를 넣으면 `n>1` 에서 죽는다** | 반드시 **연결**로 넣는다(4-1). 검증에 `n=2·3` 을 넣어 못박는다 |
| 7-2 | 세 점이 일직선이면 **폴 벡터로 못 쓴다** | 만들 때·`Check` 때 **경고**(4-3). 만들기는 한다 — 나중에 굽히면 살아난다 |
| 7-3 | 세 점의 **순서를 잘못 주면** 엉뚱한 곳에 간다 | 순서가 `[끝, 가운데, 끝]` 임을 UI 에 적고, **선택 순서**를 쓴다([[tsl-selection-order]]). `Check` 표에 세 이름을 순서대로 보여 준다 |
| 7-4 | 타깃의 translate 가 **이미 구동되고 있으면** 컨스트레인트가 실패한다 | 미리 보고 건너뛴다([[wip-a00130-pair-constrain]] 와 같은 판정) |
| 7-5 | 같은 이름이 이미 있는데 덮어쓴다 | **덮어쓰지 않는다**(5-5). `Update` 로 유도 |
| 7-6 | 노드 이름이 겹쳐 **다른 폴 타깃의 노드를 건드린다** | 노드 이름을 타깃 이름에서 파생시키고, 만든 뒤 **실제 이름을 되돌려** 쓴다(마야가 이름을 바꿀 수 있다) |
| 7-7 | `Bake` 후 되돌릴 수 없다 | undo 한 스텝으로 묶는다. 버튼 툴팁에 분명히 적는다 |
