# A00630_MotionPathEditor — 매니퓰레이터 · 폴오프 편집 하위 계획서

> 작성 2026-11-20 · 상태: **G0 헤드리스 실측 완료(35/35) · GUI 실측 대기** · 상위 계획서 [`A00630_MotionPathEditor_plan.md`](A00630_MotionPathEditor_plan.md) §5 **1.5단계 "프레임 단위 편집 · 비례 편집"** 의 하위 계획
> · 형제 계획서 [`A00630_MotionPathEditor_speed_graph_plan.md`](A00630_MotionPathEditor_speed_graph_plan.md) (Speed 탭 · 획 세션 · refit — 이 계획이 그대로 재사용한다)
>
> 요청 (2026-11-20):
> 1. Path 탭에서 **Edit Path** 를 켜고 그려진 경로의 점을 고르면, 고른 점을 **이동 · 회전하는 매니퓰레이터**가 나온다.
> 2. 경로에서 점을 고르고 **`b` 를 누른 채 마우스로 끌면 폴오프 범위**를 정한다. 범위 안의 점은 **색이 바뀌고, 강도에 따라 색이 다르다.**
>    이후 매니퓰레이터로 이동 · 회전하면 폴오프 가중치만큼 함께 움직인다.
> 3. **Speed 탭에도 Edit Path 버튼**이 있어야 한다. 경로를 고치면 **Speed 그래프가 라이브로** 따라 바뀐다.
> 4. Speed 탭에서 Edit Path 를 켜고 폴오프로 점들을 고를 수 있다. 폴오프 범위의 프레임을 [a, b] 라 하면 **그래프의 [a, b] 구간도 강도에 따라 색이 바뀐다.**
>    그 상태에서 **Smooth Range** 를 누르면 그 범위의 경로가 **위치 스무딩**된다.

## 0. 요약

| 요청 | 방법 (한 줄) | 새로 만드는 것 | 재사용 |
|------|--------------|----------------|--------|
| 1 매니퓰레이터 | 플러그인이 **직접 그리는 이동 · 회전 기즈모**(축 화살표 · 평면 · 회전 고리), 편집 컨텍스트가 집어서 끈다 | `core/gizmo.py`(모양 · 고르기 · 끌기 수학) · 플러그인 그리기 | `picking.ray_axis/ray_plane` · `ViewState` |
| 1 점 고르기 | 키뿐 아니라 **프레임 점도 고른다** (선택 단위 = 경로 · 프레임 시간) | `path_manager` 선택 모델 확장 | 박스 선택 · Shift/Ctrl 규칙 그대로 |
| 2 폴오프 | **경로를 따라 잰 프레임 거리**로 가중치 `w(f)`. `b`+끌기 = 반경. 색 = 가중치 색표 | `core/falloff.py`(마야 비의존) · `b` 키 감지 | 공용 `Framework/core/falloff_curve` + `JUN_mod_falloffCurve_qt`(모양) |
| 1+2 편집 쓰기 | 고른 점 · 가중치 → **목표 경로** → 기존 **획 세션**(`StrokeSession`)에 새 모드 `deform` → 놓을 때 refit, **undo 한 번** | `speed_session.MODE_DEFORM` | `StrokeSession` 의 미리보기 · 차이만 쓰기 · refit · 레이어 β |
| 3 Speed 탭 Edit Path | 같은 편집 컨텍스트 하나를 **두 탭의 버튼이 함께** 켜고 끈다. 끄는 동안 세션 미리보기를 그래프가 그린다 | 관리자 신호 `preview_changed` | Speed 패널의 미리보기 곡선(회색 = 원래, 색 = 새) |
| 4 그래프 [a, b] 색 · 위치 Smooth | 그래프 배경에 프레임마다 `w(f)` 색 띠. Smooth Range = 브러시 결과를 `w(f)` 로 섞는다 | `ShapeSmoother/AccelSmoother.apply_mask` | Smooth Shape(Taubin) · Smooth Acceleration |

- **씬을 바꾸는 것은 지금처럼 애님 커브 키뿐이다.** 매니퓰레이터 · 폴오프 · 선택은 씬 노드를 만들지 않는다(그리기 노드의 데이터일 뿐, undo 큐 밖).
- **한 동작 = Ctrl+Z 한 번** (매니퓰레이터 끌기 한 번 · Smooth Range 한 번). 여러 경로를 함께 끌어도 한 번.
- 폴오프 반경이 0 이고 **키만** 골랐으면 지금의 키 끌기(`DragSession`)를 그대로 쓴다 — 오브젝트가 끄는 동안 바로 따라오고 결과가 정확하다(회귀 없음).

| Q4 | 폴오프 편집 중 오브젝트 | **끄는 동안은 경로 · 그래프 미리보기**(원래 경로 회색 점선 + 새 경로), **놓을 때 키를 쓰고 오브젝트가 따라온다** | Speed 탭 획과 같은 방식. 끄는 중 매번 refit + 쓰기를 하면 키가 들어갔다 빠졌다 해서 undo · 정확도가 흔들린다 (§3-3) |

| Q6 | `b` 를 **눌렀다 떼기만** 하면 | **폴오프 켜기 / 끄기 토글**(마야 소프트 셀렉션의 `b` 와 같은 기대). 끄면 반경은 기억 | 반경을 0 으로 끌어 내리는 것보다 빠르다 |

## 2. 사용 흐름 (완성 모습)

```
[ Path ] [ Speed ]
┌ Edit ─ [   Edit Path   ] [Refresh]                                  ┐
│   Manipulator (o) Move ( ) Rotate     Axes (o) World ( ) Path        │
│   [x] Falloff  Radius [  8.0 fr]  [Curve...]   (b + drag = radius)   │
│   Drag in (o) View ( ) Ground ( ) X ( ) Y ( ) Z     (가운데 점 끌기)  │
│   3 point(s) selected · falloff 21 frame(s) [32, 52]                  │
```

1. Path 탭(또는 Speed 탭)의 **Edit Path** 를 켠다 → 두 탭의 버튼이 함께 연한 빨강.
2. 경로의 **키 점 또는 프레임 점**을 클릭 / 박스로 고른다 → 고른 점에 **매니퓰레이터**가 나온다(고른 점들의 무게중심).
3. **`b` 를 누른 채 왼쪽 버튼으로 좌우로 끈다** → 반경이 늘고 줄고, 범위의 점 · 선이 **가중치 색**(§3-2)으로 칠해진다. 화면에 `Falloff 8.0 fr` 이 따라다닌다.
4. 매니퓰레이터의 **축 화살표 · 평면 사각형 · 가운데**를 끌면 이동, **Rotate** 모드면 **고리**를 끌어 회전.
   고른 점은 1, 범위의 점은 `w(f)` 만큼 따라온다. 끄는 동안 원래 경로가 회색 점선, Speed 그래프도 같이 움직인다.
5. 놓으면 키에 쓰고 오브젝트가 따라온다 — **Ctrl+Z 한 번**. 오른쪽 버튼 / Esc = 취소.
6. Speed 탭: 그래프 배경의 [a, b] 가 같은 색표로 칠해져 있다. **Smooth Range** = 그 범위만, 가중치만큼 위치 스무딩(undo 한 번).

## 3. 설계

### 3-1. 선택 모델 — 키에서 프레임 점으로

- 지금: `manager.selection = {cache.key: {키 시간}}`, 고를 수 있는 것 = `pickable()` = 키.
- 바꿈: 선택 값은 그대로 **시간 집합**이지만 **프레임 점(cache.times 의 모든 시간)도** 고를 수 있다. 키 시간은 키 점으로, 그 밖은 프레임 점으로 그린다.
- 고르기 우선순위: 같은 픽셀 반경 안이면 **키 > 프레임 점**(지금 동작 유지). `Display > Frame dots` 가 꺼져 있으면 프레임 점은 고르지 않는다(안 보이는 것을 고르지 않는다).
- 선택은 지금처럼 undo 큐 밖 · 경로를 빼면 정리(`_prune_selection`).
- 선택 점 색: 키 = 지금의 주황(크게), 프레임 점 = 같은 주황(작게).

### 3-2. 폴오프 — `app/core/falloff.py` (마야 · Qt 비의존)

```
d(f) = 고른 시간들 중 가장 가까운 것과의 |f − s| (프레임)          # Q2: 경로를 따라 잰 거리
w(f) = curve( 1 − d(f) / R )   (d < R),  0 (그 밖),  고른 점은 1
[a, b] = w > 0 인 프레임의 처음 · 끝 (경로마다, 선택 덩어리가 여럿이면 덩어리마다)
```

- `curve` = 공용 `Framework/core/falloff_curve.evaluate` (기본 Smooth 프리셋). `Curve...` 버튼 = 공용 팝업 `JUN_mod_falloffCurveDialog_qt_v01`(가로축 = 고른 점 → 범위 끝).
- 고른 점이 여럿이면 **가장 가까운 고른 점** 기준(가중치 최대값) — 사이 구간이 1 로 메워지지 않고 각 점 둘레로 부드럽다.
- 반경 `R` 은 프레임, 소수 허용, 0 = 폴오프 없음. 설정에 저장(`falloff_radius`, `falloff_on`, `falloff_curve`).
- **색표**(마야 소프트 셀렉션과 같은 기대): 1 = 노랑 → 0.5 = 주황 → 0 에 가까울수록 빨강 → 어두운 빨강. 범위 밖은 경로 원래 색.
  `color_for(w)` 하나를 뷰포트 · 그래프가 함께 쓴다(같은 색이 두 곳에 보인다).
- 그리기: 플러그인 `_draw_path` 가 **점마다 색**을 받는다 — `MUIDrawManager.mesh(kPoints / kLineStrip, 점, None, 색 배열)` (§4-2 실측).
  선도 범위 구간만 색 선분으로 덧그려 범위가 한눈에 보이게 한다.

### 3-3. 편집 쓰기 — 획 세션의 새 모드 `deform`

새 세션을 만들지 않고 **`StrokeSession` 에 모드 하나**를 더한다. 이미 있는 것:
상태 = `cache.times` 의 월드 점 (N,3)(Shape · Accel 모드와 같은 꼴) · 미리보기(`preview_points` · `preview_speed`) ·
**늘 세션 시작 경로에서 계산 + 직전 상태와의 차이만 커브에 더하기**(흘러가지 않음) · 레이어 β 역산 · refit(키 프레임 유지 · 필요한 곳만 키 추가) ·
`end_stroke` = `junMotionPathSetKeys` 로 undo 하나 · `valid()` 로 바깥 변경 감지.

```
끄기 시작   s.begin_stroke();  P0 = s.stack[-1];  w = falloff.weights(times, selected, R, curve)
이동        P = P0 + w[:,None] * Δ
회전        P = pivot + R(w·θ, axis) (P0 − pivot)     # 점마다 각도를 w 로 줄인 회전 (축 = 고리 축)
            s.set_state(P)   → 미리보기 · 그래프 라이브
놓기        s.end_stroke()   → refit + 쓰기, undo 한 번
취소        s.drop_stroke()
```

- `set_state(P)` 하나만 새로 붙인다(Shape 모드의 `dab` 자리에 들어가는 것). 쓰기 · undo · 레이어는 **한 줄도 새로 안 쓴다.**
- 피벗 = 고른 점들의 무게중심(기본). 옵션 `Pivot = First selected / Current frame` 은 나중.
- 축 `Axes`: World(기본) / **Path** = 고른 점 자리의 접선 · 법선 · 종법선(경로를 따라 미는 · 옆으로 미는 동작이 쉬워진다).
- **여러 경로**를 함께 고르면 경로마다 세션 하나, 놓을 때 `undoInfo` 묶음 하나로 감싼다 → Ctrl+Z 한 번.
- **폴오프 0 + 키만 고름** → 지금의 `DragSession`(키 값 직접, 오브젝트가 끄는 동안 따라옴). 그 밖(프레임 점 포함 또는 폴오프 > 0) → `deform` 세션.
  - 프레임 점 하나를 폴오프 없이 끌면 그 프레임 둘레에 키가 들어간다 — **G0 실측: 끈 축에 3개**(뾰족한 점 + 양옆이 원래 곡선에서 벗어나지 않게 붙드는 키).
    상위 계획 1.5단계의 `Insert key`(키 하나 + 이웃 모양 변화)와 달리 **범위 밖은 정확히 그대로**다.
- 허용 오차: Speed 탭 `Tolerance %` 를 함께 쓴다. 로그 = 축마다 남은 오차 · 넣은 키 수(지금 Speed 획과 같은 줄).
- 매 프레임 키(모캡)는 값만 바뀌므로 정확하고 키가 늘지 않는다 — 이 기능이 가장 빛나는 경우(상위 계획서 1.5단계 "모캡에서 핵심").

### 3-4. 매니퓰레이터 — `app/core/gizmo.py` + 플러그인 그리기

- **모양**(화면 크기 고정 — 카메라 거리에 비례해 월드 크기를 정한다):
  - Move: X/Y/Z 화살표(빨 · 초 · 파), 평면 사각형 XY · YZ · ZX, 가운데 사각형(= `Drag in` 평면으로 자유 이동).
  - Rotate: X/Y/Z 고리 + 바깥 화면 고리(시선 축 회전). 끄는 동안 각도 숫자 표시.
  - 끄는 중인 부분은 노랑(마야와 같은 기대).
- **고르기**(`gizmo.hit(view, x, y)` → `"x" / "xy" / "center" / "rx" / "rv" / None`): 축 · 고리를 화면에 투영해 픽셀 거리로. 기즈모가 점보다 **먼저** 고려된다.
- **끌기 수학**: 축 = `picking.ray_axis`, 평면 = `picking.ray_plane`, 회전 = 고리 평면 위에서 피벗 기준 시작 벡터 → 지금 벡터의 부호 있는 각도
  (시선과 거의 평행한 고리는 화면 접선 방향 이동량으로 대신 — 마야 회전 툴과 같은 처리).
- 그리기 데이터는 지금처럼 `draw_bridge.HUD` 에 둔다(경로 노드 하나가 그린다, `owner`). 2D 선이 아니라 3D 선 · 원뿔 — x-ray 로 경로 위에.
- 마야 매니퓰레이터를 쓰지 않는 이유는 Q3. 단, 모양 · 색 · 끄는 감각은 마야 Move/Rotate 를 따른다.

### 3-5. `b` 키와 컨텍스트 안 단축키 — 가장 큰 기술 위험 (§4 실측 G1)

`draggerContext` 는 **마우스 버튼 · Shift/Ctrl/Alt 만** 알려 준다. `b` · `w` · `e` 는 마야 핫키로 먼저 간다
(`b` = 마야 소프트 셀렉션 반경 조절 / 켜기 — 그대로 두면 **마야 소프트 셀렉션 설정이 바뀐다**).

| 안 | 방법 | 판단 |
|----|------|------|
| A (추천) | 편집 컨텍스트가 켜져 있는 동안만 **Qt 이벤트 필터**(마야 메인 창 · 뷰포트 패널)가 `B / W / E` 누름 · 뗌을 받아 **먹는다**(핫키로 안 감). `b` 누름 상태를 기억하고, 그 상태의 왼쪽 끌기 = 반경 조절 | 마야 설정을 안 건드린다. **GUI 에서만 확인 가능** — 핫키가 Qt 이벤트보다 먼저 처리되면 실패 |
| B | 컨텍스트가 켜져 있는 동안 핫키 `b` 를 툴 명령으로 바꿔 끼우고 나갈 때 되돌린다 | 마야가 비정상 종료되면 사용자 핫키가 바뀐 채 남는다 → 원래 값을 optionVar 에 적어 두고 다음 실행 때 복구 |
| C (안전망) | 창의 `Radius` 칸 · 슬라이더 + **Ctrl+Shift+왼쪽 끌기** = 반경 조절 | 키 감지 없이 늘 된다. A · B 가 다 막혀도 기능은 쓸 수 있다 |

- 메모 [[maya-viewport-tab-is-mtk]]: 뷰포트 `Tab` 은 MTK 가 가로채 핫키를 무시했다 — 뷰포트 키 처리는 **실측 없이 장담하지 않는다.** 그래서 C 를 처음부터 함께 넣는다.
- 반경 조절 감각: 가로 1 px = 0.1 fr (기본, 경로 길이 비례 보정 옵션), 위아래는 무시. 끄는 동안 `Falloff 8.0 fr` 을 커서 옆에 그린다.
- `w` / `e` 는 A 가 되면 Move / Rotate 전환에 쓴다. 안 되면 창의 라디오만.

### 3-6. Speed 탭 — Edit Path 버튼 · 라이브 그래프 · [a, b] 색

- Speed 패널 위쪽 줄에 **Edit Path** 버튼(Path 탭 버튼과 같은 모양 · 같은 동작). 편집 컨텍스트는 **창에 하나**, 두 버튼은 같은 상태를 보인다
  (지금의 `_sync_edit_button` 이 두 버튼을 함께 맞춘다 — 툴이 바뀌어도, `Q` 로 나가도).
- **라이브**: 관리자에 `preview_changed(cache_key, points or None)` 를 둔다. 매니퓰레이터를 끄는 동안 deform 세션의 미리보기를 보내면
  Speed 패널이 받아 **회색 = 원래 곡선, 색 = 새 곡선**으로 그린다(그래프 획과 같은 그림). 놓으면 `None` → 커브에서 다시 읽은 실제 결과.
  Speed · Position · Acceleration 세 보기 모두 같은 미리보기에서 계산.
- 그래프가 보이는 경로(`Path` 콤보)와 끄는 경로가 다르면 흐린 경로로만 갱신.
- **[a, b] 색**: 그래프 배경에 프레임마다 `color_for(w(f))` 세로 띠(반투명), 고른 프레임은 진한 세로선. 곡선의 [a, b] 부분도 같은 색으로 덧그린다.
  `Frames` 에 **`Falloff`** 항목을 하나 더한다 — [a, b] 앞뒤로 반경만큼 여유를 둔 구간만 보기(선택이 없으면 Whole Path 처럼).
- Speed 탭에서 Edit Path 를 켜도 그래프 위 마우스 동작(오른쪽 = 브러시, 왼쪽 = 끌기 · 스크럽)은 그대로다. 점 고르기는 **뷰포트에서** 한다.

### 3-7. Smooth Range + 폴오프 = 위치 스무딩

```
폴오프 선택이 있으면:  S = smoother.smooth_all(P0, 반복 = 브러시 세기에서)      # Smooth Shape(Taubin) 또는 Smooth Acceleration
                       P = P0 + (w · strength)[:,None] * (S − P0)
                       s.set_state(P); s.end_stroke()          → undo 한 번
없으면: 지금 그대로(보이는 구간 전체에 브러시)
```

- `ShapeSmoother` · `AccelSmoother` 에 **가중치 배열을 받는** `apply_mask(state, weights, strength)` 를 더한다(지금의 `dab` 은 가우스 브러시 모양을 안에서 만든다 — 그 모양 대신 `w` 를 쓰는 것).
- 브러시가 Smooth Speed 면 Q5 대로 Smooth Shape 로 하고 로그 `Falloff smoothing smooths the position - used Smooth Shape.`
- 버튼 글자는 그대로 `Smooth Range`, 폴오프가 있으면 툴팁 · 로그가 `Smooth the falloff range [32, 52] (weighted).` 로 바뀐다.
- 범위 밖 점은 차이가 정확히 0 → 키 그대로(세션 원칙).
