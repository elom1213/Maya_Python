# A00440_SetTool — Set Tool (사용 안내)

컴포넌트를 원소로 갖는 **마야 오브젝트 세트들끼리 집합론의 기본 연산**을 수행하는 툴이다.
합집합 · 교집합 · 차집합으로 새 세트를 만들고, 씬에서 고른 컴포넌트를 기준으로
세트 하나를 두 조각으로 **분할(split)** 한다.

탭은 둘이다 — **`Edit`**(있는 세트를 다룬다, v01.00 의 기능 전부) 와
**`Create`**(오브젝트마다 세트를 하나씩 만든다, v01.01).

- 버전: `v01.01` (`app/config/version.py`) — **탭 2개 : `Edit` / `Create`** (§7)
- 위치: `JUN_All/tools/A00440_SetTool`
- 형태: 아키텍처 (B) — Maya 내 PySide 툴. 집합 연산 로직은 `maya.cmds` 무의존

## 2. 연산

| 버튼 | 식 | 결과 |
|------|-----|------|
| `Union ( ∪ )` | A ∪ B ∪ … | 어느 한 세트에라도 들어 있는 원소 전부 |
| `Intersection ( ∩ )` | A ∩ B ∩ … | 모든 세트에 공통으로 들어 있는 원소 |
| `Difference ( ∖ )` | A ∖ B ∖ … | **첫 세트**에서 나머지 세트의 원소를 뺀 것 |
| `Split ( A ∖ S , A ∩ S )` | A = (A ∖ S) ⊔ (A ∩ S) | A 에서 씬 선택 S 에 해당하는 원소를 빼내 새 세트로 |

- ∪ / ∩ 은 **리스트에 담긴 모든 세트**를 순서대로 접어(fold) 계산한다. 2개 이상 필요.
- ∖ 는 **순서가 의미를 갖는 유일한 연산**이다. 리스트의 **첫 항목이 감수(minuend)**.
  순서는 TSL 의 `Up`/`Down`/`Reverse` 로 바꾼다.
- 결과는 **항상 새 세트**로 만든다(Split 제외). 원본 세트는 건드리지 않는다.

### 결과 세트 이름
`New Set Name` 이 비어 있으면 `union_set` / `intersection_set` / `difference_set` /
`<A>_split` 로 자동 명명한다. 이름이 겹치면 **마야가 뒤에 번호를 붙이므로 실제 이름은 다를 수
있고**, 로그에는 실제로 붙은 이름이 찍힌다.

## 3. Split — 이 연산의 수학적 이름

> "집합 A 에서, 지금 선택한 것들 중 A 에 속한 것만 빼내 새 집합 B 를 만든다"

집합론에 이 동작 **전체**를 가리키는 표준 연산자 이름은 없다. 다만 결과를 이루는 조각들에는
정확한 이름이 있다.

| 조각 | 이름 |
|------|------|
| A ∩ S | **자취 (trace of S on A)** — 부르바키의 용어 |
| A ∖ S | **상대여집합 (relative complement of S in A)** — A 에 대한 S 의 여집합 |
| {A∖S, A∩S} | **S 가 A 에 유도하는 분할 (partition of A induced by S)** |

두 조각은 서로소이고 합치면 A 가 된다 → `A = (A ∖ S) ⊔ (A ∩ S)` (⊔ 는 서로소 합집합).
원소가 두 덩이로 나뉘므로 **이분할(bipartition)** 이라 부르기도 한다.

구현 세계에서는 보통 **partition** 또는 **split** 이라 부른다
(Ruby `Enumerable#partition`, Rust `Iterator::partition` 등이 같은 동작이다).
그래서 이 툴도 버튼 이름을 `Split` 으로 했다.

### 쓰는 법

1. 씬에서 빼낼 컴포넌트를 고른다
2. **`Capture Selection ( S )`** 를 누른다 ← **먼저 누를 것**
3. 리스트에서 A 를 고른다 (한 행만 고르면 그것, 아무것도 안 고르면 첫 행)
4. `Split ( A ∖ S , A ∩ S )`

> ⚠️ **왜 Capture 를 먼저 눌러야 하나**
> 리스트의 행을 클릭하면 공용 TSL 위젯이 그 노드를 씬에서 선택하는데, 대상이 **세트**면
> `cmds.select` 가 세트를 **펼쳐서 멤버 전체를 선택**한다. 그러면 S 가 A 의 멤버 전체가 되어
> A 를 통째로 빼내는 사고가 난다.
> 툴은 이 상황(씬 선택 == A 의 멤버 전체)을 감지해 **실행을 거부하고** 이유를 로그에 적는다.
> Capture 해 둔 게 있으면 그것을 우선 사용한다.

### `Remove the extracted elements from A`

| 상태 | 결과 |
|------|------|
| **켬**(기본) | A 는 A∖S 만 남고, 새 세트가 A∩S 를 가져간다 → **진짜 분할** |
| 끔 | A 는 그대로 두고, 새 세트에 A∩S 를 **복사**만 한다 |

A 의 원소가 전부 빠져 A 가 비어도 **세트 노드 자체는 지우지 않는다**(로그로 알린다).

## 4. 컴포넌트 종류가 섞이면

지금은 "모든 세트가 같은 종류의 컴포넌트로 구성된다"고 가정해도 되지만,
**연산 자체는 종류를 가리지 않게** 만들어 두었다. 버텍스와 엣지는 그냥 서로 다른 원소이므로
∪ / ∩ / ∖ 는 그대로 성립한다(버텍스 세트 ∩ 엣지 세트 = 공집합).

- 막지 않고 **경고만** 한다: 한 세트 안에 종류가 섞였을 때, 세트들끼리 종류가 다를 때
- 로그에 구성이 함께 찍힌다 — `setA : 12 elements (vertex x12)`
- 리스트의 `Info` 버튼으로 언제든 각 세트의 원소 수 / 종류를 확인할 수 있다

인식하는 종류: `vtx`(vertex) · `e`(edge) · `f`(face) · `map`(uv) · `vtxFace` ·
`cv` · `ep` · `pt`(lattice) · `u` / `v`, 그리고 컴포넌트가 아닌 것은 `object`.
모르는 토큰은 토큰 그대로 표시하므로 새 컴포넌트 타입이 와도 깨지지 않는다.

## 6. 구현에서 중요한 것 — 이름 정규화

집합 연산의 전제는 **같은 원소가 항상 같은 문자열**이어야 한다는 것이다.
마야는 같은 컴포넌트를 여러 형태로 부른다.

```
pCube1.vtx[0:2]        세트가 돌려주는 축약형
pCube1Shape.vtx[1]     셰이프로 선택했을 때
|grp1|pCube1.vtx[1]    풀 패스
```

그래서 **읽어들이는 모든 경로**에서 `cmds.ls(..., flatten=True, long=True)` 로 한 형태로
통일한다. mayapy 로 확인한 사실들:

- 축약 범위(`vtx[0:2]`)가 `flatten` 으로 펼쳐진다
- **셰이프로 선택해도 트랜스폼 롱네임으로 정규화된다** → 세트 멤버와 씬 선택을 바로 비교해도 된다
- 동명 노드가 있으면 `cmds.sets(q=True)` 가 **구분되는 부분 경로**를 준다(`grp1|pCube1.vtx[0:2]`)
  → 모호하게 뭉개지지 않는다. 반대로 **모호한 짧은 이름을 `cmds.sets()` 에 넘기면 에러**가 나므로
  항상 정규화된 이름으로 넘긴다
- 빈 세트는 `None` 을 돌려준다 → 반드시 `or []` 로 받는다
- `cmds.sets(members, remove=...)` 로 들어 있지 않은 것을 빼도 에러가 아니다(무시)

세트 이름은 TSL 이 **UUID 로 보관**하므로 담아 둔 뒤 리네임해도 올바른 노드를 찾는다.

### 그 밖에
- 순서 보존: 판정에만 `set` 을 쓰고 결과는 `dict` 로 만들어 **원소 순서를 유지**한다
- 세트 안의 세트는 펼치지 않고 **원소 하나**로 센다(경고로 알린다)
- 씬을 바꾸는 연산은 전부 `undo_chunk()` — **Ctrl+Z 한 번**으로 되돌아간다

## 7. Create 탭 — 오브젝트마다 세트 하나 (v01.01)

리스트에 담은 오브젝트를 **하나마다 하나씩** 세트로 만든다.
**세트 개수 = 오브젝트 개수**이고, 이름은 **`<오브젝트 이름>_Set`** 이다.

```
Objects                      -> 만들어지는 세트
[ ctl_l_arm  ]                  ctl_l_arm_Set   { ctl_l_arm }
[ ctl_r_arm  ]                  ctl_r_arm_Set   { ctl_r_arm }
[ ctl_spine  ]                  ctl_spine_Set   { ctl_spine }
```

- `Create Sets` : 리스트 순서대로 만든다. 전체가 **undo 한 스텝**.
- `Add the new sets to the Edit tab list` (기본 ON) : 만든 세트를 `Edit` 탭 리스트에 담고
  탭을 그쪽으로 넘긴다 — 방금 만든 세트가 곧 다음에 합칠 것들이기 때문이다.
- `Select the new sets in the scene` : 만든 **세트 노드**를 선택한다.
  - ★ 세트를 그냥 `select` 하면 마야가 **멤버를 펼쳐** 선택한다. 세트 자체를 고르려면
    `noExpand` 가 필요하다(`maya_sets.select_sets`). 이 툴이 §6 에서 말하는 함정과 같은 것이다.

### 7.1 이름은 우리가 다듬는다 ★

**경로와 네임스페이스를 뗀다** — `|grp|rig:pCube1` → `pCube1_Set`.
네임스페이스를 남기면 마야가 세트를 **그 네임스페이스 안에** 만든다(레퍼런스면 곤란해진다).

마야에 이름을 그대로 넘기면 **조용히 고친다**(실측):

| 넘긴 이름 | 마야가 만든 이름 | |
|---|---|---|
| `pCube1.vtx[0]_Set` | `pCube1_vtx_0__Set` | 못 쓰는 문자를 `_` 로 |
| `1_Set` | `_Set` | **앞 숫자를 버린다** |
| `rig:pCube1_Set` | `rig:pCube1_Set` | 그 네임스페이스 안에 만든다 |

앞 숫자를 버리는 것이 특히 나쁘다 — 다만 **씬에서 온 이름은 애초에 숫자로 시작할 수 없다**
(마야가 노드·그룹·네임스페이스 이름에서 똑같이 버린다: `01_arm` → `_arm`, `9grp` → `grp`,
네임스페이스 `1ns` → `ns`). 그래도 손으로 넣은 이름이 들어올 수 있으므로 숫자로 시작하면
앞에 `_` 를 둔다.

### 7.2 이름이 겹치면 짚는다

같은 이름이 이미 있으면 마야가 뒤에 번호를 붙인다(`pCube1_Set` → `pCube1_Set1`).
**세트가 아닌 노드**가 그 이름을 쓰고 있어도 마찬가지다. 밀린 것은 **하나하나 경고로 적는다** —
이름을 보고 찾을 사람에게는 조용히 밀리는 것이 가장 나쁘다.

짧은 이름이 같은 두 오브젝트(`|grpA|ctl` · `|grpB|ctl`)를 함께 넣으면 `ctl_Set` 과
`ctl_Set1` 이 되고, 둘 다 로그에 남는다.

씬에 없는 항목은 **건너뛰고 몇 개였는지 적는다.** 리스트가 비었으면 아무것도 만들지 않는다.
