## 3. 작업 순서

**탭 순서가 곧 작업 순서다** — 왼쪽부터 `Orient & Place` · `Length` · `Match` · `Pair` · `Constrain`.

1. **케이지를 레퍼런스로 불러온다.** `Source > Cage namespace` 에서 그 네임스페이스를 고른다.
   레퍼런스가 아니면 `(none)`.
2. **`Match` 탭 > `Create Template Joints`** — 매핑 표의 이름·부모 관계대로 조인트를 만든다.
   **전부 원점에 쌓인다** — 위치는 사람이 놓는다. 이미 있는 조인트는 건드리지 않는다.
3. **템플릿 조인트를 아바타에 맞춰 손으로 옮긴다.** (왼쪽과 가운데만 — 오른쪽은 미러가 채운다)
4. **`Orient & Place` 탭 > `Orient & Place`** — 미러하고 방향을 잡은 뒤,
   발·발끝 폴 타깃 4개를 자기 축 `+Z` 로 10 만큼 내보낸다. **undo 한 스텝.**
5. **`Match` 탭 > `Check`** — 없는 템플릿 조인트 / 없는 케이지 세트를 보고한다. **씬 불변.**
6. **`Match` 탭 > `Match`** — 각 케이지 세트의 원소를 짝인 조인트 자리로 옮긴다. **undo 한 스텝.**
7. **`Length` 탭 > `Measure`** → **`Write Values`** — 거리를 재서 옵션 컨트롤러에 쓴다.
8. **`Pair` 탭 > `Check`** → **`Pair`** — 짝지어진 두 세트의 원소를 맞춘다. **Match 뒤.**
9. **`Constrain` 탭 > `Check`** → **`Constrain`** — 포즈 오브젝트를 `Con` 이 가리키는
   노드에 물린다. **Pair 뒤.**

> **`Orient & Place` 가 `Match` 보다 먼저**여야 한다 — Match 는 케이지를 조인트 자리로
> 옮기므로 조인트가 다 잡힌 뒤에 맞춰야 한다. 그래서 탭도 맨 앞이다.

> `Length` 는 **`Match` 와 순서 의존이 없다.** Match 는 케이지를 움직이지 조인트를
> 움직이지 않으므로, 조인트만 놓여 있으면 언제 눌러도 값이 같다.

## 4. 동작 규칙

### 4.1 무엇을 어디로 옮기나

매핑 표의 한 줄은 **`템플릿 조인트 ← 케이지 세트`** 다.
세트의 **원소 전부**가 그 조인트의 월드 트랜스폼으로 간다.

- **세트가 아니라 오브젝트**를 적어도 된다 — 그 오브젝트 하나만 옮긴다.
- **세트 안에 또 다른 세트가 있으면 통째로 무시**한다. 재귀하지 않으므로 **하위 세트 안의
  오브젝트도 건드리지 않는다.** 몇 개를 무시했는지 로그로 알린다.
- 한 조인트에 세트를 **여럿** 붙일 수 있다(예: `helper_foot_l`).

### 4.2 위치만 맞추는 세트

`match` 가 `["t"]` 인 세트는 **위치만** 옮기고 **회전은 그대로 둔다.** 지금 그런 세트는 **12개**다.

| 세트 | 왜 |
|---|---|
| `B01_Leg_L_ik_01_foot` · `B02_Leg_R_ik_01_foot` | 발 IK 컨트롤 — 회전은 리그가 정한다 |
| `B01_Leg_L_ik_08_polTgt_foot` · `B01_Leg_R_ik_08_polTgt_foot` | 발 IK 폴 타깃 |
| `B01_Leg_L_ik_09_polTgt_toe` · `B01_Leg_R_ik_09_polTgt_toe` | 발끝 IK 폴 타깃 |
| `B01_Leg_L_ik_07_Ball` · `B02_Leg_R_ik_07_Ball` | 발 볼 IK 컨트롤 — 회전은 리그가 정한다 |
| `A01_Arm_L_04_Pole` · `A02_Arm_R_04_Pole` | 폴 타깃 — `poleVectorConstraint` 는 **위치만** 쓴다 |
| `B01_Leg_L_06_pole` · `B02_Leg_R_06_pole` | 〃 |

### 4.3 없어도 멈추지 않는다

**템플릿 조인트가 없으면 그 짝만 건너뛰고 로그를 남긴 뒤 다음 매칭을 계속한다.**
케이지 세트가 없을 때도 같다(이때는 "네임스페이스를 확인하라" 고 덧붙인다).
한 짝이 없다고 전체가 멈추지 않는다.

### 4.4 잠기거나 구동되는 오브젝트는 **반쯤 옮기지 않는다**

**`matchTransform` 은 잠긴 채널을 조용히 건너뛴다**(실측: `translateX` 만 잠근 오브젝트가
X 만 안 움직이고 에러도 없었다). 그래서 쓰기 전에 **잠금과 입력 연결을 직접 보고**,
막힌 채널이 하나라도 있으면 **그 오브젝트를 통째로 건너뛰고** 어떤 채널이 막혔는지 알린다.
반쯤 옮겨진 상태가 제일 나쁘다.

> `getAttr(plug, settable=True)` 는 판정에 쓰지 않는다 — **컨스트레인트가 구동하는
> 트랜스폼에도 `True` 를 돌려준다**(A00060 에서 실측).

### 4.4b 막힌 채널은 **그룹 단위**로 가른다 ★

컨트롤러에 컨스트레인트가 걸려 있으면 그 채널은 **리그가 갖고 있어서** 매칭이 안 된다.
그렇다고 그 오브젝트를 통째로 건너뛰면 **비어 있는 나머지 채널이 방치된다.**

**실측 — 컨스트레인트는 그룹을 통째로 막는다**

| 걸린 것 | translate | rotate | 툴이 하는 일 |
|---|---|---|---|
| `pointConstraint` | **3/3 막힘** | 0/3 | **회전만 매칭** |
| `orientConstraint` · `aimConstraint` | 0/3 | **3/3 막힘** | **위치만 매칭** |
| `parentConstraint` | 3/3 | 3/3 | 통째로 건너뛴다 |
| `translateX` 만 잠금 | **1/3** | 0/3 | **위치는 손대지 않고** 회전만 매칭 + 경고 |

- **그룹이 통째로 막혔으면** 그 그룹만 깨끗이 건너뛰고 **나머지는 매칭한다.**
  로그에 `matched rotation only - position is driven by the rig` 처럼 적는다.
- **축이 일부만 막혔으면 그 그룹은 건드리지 않는다.** `translateX` 만 잠근 채 위치를
  맞추면 `t = [90, 2, 3]` 처럼 **X 만 남고 Y·Z 만 가는 반쪽**이 된다(실측).
  이때는 크게 경고한다 — `only some axes are locked`.
- **양쪽 다 막혔으면** 그 오브젝트는 건너뛰고 이유를 적는다.

> **2026-08-28** 처음에는 채널 하나라도 막히면 **통째로 건너뛰었다**("반쪽이 제일 나쁘다").
> 실제 케이지에서 과했다 — `A01_Arm_L_01_UpperArm` 안의 `pointConstraint` 가 걸린
> 오브젝트들이 **회전까지 매칭 안 된 채 방치**됐다(사용자 보고).
> 컨스트레인트는 그룹을 통째로 막으므로 **그룹 단위 all-or-nothing 이 맞다.**

### 4.4c IK 가 걸린 조인트 — Match 가 앞뒤로 IK 를 껐다 켠다 ★

`D01_IK_handle` 세트의 ikHandle 이 구동하는 조인트는 **그냥 매칭되지 않는다.**
Match 를 누르면 이 순서로 돈다:

```
IK 끄기  ->  매칭  ->  핸들 스냅 + 폴 벡터 역산  ->  IK 켜기
```

**왜 필요한가 (실측)** — IK 는 어트리뷰트 연결이 아니라 **솔버로** 값을 쓴다.
그래서 잠긴 채널로 보이지 않고, `matchTransform` 은 **성공하는데** 다음 평가에서
IK 가 **도로 가져간다**:

```
connectionInfo("jnt_mid.rotateZ", isDestination=True)  ->  False   (막힌 걸로 안 보인다)

전     jnt_mid r = [0, 0, 0]
직후   jnt_mid r = [15, 25, 35]      <- 들어갔다
평가후 jnt_mid r = [0, 0, 0]         <- IK 가 되돌렸다
```

→ 툴은 `[OK] matched` 라고 보고하는데 **아무것도 안 바뀐다.** 이것이 "IK handle 편집이
잘 안 된다" 의 정체였다.

**끄고 켜는 것만으로도 부족하다** — `ikBlend` 를 0 으로 두고 매칭한 뒤 1 로 되돌리면
조인트가 **원위치로 돌아간다.** 핸들을 새 체인 끝에 스냅하고 **폴 벡터를 역산**해야
편집이 남는다. 그 계산은 `A00060_jointTool_V03` 의 IK Edit 을 **불러서** 쓴다
(다시 만들지 않는다).

| | 내용 |
|---|---|
| 세트 이름 | `template_map.json` 의 `ik_handle_set` (기본 `D01_IK_handle`) |
| 찾는 법 | 조인트·세트와 같은 이름 해석 — 네임스페이스 먼저, 없으면 이름 그대로 |
| 끄는 법 | 핸들별 `ikBlend` 0. **이 리그는 `ikBlend` 를 FK/IK 스위치로 쓰지 않는다** |
| 세트가 없으면 | 조용히 세션 없이 매칭한다 (예전 동작) |
| 핸들이 아닌 멤버 | 무시하되 **몇 개를 무시했는지 알린다** |
| 매칭 중 예외 | **체인을 시작 상태로 되돌리고** IK 를 켠 뒤 예외를 올린다 |

Match 탭의 체크박스로 끌 수 있다 (기본 켬).

> **`snapEnable` 은 세션 동안 꺼 둔다.** 켜 두면 마야가 **평가 중에 핸들 translate 를
> 직접 써서** undo 큐와 뒤섞인다 — undo 한 번에 핸들이 중간값에 착지한다
> (실측: `undo=[19.063, 4.226, 0]`, 꺼 두면 `[20, 0, 0]` 로 정확히 복원).

> **세트에 없는 핸들도 찾아서 함께 끈다** — `D01_IK_handle` 은 리거가 손으로 채우는
> 목록이라 **빠진 것이 있을 수 있다.** 특히 **중첩 IK**:
>
> ```
> CH_r_UpperArm_xx_ikjnt
> └── CH_r_UpperArmDrv_xx_ikjnt      <- 이 체인에도 제 ikHandle 이 있다
>     └── CH_r_LowerArmDrv_xx_ikjnt
> ```
>
> Drv 핸들이 세트에 없으면 **매칭 중에도 계속 풀려서**, 부모 체인이 움직이는 동안
> 솔버가 Drv 조인트를 다시 잡는다. 위치는 맞는데 **회전만 부모와 어긋난 채 남는다**:
>
> | Drv 핸들이 세트에 | `UpperArmDrv` 의 부모 대비 회전 |
> |---|---|
> | 있을 때 | **0.000°** |
> | 없을 때 (고치기 전) | **7.643°** |
>
> 그래서 매칭 대상(과 그 하위)을 체인에 포함하는 핸들을 **씬에서 찾아 함께 끄고,
> 무엇을 더 껐는지 로그에 적는다** — 세트를 고칠 수 있도록. 관계없는 체인은 안 건드린다.
>
> `LowerArmDrv` 가 멀쩡해 보이는 건 **끝 조인트라 솔버가 안 돌리기** 때문이다 —
> 겉보기엔 한 조인트만 틀어진 것처럼 보인다.

> **`ikBlend` 가 구동되고 있으면 크게 알린다.** 그건 이 리그의 전제가 깨졌다는 뜻이고,
> 그대로 두면 A00060 이 **씬 전체 IK 를 끄고** 매칭한다(계획서 7-4 의 위험).

### 4.5 네임스페이스는 **골라 본 뒤 없으면 이름 그대로** 찾는다

이름 하나를 씬에서 찾을 때 **후보 두 개를 순서대로** 본다 — 조인트든 세트든 똑같다.

```
Cage namespace = CAGE   ->   1) CAGE:helper_pelvis      2) helper_pelvis
Cage namespace = (none) ->      helper_pelvis
```

그래서 세 경우가 전부 된다:

| 케이지를 어떻게 불러왔나 | Cage namespace | 찾히는 이름 |
|---|---|---|
| **레퍼런스** | 그 네임스페이스 | `CAGE:helper_pelvis` · `CAGE:A00_Spine_00` |
| **임포트** | `(none)` | `helper_pelvis` · `A00_Spine_00` |
| 조인트만 툴로 만들고 케이지는 레퍼런스 | 그 네임스페이스 | 조인트는 로컬, 세트는 `CAGE:` |

- **둘 다 있으면** 네임스페이스 쪽을 쓰고, `ambiguous joint - using CAGE:x (also found x)`
  라고 **알린다.** 어느 쪽을 골랐는지 감추지 않는다.
- **못 찾으면** 무엇을 찾아봤는지 적는다 — `looked for CAGE:x and x`.
- `Create Template Joints` 도 같은 방식으로 본다. 그래서 **레퍼런스 케이지가 이미 조인트를
  갖고 있으면 아무것도 새로 만들지 않는다** (로컬에 같은 이름을 하나 더 만들지 않는다).

매핑 json 에는 **양쪽 다 네임스페이스 없이** 적는다 — 붙이는 것은 실행 시점의 일이다.

> **2026-08-28** 이전 v02.00 은 네임스페이스를 **세트에만** 붙였다. 템플릿 조인트가 케이지
> 파일 안에 함께 들어 있어서, 케이지를 **레퍼런스**하면 `Check` 가 전부
> `joint missing` 이 됐다(임포트는 멀쩡했다). 지금은 위처럼 양쪽 다 본다.

## 5. 매핑 파일

`app/data/mapping/v001/template_map.json` — **조인트 하나가 한 항목**이다.

```jsonc
{
  "name":   "helper_foot_l",
  "parent": "helper_calf_l",
  "targets": [
    { "set": "B01_Leg_L_03" },                          // 기본 = 위치 + 회전
    { "set": "B01_Leg_L_ik_01_foot", "match": ["t"] }   // 위치만
  ]
}
```

| 필드 | 뜻 |
|---|---|
| `name` | 템플릿 조인트 이름 (네임스페이스 없음) |
| `parent` | 부모 조인트. 루트는 `null` |
| `targets[].set` | 짝인 케이지 세트(또는 오브젝트) 이름 (네임스페이스 없음) |
| `targets[].match` | `["t","r"]` 가 기본(생략 가능). `["t"]` 면 위치만 |
| `targets` 가 빈 목록 | **정상** — 배치·계층용 조인트(현재 10개) |
| `orient` | **아직 안 쓴다.** orient 규칙이 정해지면 이 자리에 들어간다 |

**짝이 늘거나 줄면 이 파일만 고치면 된다.** 케이지 버전이 갈리면
`app/data/mapping/` 아래에 폴더를 하나 더 만들면 `Mapping` 콤보에 뜬다.

> **값이 언제나 목록인 이유**: 원본 표에서 한 조인트가 세트 둘을 갖는 모양이 두 가지였다 —
> `helper_foot_l` 은 한 줄에 둘, `helper_ball_l` 은 **줄이 둘로 나뉘어** 있었다.
> `{조인트: 세트}` 로 만들면 **`helper_ball_l` 의 한쪽이 조용히 사라진다.**
> 로드할 때 같은 이름이 또 나오면 합친다.

**현재 데이터**: 조인트 **80** · 짝 **74** · 매칭 대상이 없는 조인트 **10** · 위치 전용 세트 **6**.

## 6. Length — 템플릿 조인트 길이를 옵션 컨트롤러에

계획서: [`plans/A00130_ControlRig_V02_length_plan.md`](plans/A00130_ControlRig_V02_length_plan.md)

### 6.1 어트리뷰트 12개

부위마다 **세 개씩**이다. `_up` · `_low` 는 `total` 만큼 필수다.

| 부위 | 전체 | 위 | 아래 | 재는 조인트 |
|---|---|---|---|---|
| Arm L | `Arm_L` | `arm_l_up` | `arm_l_low` | `upperarm_l` → `lowerarm_l` → `hand_l` |
| Arm R | **`Arm_r`** | `arm_r_up` | `arm_r_low` | `upperarm_r` → `lowerarm_r` → `hand_r` |
| Leg L | `Leg_L` | `leg_l_up` | `leg_l_low` | `thigh_l` → `calf_l` → `foot_l` |
| Leg R | `Leg_R` | `leg_r_up` | `leg_r_low` | `thigh_r` → `calf_r` → `foot_r` |

> **`Arm_r` 만 소문자 `r`** 이다(다른 셋은 대문자). 리그 쪽 이름이 불규칙한 것이라
> **좌우 대칭으로 유도하지 않고 json 에 전부 적어 둔다** — 유도하면 한쪽이 조용히 틀린다.

### 6.2 `Total` 은 직선인가 합인가 ★

세 조인트가 직렬이라 **`total` 은 팔꿈치를 무시한 직선 거리**고, `up + low` 와 다르다.

| 팔꿈치 | 직선 | 합 | 차 |
|---|---|---|---|
| 0° | 20.0000 | 20.0000 | 0 |
| 30° | 19.3185 | 20.0000 | **−3.4 %** |

`Total` 콤보로 고른다. 기본값은 **`straight`**(V01 과 같다). 값이 **IK 스트레치 기준**이면
보통 **`sum`**(완전히 폈을 때 길이)이 맞다 — 직선을 쓰면 스트레치가 일찍 걸린다.
두 값이 0.5 % 넘게 벌어지면 그 행에 `bent - straight ... vs sum ...` 이 뜬다.

### 6.3 쓰기 전에 전부 미리 본다

`setAttr` 을 던지고 예외를 받는 대신 행마다 먼저 판정한다. **막힌 것만 건너뛰고 나머지는 쓴다.**

| 상태 | 뜻 | 실측한 에러 |
|---|---|---|
| `joint missing` | 템플릿 조인트가 없다 | — |
| `attr missing` | 옵션 컨트롤러에 그 어트리뷰트가 없다 | `setAttr: No object matches name` |
| `blocked` | 잠겼거나 무언가가 구동한다 | `... is locked or connected` |
| `out of range` | `min`/`max` 밖이다 | `... past its maximum value of 10` |

> **범위를 넘으면 잘라서 쓰지 않고 거부한다.** 잘린 길이는 틀린 리그를 조용히 만든다.
> (마야도 자르지 않는다 — 예외를 내고 값을 그대로 둔다.)

### 6.4 옵션 컨트롤러 — 자동으로 찾고, 안 되면 손으로

**순서대로 셋을 본다.**

| 순서 | 방법 | 표시 |
|---|---|---|
| 1 | **손으로 지정한 것** (`Get Selected` 또는 필드 입력) — **있으면 이것이 이긴다** | `set by hand` |
| 2 | `length_map.json` 의 이름 — 네임스페이스 붙인 쪽 먼저, 없으면 이름 그대로 | `found by name` |
| 3 | 그 이름을 **부분 문자열로 갖는 transform** | `matched by name - check it is the right node` |

3번에서 **여럿이 나오면 고르지 않고 멈춘다** — 후보를 로그에 적고 `Get Selected` 를 권한다.
남의 노드에 조용히 쓰는 것이 최악이다(V01 은 첫 개를 골랐다).

**버튼 셋**

- **`Get Selected`** — 씬에서 고른 것을 옵션 컨트롤러로 삼는다.
  **셰이프를 골랐어도 트랜스폼으로 올려 준다** (컨트롤러는 커브라 셰이프가 잡히기 쉽다).
- **`Auto`** — 손으로 지정한 것을 버리고 다시 자동으로 찾는다.
- 필드에 **이름을 직접 쳐도** 된다. 씬에 없는 이름이면 거부하고 알린다.

> **왜 수동이 필요한가.** 리그의 이름 규칙은 프로젝트마다 다르다.
> **자동 탐지는 편의고, `Get Selected` 가 보장이다.** 자동이 실패해도 툴은 멈추지 않는다.

> **2026-08-28** 처음에는 `option_ctl` 에 V01 의 **토큰**(`OptionAll_xx_ctl`)을 전체 이름으로
> 적어 두어 **아무것도 못 찾았다.** 실제 이름은 `CH_n_OptionAll_xx_ctl` 이다.
> 더해서 `cmds.ls("*토큰*")` 은 **네임스페이스를 넘지 않고**(레퍼런스면 빈 목록)
> **셰이프까지 잡아** 후보를 부풀린다 — 폴백도 못 쓰는 상태였다.
> 지금은 `recursive=True` + `type="transform"` 이고, 그래도 안 되면 손으로 지정한다.

### 6.5 씬 단위

거리는 **씬의 선형 단위**를 탄다(같은 두 점이 `cm` 10 · `m` 0.1 · `mm` 100).
툴은 단위를 **바꾸지 않고** `Measured in cm` 처럼 **표시**한다. 미리보기 값이 예상과
100배 다르면 단위가 원인이다.

### 6.6 조인트를 아직 안 놓았다면

길이가 전부 0 이면 **"조인트가 아직 원점에 있는 것 같다" 고 경고**한다.
0 을 쓰는 것 자체는 막지 않는다 — 의도일 수 있다.

### 6.7 부위를 더하려면

`app/data/mapping/<version>/length_map.json` 에 항목을 하나 더한다. **코드는 안 고친다.**

```jsonc
{
  "part":  "Spine",
  "chain": ["helper_spine_01", "helper_spine_03", "helper_spine_05"],
  "attrs": { "total": "Spine_All", "upper": "spine_up", "lower": "spine_low" }
}
```

`chain` 은 2개 이상이면 된다. `upper`/`lower` 는 **정확히 3개일 때만** 뜻이 있고,
아니면 경고와 함께 `total` 만 쓴다. `chain` 의 조인트 이름이 `template_map.json` 에
없으면 **로드 단계에서 잡힌다** — 씬에서 조용히 0 이 되지 않는다.

## 7. Orient & Place — 템플릿 조인트의 방향과 (일부) 위치

계획서: [`plans/A00130_ControlRig_V02_orient_plan.md`](plans/A00130_ControlRig_V02_orient_plan.md)

조인트를 손으로 놓은 뒤 `Orient & Place` 한 번이면 방향이 규칙대로 잡힌다.
**대부분은 위치가 안 바뀌지만**, 미러로 채우는 오른쪽과 **폴 타깃 4개**는 위치도 정해진다.

> **왜 이름이 `Orient` 가 아닌가.** 발·발끝 폴 타깃 4개는 **위치까지** 놓기 때문이다(7.7).
> 방향만 다루지 않으므로 탭도 버튼도 `Orient & Place` 다.

### 7.1 순서가 강제된다

```
미러  ->  A1(척추)  ->  A2(팔·다리 + tail/preserve)  ->  위치 전용(월드 회전 0)  ->  Place
```

**미러가 먼저여야 한다** — A2 는 오른쪽 **폴 타깃 위치를 읽는데**, 그걸 제자리에 놓는 게
미러다. 미러 체크를 끄면 그 사실을 경고한다.

### 7.2 규칙 셋

| | 대상 | 하는 일 |
|---|---|---|
| **A1** | 척추 계열 9개 | 체크 시 **월드 회전 0,0,0**(기본) · 해제 시 forward `+X` 가 다음 조인트를 보고 `+Z` 가 월드 `+Z` 쪽 |
| **A2** | 팔·다리 4벌 | forward 가 다음 조인트, **up(`+Z`)이 폴 타깃 쪽**. 끝 조인트는 아래 참고 |
| **A3** | 미러 | 팔은 **Behavior**(방향까지) · 다리는 **위치만**(방향은 A2 가 새로 만든다) · 보조 14개는 위치 미러 + 월드 회전 0 |

### 7.3 끝 조인트 — `tail` 과 `preserve`

IK 솔버는 **끝 조인트를 회전시키지 않는다**(실측). 그래서 A2 는 `A[-1]` 을 정하지 못한다.

| 부위 | 끝 조인트 | 처리 |
|---|---|---|
| 다리 | `foot` | **`tail`** — `foot → ball → ballEnd` 를 `+Z` 가 월드 `+Y` 쪽이 되게 |
| 팔 | `hand` | **`preserve`** — **손대지 않는다.** IK 를 걸기 전과 같은 회전값 |

> **`preserved` 와 `no rule` 은 다르다.** 둘 다 씬을 안 바꾸지만, 앞은 **정해진 것**이고
> 뒤는 **아직 안 정해진 것**이다. 표에서 갈라 보여 준다.
>
> `preserve` 는 **로컬 값**(`rotate`+`jointOrient`) 기준이다 — 마야 IK 도 그렇게 한다.
> 부모가 돌면 **손목의 월드 방향은 따라 움직인다.** 그건 정상이다.

### 7.4 forward 가 up 보다 우선한다

`+Z` 를 월드 축에 맞추라는 규칙과 forward 를 다음 조인트에 맞추라는 규칙은
**체인이 기울어 있으면 동시에 만족될 수 없다.**

```
foot -> ball 이 수직에서 36.87도 기울면
  forward 오차   = 0.00 도
  +Z 와 월드 +Y = 36.87 도   <- 딱 그만큼
```

**본이 체인을 따라 서는 것이 먼저다.** `+Z` 는 그 조건에서 월드 축에 가장 가까운 값이 된다.
**기운 각도는 로그에 적는다** — 실제 발은 평평하므로 이 값이 크면 배치가 이상한 것이다.

### 7.5 표가 알려 주는 것

| 열 | 뜻 |
|---|---|
| `Rule` | 어느 규칙이 이 조인트를 맡았나 (`A1 world zero` · `A2 leg_l` · `A2 keep` · `A3 behavior` ...) |
| `Up dev` | up 축이 기대한 월드 축에서 몇 도 벗어났나 — **A2 의 up 축이 `+Z` 라는 전제가 맞는지 여기서 갈린다** |
| `Status` | `ok` · **`preserved`**(정해진 것) · **`no rule`**(미결) · `joint missing` |

### 7.6 아직 규칙이 없는 40개

`helper_root` · `helper_clavicle_l` · **손가락 38개**. 표에 `no rule - untouched` 로 뜨고
**건드리지 않는다.** 오른손 19개는 팔 Behavior 미러가 계층째 덮으므로, 실제로 사람이
놓아야 하는 것은 **왼손 19개와 `clavicle_l`** 이다.

규칙이 정해지면 `orient_map.json` 에 줄만 더하면 된다 — **코드는 안 고친다.**

### 7.7 Place — 발·발끝 폴 타깃 4개

| 조인트 | 부모 | 짝인 케이지 세트 (**위치만**) |
|---|---|---|
| `helper_polTgt_foot_l` | `helper_foot_l` | `B01_Leg_L_ik_08_polTgt_foot` |
| `helper_polTgt_toe_l` | `helper_ball_l` | `B01_Leg_L_ik_09_polTgt_toe` |
| `helper_polTgt_foot_r` | `helper_foot_r` | `B01_Leg_R_ik_08_polTgt_foot` |
| `helper_polTgt_toe_r` | `helper_ball_r` | `B01_Leg_R_ik_09_polTgt_toe` |

> **오른쪽 두 세트의 접두가 `B01` 이다.** 다른 오른쪽 다리 세트 13개는 전부 `B02_Leg_R_*`
> 인데 이 둘만 `B01_Leg_R_*` 다 — 받은 그대로 넣었다. 오타라면 json 한 줄이고,
> 씬에 그 이름이 없으면 Match 가 `set missing` 으로 **찾아본 이름을 그대로 적어** 알린다.

방향이 전부 정해진 **뒤에**, 이 넷은 `translate` 가 **`(0, 0, 10)`** 이 된다 —
부모 자리에서 **자기 축 `+Z`** 로 10.

> **실측**: `setAttr .translate 0 0 10` · `xform -os -t 0 0 10` · `move -r -os 0 0 10` 이
> **모두 같은 결과**다. 오브젝트 공간 이동은 곧 `translate` 어트리뷰트다.

**방향 단계가 끝난 뒤에 돈다** — 자기 축이 확정돼야 `+Z` 가 어디인지 정해지기 때문이다.

표에서 이 넷은 `ok` 가 아니라 **`placed`** 로 뜨고, `Check` 는 로그에
`N joint(s) will be MOVED, not just rotated` 라고 미리 알린다 — **회전만 될 거라
생각하고 눌렀다가 위치가 바뀌는 일이 없도록.**

`translate` 가 잠겼거나 구동되면 건너뛰고 알린다.

축과 거리는 `orient_map.json` 의 `place` 에 있다 — **코드는 안 고친다.**

```jsonc
{ "joints": [...], "reset": true, "axis": "+Z", "distance": 10.0 }
```

### 7.8 손가락

| 손 | 규칙 |
|---|---|
| **왼손** (`helper_hand_l` 하위 19개) | forward **`+X`** 가 제 자식을, **`+Y`** 가 월드 `+Y` 쪽 |
| **오른손** (19개) | **왼손을 Behavior 미러**한 결과 |

조인트 이름을 하나하나 적지 않는다 — **뿌리 하나(`helper_hand_l`)만** 적으면 그 아래
전부에 적용된다. 손가락 마디가 늘거나 줄어도 json 은 그대로다.

**끝마디는 부모의 방향을 물려받는다** — aim 할 자식이 없다.

> **★ 순서가 중요하다.** 오른손 미러는 **왼손을 정렬한 뒤에** 돌아야 한다.
> 팔 전체를 미러하는 이른 단계(1번)는 **아직 손대지 않은 왼손가락**을 복사하므로,
> 사용자가 놓아 둔 방향이 그대로 오른쪽에 박힌다.
> 그래서 손 미러는 `"stage": "late"` 로 표시해 **정렬 뒤에** 돈다:
>
> ```
> 미러(이른) → A1 → A2 → 손가락 정렬 → 미러(늦은) → 위치 전용 → Place
> ```
>
> 검증에 **"이른 단계로 되돌리면 깨진다"** 를 넣어 뒀다 — 순서가 진짜 필요하다는 증거다.

이제 **규칙이 없는 조인트는 `helper_root` 와 `helper_clavicle_l` 둘뿐이다**(40 → 2).

## 8. Pair — 세트 대 세트로 하나씩

`pair_map.json`. **Match 가 끝난 뒤에** 돈다.

Match 는 **템플릿 조인트**를 기준으로 세트의 원소들을 옮긴다(1:N).
Pair 는 **세트 대 세트**다 — `from` 세트의 원소 하나로 `to` 세트의 원소 하나를 맞춘다.
조인트가 끼어들지 않는다.

### 8.1 하나임을 검사한다

**두 세트가 모두 원소를 정확히 하나 가질 때만** 맞춘다. 0개거나 2개 이상이면
**추측하지 않고 건너뛰고 알린다** — 어느 것을 고를지 정할 근거가 없는데 하나를 골라
버리면 조용히 틀린 리그가 된다.

| 상태 | 뜻 |
|---|---|
| `ok` | 양쪽 다 하나 — 맞출 준비가 됐다 |
| `not exactly one` | 한쪽이 0개거나 2개 이상 (**몇 개인지 적는다**) |
| `set missing` | 세트가 없다 (**찾아본 이름을 적는다**) |
| `blocked` | 대상의 채널이 잠겼거나 구동된다 |

### 8.2 짝 24개

`ik` 10짝 + `fk` 14짝. `from` = `C04_match_*`, `to` = `C04_ik_*` / `C04_fk_*`.
위치와 회전을 모두 맞춘다(`match: ["t","r"]`).

> **2026-08-31**: `C04_match_10_l_ArmPol` 의 끝 `e` 가 빠져 있던 것을 짚었고, 오타로 확인돼
> `C04_match_10_l_ArmPole` 로 고쳤다. 이제 24짝 모두 `from` 과 `to` 의 접미가 같다.

## 9. Constrain — `Con` 이 가리키는 노드가 포즈 오브젝트를 몬다

`constrain_map.json`. **Pair 가 끝난 뒤에** 돈다.

`C04_pose_objects` 세트의 원소마다 `Con` 어트리뷰트를 보고, 거기 **연결된 노드**가 그
오브젝트를 **drive** 하도록 `parentConstraint` 를 건다.

| 상태 | 뜻 |
|---|---|
| `ok` | `Con` 이 있고 연결도 있다 |
| `no Con attribute` | 그 어트리뷰트가 없다 |
| `Con is not connected` | 어트리뷰트는 있는데 아무것도 안 붙어 있다 |
| `already constrained` | **이미 걸려 있다 — 손대지 않는다**(9.1) |
| `blocked` | 채널이 잠겼거나 구동된다 |

### 9.1 이미 걸린 것은 건드리지 않는다 ★

**실측**: 같은 드라이버로 다시 걸면 멱등이다(타깃 1개 유지). 그런데 **드라이버가 다르면
조용히 타깃이 2개로 늘어난다** — `Con` 을 바꾼 뒤 다시 돌리면 **두 노드가 반씩 끌어당기는**
리그가 된다.

그래서 이미 `parentConstraint` 가 있는 오브젝트는 **건너뛰고 알린다.**
드라이버를 바꿨다면 **기존 컨스트레인트를 지우고** 다시 돌린다.

### 9.2 `maintain offset`

`constrain_map.json` 의 `maintain_offset` (기본 **off**).

| | 결과 |
|---|---|
| off | 오브젝트가 **드라이버 자리로 끌려간다** |
| on | 오브젝트가 **제자리에** 남는다 |

드라이버와 오브젝트가 떨어져 있으면 **거리를 로그에 적는다** — `off` 때문에 튀는 경우가
바로 그때뿐이라서다.

### 9.3 `Con` 의 타입은 상관없다

`message` 든 일반 어트리뷰트든 연결된 노드를 찾는다. 소스 쪽을 먼저 보고, 없으면 반대
방향도 본다(그때는 어디서 찾았는지 적는다).

> **2026-08-31**: 세트 이름이 `C04_pose_objects`(`j` 없음)였던 것을 짚었고, 오타로 확인돼
> **`C04_pose_objects`** 로 고쳤다.
