# A00390_WindTool

본 체인에 **싸인 주기함수 키프레임**을 찍어 *바람에 일렁이는* 간단한 애니메이션을 만드는
in-Maya PySide 툴. 조인트마다 위상만 어긋난 같은 파형을 넣어 체인이 순차적으로 흔들리게 한다.

> [!info] 아키텍처
> arch (A) in-Maya PySide. 공용 위젯 `JUN_mod_tsl_qt`(TSL) + `JUN_mod_timeRange_qt`(Start/End) 사용.
> 로직은 `app/core/wind_manager.py`(maya.cmds, UI 비의존), UI 는 `app/ui/main_window.py`.

---

## 파형 정의

각 조인트 `i`(리스트 순번 0,1,2…)의 선택 축 값:

```
value(t) = amplitude * sin( 2π * (t - i*offset) / period )
```

- 키는 1/4 주기마다 계산하되(격자 간격 `quarter = period/4`), 기본적으로 **구간 내부의 0 교차 키는
  빼고 극값(±amplitude)만** 남긴다(v01.01~). 극값 사이 0값 키가 있으면 spline 커브가 그 지점에서
  평평/각지게 되기 때문. 대신 구간 **양끝(Start/End)** 에는 그 지점의 실제 싸인 값으로 **앵커 키**를 둬
  커브가 구간 밖으로 흘러가지 않게 한다. (`Keep zero-crossing keys` 를 켜면 0 교차 키까지 모두 찍는다.)
- 키 사이는 **spline 탄젠트**로 보간되어 깔끔한 싸인 파형이 된다.
- `quarter` 가 소수면(예: `period=10 → 2.5`) **소수 프레임에 키**가 찍힌다.
- 조인트 순번 `i` 는 위상을 `i*offset` 프레임만큼 미룬다 → 체인이 계단식으로 흔들린다.
  A00110 의 Stagger offset 과 달리 **offset 은 실수 프레임**을 쓸 수 있다.

### 모드 (v01.02~)

| 모드 | 순번(i)의 의미 | 대상 |
|------|----------------|------|
| **Bone Chain**(기본) | 리스트 순서 | 리스트업한 조인트들 **자체** (하나의 체인) |
| **Bone Root** | root 로부터의 **깊이(depth)** | 리스트업한 각 조인트를 **루트로 보고 그 자손 조인트 전부** |

- **Bone Root**: `jnt_01, jnt_02, jnt_03` 을 리스트업하면 각각을 체인 루트로 가정하고, 그 조인트 +
  모든 자손 조인트에 Bone Chain 과 같은 파형을 반복 적용한다. offset 순번은 **루트마다 리셋**(root=0,
  자식=1, …)되고, 분기 체인에서 **같은 깊이의 형제는 같은 offset** 을 갖는다. 같은 조인트가 여러
  루트에서 겹쳐 잡히면 처음 것만 쓴다(중복 키 방지).

### 예시

`rotateX`, Start=0, End=100, Period=12, Amplitude=40, Offset=10:

| 조인트 | 위상 지연 | 키(값) |
|--------|-----------|--------|
| `jnt_01` (i=0) | 0f | 3→40, 9→-40, 15→40 … (극값만, 매 12프레임 반복) + 양끝 앵커(0, 100) |
| `jnt_02` (i=1) | 10f | 같은 파형이 +10f 밀림 (13→40 …) + 양끝 앵커 |
| `jnt_03` (i=2) | 20f | 같은 파형이 +20f 밀림 (23→40 …) + 양끝 앵커 |

내부 0 교차 키(6·12·18…f)는 제거되고 극값 사이는 spline 으로 보간된다.
`period=10` 이면 2.5f(최대), 7.5f(최소)에 키가 찍힌다(소수 프레임).

### 출력 (Curve / Node, v01.03~)

| 출력 | 방식 | 특징 |
|------|------|------|
| **Curve**(기본) | 조인트에 **키를 굽는다** | 씬 재생으로 재생. 기존 동작. |
| **Node** | **드라이버 null + 노드망** | 파형을 **실시간** 재현. 어트리뷰트로 편집. |

- **Node** 는 `windPeriod / windAmplitude / windOffset / windSpeed` 어트리뷰트를 가진 **null(로케이터)
  드라이버**를 만들고, 노드망으로 각 조인트를 구동한다:
  `value = windAmplitude · sineLUT( (windPhaseTime − i·windOffset) / windPeriod )`.
  드라이버 파라미터를 바꾸면 애니메이션이 **즉시 갱신**된다.
- **재생 속도 = `windSpeed`(값 = 속도)**. 1=보통, 2=2배, 0=정지. **상수로 둬도 계속 재생**된다.
  - **값이든 키든 자동·실시간**(v01.07~): `windPhaseTime` 을 **`∫windSpeed dt` 적분 표현식**(MEL
    expression)으로 라이브 계산한다. windSpeed 를 **값으로 바꾸든 키로 애니메이션하든 버튼 없이 즉시
    반영**되고, 속도가 변해도 **위상이 단조 전진해 역행(찰랑임 뒤집힘)이 없다**. windSpeed=1 상수면
    windPhaseTime=frame(curve 모드와 같은 위상).
  - ⚠️ 왜 적분인가: 속도는 시간의 적분(`phase=∫speed dt`)이다. 단순 곱셈 `time×speed` 는 가변 속도에서
    위상이 역행하고(v01.03/06), `windTime` 시간값(v01.04)은 상수로 두면 멈춘다. 적분 표현식이 둘 다 해결.
  - Speed 입력은 windSpeed 의 **초기값**을 정한다.
  - 성능: 표현식이 매 프레임 startFrame~현재프레임을 훑어 적분한다(구간이 매우 길고 드라이버가 많으면
    다소 무거울 수 있음).
- 드라이버 개수: **Bone Chain → 1개**, **Bone Root → 루트 수만큼**.
- **`windPhaseOffset`(전체 타이밍 offset, v01.08~)**: 드라이버(노드) **하나의 전체 타이밍**을 미는
  어트리뷰트(`base = windPhaseTime − windPhaseOffset`, 그 드라이버의 모든 본에 공용). 드라이버마다
  다른 값을 주면 서로 다른 타이밍으로 찰랑인다. UI 의 **Node Offset** 은 드라이버 순번 k 마다
  `windPhaseOffset = k×값` 으로 초기화 → **Bone Root 모드에서 루트별로 자동 다른 타이밍**(0 이면 동일).
- sin 은 정규화 싸인 `animCurveUU` LUT(한 주기, 무한 반복 cycle)로 만들어 Maya 2023 의 네이티브 sin 노드
  부재를 피한다(A00170 Remap Value 아이디어 응용). 다시 Build 하면 새 드라이버가 생기고 이전 연결은
  끊긴다(이전 드라이버는 수동 삭제 또는 undo).

## 사용법

1. 씬에서 조인트를 선택하고 **Select Joints** → TSL 에 리스트업(Chain 모드는 순서 = offset 순번, Up/Down 재정렬).
2. **Mode** 선택 — **Bone Chain**(리스트 = 한 체인) 또는 **Bone Root**(각 항목 = 체인 루트, 자손까지).
3. **Output** 선택 — **Curve**(키 굽기) 또는 **Node**(드라이버 노드망 실시간).
4. **Axis** 로 축 선택(rotateX/Y/Z · translateX/Y/Z).
5. **Start / End** (Curve 전용) 로 키를 만들 구간 지정(Get Current / Get Sel Range 지원).
6. **Period / Amplitude / Offset** 입력(모두 소수 허용). **Speed**·**Node Offset** 은 Node 전용
   (windSpeed 초기값 / 드라이버별 타이밍 스태거 = 루트마다 다른 타이밍).
7. (Curve) **Clear existing keys in range**(기본 on) — 재적용 시 구간의 해당 축 키를 먼저 지운다.
8. **Apply Wind Keys**(Curve) / **Build Wind Node**(Node) — 전체가 한 번의 undo 로 묶인다.
9. (Node) 드라이버의 **windSpeed** 를 값으로 바꾸거나 키로 애니메이션하면 재생 속도가 **자동 반영**된다.

## 참고 (mayapy 검증)

- Maya 는 **회전(각도) 키를 내부적으로 라디안으로 저장**했다가 도로 변환하므로, 30° 같은 값은
  `29.999999999999996` 처럼 미세 오차로 돌아올 수 있다(도↔라디안 왕복). 표시·동작상 30 과 동일하며
  회전 키를 찍는 모든 툴에 공통이다.
- 키 시간은 `round(shift + n*quarter, 5)` 로 부동소수 잡음을 정리한다.
- `_SIN_QUARTER = (0, 1, 0, -1)` 를 `n % 4` 로 인덱싱 — 파이썬 모듈로가 음의 격자에도 맞으므로
  구간이 0 보다 앞/뒤여도 파형이 이어진다.

## Chain Wave 탭 (v01.09~)

체인이 **회전값만 바꿔서** 진행하는 싸인 파형을 따라가게 한다.
"커브에 마야 기본 **Nonlinear > Sine** 디포머를 걸고 그 커브에 조인트를 붙인" 결과를,
조인트의 translate 는 **한 번도 건드리지 않고** 재현하는 것이 목표다.

### 왜 필요한가 — Sine 탭으로는 둘 중 하나만 된다

조인트 9개(뼈 2.0)를 X 축으로 세우고 Sine 탭으로 실측한 결과다.

| Sine 탭 Axis | 월드 위치 | 뼈 길이 | 조인트가 자식을 향하나 |
|---|---|---|---|
| `translateY` | 파도처럼 보인다 | **2.0 → 2.02~2.22 로 늘었다 줄었다** | **아니오** (rotate 가 전부 0) |
| `rotateZ` | 파형을 따라가지 않는다(체인이 말린다) | 2.0 유지 | 예 |

`translateY` 는 조인트를 **옮기는** 것이라 뼈가 늘어나고 방향이 안 생기고,
`rotateZ` 는 각 조인트의 회전이 **자손에 누적**되어 체인이 감긴다. 둘 다 원하는 그림이 아니다.

### 어떻게 푸나 — ikSplineSolver

마야에 이 문제의 정답이 이미 있다. **ikSpline** 은 커브를 따라 체인을 눕히되 **회전만** 쓰고
뼈 길이를 유지한다. 그래서 이 탭은:

1. 조인트 rest 위치에 CV 를 둔 커브를 만들고,
2. 그 커브에 ikSpline 핸들을 물리고(`rootOnCurve=False`),
3. 커브의 **CV 를 노드망으로 흔든다** —
   `CV_k = rest + windAmplitude · ramp_k · sin( 2π ( s_k / windWavelength − phase ) )`
   (`s_k` = 그 CV 의 체인 위 거리, `phase` = `windPhaseTime / windPeriod`).

디포머를 안 쓰고 CV 를 직접 흔드는 이유: 디포머의 amplitude/wavelength 는 핸들 스케일이 섞인
**디포머 로컬 단위**라 월드 단위로 예측하기 어렵다. CV 를 직접 흔들면 진폭·파장을 **월드 단위
그대로** 준다.

> **`rootOnCurve=False` 가 중요하다.** 기본값(True)이면 커브 시작점이 움직일 때 마야가 루트
> 조인트의 **translate 를 커브로 끌어당긴다** — "회전만" 이라는 약속이 깨지고, 셋업을 지운
> 뒤에도 체인 전체가 통째로 밀린 채 남는다(실측: 전 조인트가 똑같이 Y −1.448). 첫 CV 도 항상
> 루트에 고정한다.

### 파라미터

| 항목 | 뜻 |
|------|-----|
| **Sway Axis (world)** | 파동이 미는 **월드 축**. X 로 누운 체인은 보통 Y |
| **Amplitude** | CV 를 미는 양(**월드 단위**). 실제 흔들림은 조금 작다(아래 참고) |
| **Wavelength** | 한 파장의 **월드 길이** |
| **Period** | 한 주기가 지나가는 프레임 수 |
| **Speed** | 재생 속도(1 = 보통). `windSpeed` 는 시간 적분이라 값·키 무엇을 바꿔도 위상이 역행하지 않는다 |
| **Root Ramp** | 0 = 루트부터 같은 진폭, 1 = 루트 0 에서 끝으로 갈수록 커짐(기본) |
| **Chain Offset** | 체인 k 의 `windPhaseOffset = k × 이 값`. Bone Root 모드에서 체인마다 타이밍을 어긋나게 한다 |

- **Node**(기본): 커브 + ikSpline + 드라이버 로케이터를 만든다. 드라이버의
  `windAmplitude / windWavelength / windPeriod / windSpeed / windRootRamp` 를 **라이브**로 편집.
- **Curve**: 위 셋업을 만들어 구간을 **회전 키로 굽고 셋업은 지운다**. 씬에는 회전 키만 남는다.
- **Remove Chain Wave**: 이 탭이 만든 셋업(`chainWave_waveSET`)을 지우고 조인트 회전을 0 으로.

### 실측 (조인트 9개 · 뼈 2.0 · 파장 10 · 진폭 1.5)

- **translate 가 하나도 바뀌지 않는다**(회전만) · **세그먼트 길이 2.0 정확히 유지**
- **루트 제자리** · 모든 조인트의 **x 축이 자식을 향한다**(내적 > 0.999)
- 조인트가 커브에서 벗어난 거리 **최대 0.067**(체인 16 의 0.4%)
- `Period` 프레임 뒤 **같은 위상**으로 돌아온다

### 조인트든 FK 컨트롤러든 (v01.10~)

리스트에 **조인트를 담든 FK 컨트롤러를 담든** 똑같이 동작한다. 라이브 어트리뷰트 조절도 그대로다.

`ikSpline` 은 **조인트에만** 걸리므로 **둘 다 프록시 조인트 체인을 거친다**(v01.11~):

1. 대상 위치에 **숨긴 프록시 조인트 체인**을 세우고,
2. 프록시에 파동 셋업(커브 + ikSpline + CV 노드망)을 그대로 걸고,
3. 프록시의 **월드 회전 변화량**을 대상 `rotate` 로 옮긴다:

   `ctrlWorld = restCtrlWorld × restProxyWorld⁻¹ × proxyWorld` → `× ctrl.parentInverseMatrix` → 로컬 회전

   앞 두 항은 빌드 시점 상수라 하나로 접어 넣는다. 곱의 3×3 블록은 각 3×3 블록의 곱이므로
   **이동 성분이 섞여 있어도 회전은 정확**하다(그래서 `outputRotate` 만 쓰고 나머지는 버린다).
   사이클도 없다 — 컨트롤러의 회전은 **조상**의 행렬과 프록시에만 의존한다.

- **오프셋 그룹은 알아서 건너뛴다.** `ctrl > grp > ctrl > ...` 처럼 중간에 그룹이 낀 FK 리그에서
  Bone Root 모드는 **셰이프가 달린 트랜스폼**(= 실제 컨트롤러)만 체인으로 잡는다.
- **rest 회전이 0 이 아닌 컨트롤러**도 Remove 하면 원래 값으로 되돌아온다(빌드 시점 값을
  세트에 적어 둔다).
- **대상이 조인트면 `jointOrient` 를 벗겨낸다.** 조인트의 로컬 행렬은 `R x JO` 라, 구한 로컬
  행렬을 그대로 `rotate` 에 넣으면 JO 가 두 번 먹는다. jointOrient 는 빌드 시점 상수이므로
  역행렬을 상수로 접어 넣는다(노드를 더 만들지 않는다).
- 조인트도 프록시를 거치므로 **사용자 체인에는 ikHandle 도, 가상 조인트도 생기지 않는다**.
- 실측: 대상이 프록시 조인트와 **위치/회전 모두 완전히 일치**(거리 0.000), translate 불변,
  간격 유지, 루트 제자리.

#### 마지막 노드도 회전한다 (v01.11~)

`ikSpline` 은 **엔드 이펙터 조인트를 회전시키지 않는다.** 그래서 그 전까지는 체인의 **맨 끝
노드가 회전값 0 으로 남아** 있었다(실측: 마지막 두 노드의 월드 회전이 31.6 도로 똑같았다 —
팁이 부모 방향을 그냥 물려받은 것).

프록시 체인 끝에 **마지막 뼈를 같은 방향/길이로 한 번 더 연장한 가상 조인트(dummy tip)** 를
붙여 해결했다. 그것이 엔드 이펙터가 되므로 **진짜 마지막 노드도 파형을 따라 회전한다.**
가상 조인트는 프록시 그룹 안에 있어 화면에 보이지 않고, Remove 하면 함께 사라진다.

> `A00410_SecondaryMotion` 의 `Rotate last node`(KawaiiPhysics 의 dummy bone)와 같은 방식이다.
> 자식이 없는 팁은 방향을 정의할 수 없으니 가상 점을 만들어 준다.

> **함정 — rest 행렬은 파동을 걸기 *전에* 읽어야 한다.** 프록시를 만든 뒤 ikSpline·CV 노드망을
> 먼저 걸고 나서 rest 를 읽으면 **이미 휘어진 자세가 rest 로 잡혀** 컨트롤러가 엉뚱한 각도로
> 간다(실측: 루트부터 어긋나고 끝으로 갈수록 1.09 까지 벌어졌다).

### 알아둘 것

- 진폭은 **CV 를 미는 양**이다. NURBS(3차) 커브는 CV 를 통과하지 않고 안쪽으로 당겨지므로
  실제 흔들림은 그보다 조금 작다(위 조건에서 약 0.85배).
- 파장 대비 진폭이 너무 크면 **커브가 체인보다 길어져** 체인이 커브 끝까지 못 간다. 그때는
  진폭을 줄이거나 파장을 늘린다.
- 갈래가 있는 체인은 ikSpline 이 한 줄만 다루므로 **첫 자식 쪽**을 따라가고 로그로 알려준다.
