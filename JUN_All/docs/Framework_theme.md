# 테마(색) 규칙

마야에 여러 툴을 동시에 띄웠을 때 **창 색만 보고 어떤 일을 하는 툴인지 알 수 있게** 한다.
**새 툴을 만들 때는 아래 표에서 색을 고른다.** 마음에 드는 색을 고르는 게 아니다.

재분류 경위와 근거는 [테마 재분류 계획서](plans/theme_reassignment_plan.md) 참고.

---

## 1. 두 축

| 축 | 뜻 |
|----|-----|
| **색상(hue)** | 이 툴이 **무엇을 만지는가** (조인트 / 스킨 / 키 / 지오메트리 / 씬 / 언리얼 / 파일) |
| **명도(dark/mid)** | `_dark` = 마야 안에서 **본 작업**을 하는 툴 · `_mid` = **마야 밖 스탠드얼론**, 또는 항상 떠 있는 **런처** |

명도 차이가 색상 차이보다 훨씬 강하게 보이므로, `_mid` 쪽에서는 hue 를 재사용해도 헷갈리지 않는다.
**두 무리는 명도로 먼저 갈리고 그 다음 hue 로 갈린다** — `_mid` 안에서의 hue 뜻은 `_dark` 쪽과 별개다.

> `_light` 는 쓰지 않는다. 너무 밝아 마야 옆에 두기 불편해서 `_mid` 로 교체했다(계획서 10절).

> 지우지는 않았다.

## 3. 쓰는 법

```python
# 마야 안에서 도는 툴
ThemeManager.load_theme_to_widget(window_instance, "teal_dark")

# 스탠드얼론 앱 (QApplication 전체에 적용)
ThemeManager.load_theme_dev(app, "slate_mid")
```

## 4. 새 색이 필요할 때

완전판 qss(`*_dark` 5734 B / `*_light` 4222 B)는 **서로 색 값만 다르고 구조가 완전히 같다.**
그래서 새 계열을 만드는 비용은 거의 없다 — 기존 파일 하나를 복사해 **색상만 회전**시키면 된다.

만들 때 지킬 것:

- **중립색은 건드리지 않는다.** 어떤 색이 계열색이고 어떤 색이 중립색인지는 추측하지 말고,
  **서로 다른 두 계열(예: green 과 blue)을 같은 자리끼리 비교해** 정한다 — 값이 같으면 중립색이다.
- **채도·명도 관계는 원본을 그대로 물려받는다.** 색상만 바꿔야 다른 계열과 같은 급이 된다.
- 만든 뒤 **hex 를 전부 마스킹해 원본과 비교**한다. 색 말고 다른 차이가 있으면 안 된다.

> ⚠️ **색을 무한정 늘리지 말 것.** 사람이 구분할 수 있는 색은 8종 안팎이고 dark 쪽은 이미 다 찼다
> (남은 빈 구간은 magenta·lime 정도뿐). 더 나눠야 하면 색을 늘리기 전에
> **명도 축(`_mid`)** 을 먼저 쓴다.

**`_mid` 만드는 법**: 바탕이 될 `_dark` 에서 **어두운 색만 들어올린다**
(`V < 0.5 → V + 0.12`, 그 이상은 그대로). 글자·accent 는 손대지 않는다.
만든 뒤 **가장 어두운 배경과 본문 글자(`#e6e6e6`)의 명암비가 4.5 이상**인지 숫자로 확인할 것
(0.12 에서 7.10:1, 0.24 까지 올리면 4.46 으로 기준 미달).

## 5. 주의

- 테마 이름에 오타가 나면 **조용히 무테마로 뜬다**(예외가 안 난다). 새로 지정한 뒤에는
  `Framework/styles/<이름>.qss` 가 실제로 있는지 확인할 것.
- `A00200_CSV_tool`(실제 기능은 **ARKit Facial Import**)은 아직 테마 지정이 없다.
  분류상으로는 **애니메이션(`blue_dark`)** 이지만 폴더명 정정과 함께 별도로 처리한다.
