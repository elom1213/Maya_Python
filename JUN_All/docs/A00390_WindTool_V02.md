# A00390_WindTool_V02 사용법

`A00390_WindTool` 을 그대로 복제한 뒤 **Chain Wave Lite** 탭을 더한 버전이다.
루트가 100개를 넘는 상황에서 **커브·ikHandle·프록시 없이** 같은 종류의 파형을 만든다.

| 탭 | 내용 |
|----|------|
| **Sine** | (V01 과 동일) 어트리뷰트 하나에 위상만 밀린 싸인 |
| **Chain Wave** | (V01 과 동일) 커브 + ikSpline 으로 체인이 회전만으로 파형을 따라감 |
| **Chain Wave Lite** (신규) | **커브·ikHandle·프록시 없이** 각도만으로 같은 종류의 파형 |

세 탭 모두 **Output = `Node`** 를 고르면 드라이버 노드로 파형을 실시간 통제할 수 있고,
그 드라이버에는 **`windEnvelope` [0, 1]** 영향력 어트리뷰트가 붙는다(→ [7장](#7-envelope-영향력-0-1)).

- **버전**: `app/config/version.py` (v02.01)
- **위치**: `JUN_All/tools/A00390_WindTool_V02`
- **설치**: `__dragDrop_A00390_V02.py` 드래그&드롭 → 셸프 버튼 **`WindToolV2`**
- 근거·측정: [계획서](plans/A00390_ChainWave_no_ik_plan.md)

---

## 1. 왜 Lite 가 필요했나

기존 Chain Wave 는 체인마다 **커브 + ikSpline 핸들 + 프록시 조인트 체인**을 만든다.
방법 자체는 옳지만 개수가 붙는다 — mayapy 로 실제로 세어 본 값이다.

| 체인 길이 | 체인당 노드 | 루트 100개 환산 |
|-----------|-------------|-----------------|
| 조인트 5개 | 89 | 약 8,900 |
| 조인트 9개 | **141** | 약 **14,100** |
| 조인트 15개 | 219 | 약 21,900 |

아웃라이너에 커브 100개·ikHandle 100개가 쌓이는 것도 문제지만, **노드 14,000개**가
씬 평가에 더 부담이다.

## 2. Lite 는 무엇을 다르게 하나

**정의를 바꿨다.**

| | Chain Wave | **Chain Wave Lite** |
|---|---|---|
| 정의 | CV 를 밀어 만든 커브를 ikSpline 이 따라간다 | **뼈의 월드 방향각이 싸인파를 그린다** |
| 진폭의 뜻 | 미는 **거리**(월드 단위) | **흔들리는 각도(도)** |
| 만드는 것 | 커브 · ikHandle · 이펙터 · 프록시 조인트 · 매트릭스 노드 | **없음** (드라이버 + 조인트별 노드만) |

```
theta_k    = swing · ramp_k · sin( 2π( s_k/λ − phase ) )     ← 뼈 k 의 월드 각도
localRot_k = theta_k − theta_(k−1)                            ← 조인트 k 의 로컬 회전
```

`theta_k − theta_(k−1)` 이 핵심이다. FK 는 로컬 회전이 자손에 **누적**되므로, 차분을 넣으면
누적 결과가 정확히 `theta_k` 가 된다 — 체인이 말리지 않고 파형을 따라간다.
(Sine 탭에서 rotate 축을 골랐을 때 체인이 말려 들어갔던 이유가 이 차분을 안 했기 때문이다.)

**회전축**은 `체인 방향 × 진동축` 으로 구한 뒤 그 조인트의 **rotate 채널 공간**으로 옮긴다
(`world_axis × (jointOrient × parentWorld)⁻¹`). 기본축(±X/Y/Z)과 맞으면 채널에 직결하고,
아니면 `axisAngleToQuat → quatProd(rest) → quatToEuler` 를 쓴다. 그래서 **조인트 오리엔트나
rotateOrder 가 어떻든** 안전하다.

> 조인트든 **FK 컨트롤러**든 같은 경로로 처리한다. 기존 탭에서 컨트롤러 때문에 필요했던
> 프록시 체인이 통째로 사라진다.

## 3. 사용법

1. 체인을 리스트에 담는다(`Bone Chain` = 리스트가 한 체인 / `Bone Root` = 항목마다 체인 루트).
2. **Chain Wave Lite** 탭에서 `Sway Axis` 와 파라미터를 정한다.
3. **Build Chain Wave Lite**

드라이버 로케이터에 붙는 어트리뷰트를 라이브로 만지면 즉시 반영된다.

| 어트리뷰트 | 뜻 |
|-----------|-----|
| `windSwingAngle` | **뼈가 흔들리는 각도(도)**. 20 이면 끝 뼈가 ±20° |
| `windWavelength` | 한 파장의 월드 길이 |
| `windPeriod` | 한 주기의 프레임 수 |
| `windSpeed` | 재생 속도(적분되므로 키를 걸어도 위상이 뒤로 안 간다) |
| `windRootRamp` | 0 = 루트부터 같은 각도 · 1 = 루트 고정, 끝으로 갈수록 커짐 |
| `windPhaseOffset` | 그 체인만의 타이밍 차이 |
| `windEnvelope` | **영향력 [0, 1]** — 0 = 영향 없음 · 0.5 = 절반 · 1 = 완전 적용 |

`Chain Offset` 을 주면 체인 k 가 `windPhaseOffset = k × 값` 으로 시작해, 여러 체인이
한꺼번에 같은 모양으로 움직이지 않는다.

**Output**
- `Node` — 라이브 노드망
- `Curve` — 구간을 회전 키로 굽고 **셋업을 지운다**(씬에 남는 것이 아무것도 없다)

**Remove Chain Wave Lite** 는 이 탭이 만든 것만 지우고 회전을 rest 로 되돌린다.
기존 Chain Wave 셋업은 건드리지 않는다(세트가 다르다).

---

## 4. ⚠️ 기존 탭과 숫자가 호환되지 않는다

**같은 값을 넣어도 같은 그림이 나오지 않는다.** 진폭의 뜻이 다르기 때문이다(거리 ↔ 각도).
옮겨 올 때는 **눈으로 맞춰야 한다.**

기존 결과를 그대로 재현하려고 시도했다가 접었다. 커브의 접선각을 그대로 쓰면
**일관되게 과대**하다(조인트 9, 뼈 2.0, A 1.5, 파장 10에서 ikSpline `−25.5°` vs 접선식 `−39.7°`).
NURBS 커브가 CV 를 통과하지 않고 안쪽으로 당겨지기 때문인데, **그 비율이 파장에 따라 변한다.**

| 조건 | 실제 / 접선식 |
|------|---------------|
| 진폭 0.5 / 1.5 / 3.0 | 0.653 / 0.657 / 0.646 (**진폭엔 무관**) |
| 파장 6 / 10 / 20 | **0.411 / 0.657 / 0.745** |

상수 보정으로는 못 맞춘다. 그래서 재현 대신 **정의를 각도로 바꿔** 예측 가능하게 만들었다.

## 5. 무엇을 얻었나 (실측)

같은 체인(조인트 9, 뼈 2.0)에서:

| | Chain Wave | Chain Wave Lite |
|---|---|---|
| 생성 노드 | 141 | **95** (−33%) |
| 커브 | 1 | **0** |
| ikHandle · 이펙터 | 1 · 1 | **0 · 0** |
| 프록시 조인트 | 10 | **0** |

지켜지는 것은 그대로다 — **translate 불변 · 뼈 길이 유지 · 루트 고정**.
뼈 각도는 정의식과 최대 **0.015°** 차이인데, 16샘플 싸인 LUT 의 보간 오차다(20° 스윙의 0.07%).

## 6. 검증

`mayapy` (Maya 2024) 헤드리스 **36항목 통과** (코어 20 + UI 16).

- 커브 / ikHandle / 이펙터 / 프록시 조인트가 **하나도 생기지 않는지**
- 뼈 각도가 정의식과 일치하는지 · 뼈 길이 유지 · 루트 고정 · translate 불변
- `windSwingAngle` 2배 → 각도 2배, `windRootRamp` 0/1 동작
- 제거 후 잔여 노드 0 · 회전 rest 복귀
- **FK 컨트롤러 체인**(셰이프 달린 트랜스폼)에서도 프록시 없이 동작
- 기존 Chain Wave 와 **서로 간섭하지 않는지**(각자 remove)
- 굽기(Curve) 후 셋업 0 · 회전 키 존재
- 같은 체인에서 노드 수 비교(141 → 95)

> 헤드리스라 **뷰포트에서 실제로 어떻게 보이는지는 확인하지 못했다.**
> 기존 탭과 나란히 걸어 눈으로 비교해 볼 것.

## 7. Envelope (영향력) [0, 1]

세 탭(`Sine` · `Chain Wave` · `Chain Wave Lite`) 전부 **Output = `Node`** 로 만든 드라이버에
`windEnvelope` 어트리뷰트가 붙는다. 디포머의 `envelope` 과 같은 뜻이다.

| 값 | 결과 |
|----|------|
| `0` | 노드가 **아무 영향도 주지 않는다** (셋업이 없는 것과 같은 자세) |
| `0.5` | **절반**의 영향력 |
| `1` | **완전히** 적용 (기본값) |

UI 의 `Envelope` 스핀박스는 **빌드 시 초기값**이고, 만든 뒤에는 드라이버에서 직접 만지거나
**키를 걸 수 있다** — 진폭을 건드리지 않고 바람을 페이드 인/아웃 시키는 용도다.
`Sine` 탭의 스핀박스는 Node 전용이라 `Curve` 출력에서는 `Speed` 처럼 비활성된다.

### 구현 — 노드 하나로 끝난다

파형 값이 **진폭에 정비례**하므로 envelope 를 진폭에 **한 번만** 곱하면 그 아래 조인트·CV 가
전부 같은 비율로 줄어든다. 드라이버당 `multDoubleLinear` 1개 이상은 필요하지 않다.

| 탭 | 실효값 | 만드는 노드 |
|----|--------|-------------|
| Sine | `windAmplitude × windEnvelope` | `<드라이버>_ampEnvelope` |
| Chain Wave | `windAmplitude × windEnvelope` | `<드라이버>_ampEnvelope` |
| Chain Wave Lite | `windSwingAngle × windEnvelope` | `<체인>_liteSwingEnv` |

Chain Wave / Lite 는 이 노드도 제거용 세트에 들어가므로 **Remove 로 함께 지워진다.**

### ⚠️ 알아둘 것

- **범위는 마야가 강제한다.** `addAttr` 의 `minValue`/`maxValue` 때문에 `setAttr` 로 `1.5` 를
  넣으면 잘리는 게 아니라 **`RuntimeError` 가 난다**(`past its maximum value of 1`).
  툴이 넘기는 초기값은 파이썬에서 먼저 클램프하므로 UI 로는 이 에러를 볼 일이 없다.
- **Chain Wave 는 CV 변위가 정확히 절반이지, 회전각이 절반은 아니다.** ikSpline 이 커브를
  푸는 과정이 비선형이라 `0.5` 에서 조인트 회전 비율이 0.47~1.08 로 흩어진다(변위가 0 근처인
  조인트에서 특히 크게). "절반" 은 **파동의 세기**가 절반이라는 뜻이다.
  각도를 직접 다루는 **Lite 탭은 회전각까지 정확히 절반**이다.
- `0` 일 때 rest 자세로 정확히 돌아오는지는 세 탭 모두 실측했다 —
  Lite 는 `1e-8` 미만, Chain Wave 는 `0.000000`(1e-3 기준) 차이.

`mayapy` (Maya 2024) 헤드리스 **35항목 통과** (코어 21 + UI 14). 위 표의 값이 그 결과다.
