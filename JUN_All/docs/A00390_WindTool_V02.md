# A00390_WindTool_V02 사용법

`A00390_WindTool` 을 그대로 복제한 뒤 **Chain Wave Lite** 탭을 더한 버전이다.
루트가 100개를 넘는 상황에서 **커브·ikHandle·프록시 없이** 같은 종류의 파형을 만든다.

| 탭 | 내용 |
|----|------|
| **Sine** | (V01 과 동일) 어트리뷰트 하나에 위상만 밀린 싸인 |
| **Chain Wave** | (V01 과 동일) 커브 + ikSpline 으로 체인이 회전만으로 파형을 따라감 |
| **Chain Wave Lite** (신규) | **커브·ikHandle·프록시 없이** 각도만으로 같은 종류의 파형 |

세 탭 모두 **Output = `Node`** 를 고르면 드라이버 노드로 파형을 실시간 통제할 수 있고,
그 드라이버에는 **`windEnvelope` [0, 1]** 영향력 어트리뷰트가 붙는다(→ [7장](#7-envelope-영향력-0-1)).

- **버전**: `app/config/version.py` (v02.05)
- **위치**: `JUN_All/tools/A00390_WindTool_V02`
- **설치**: `__dragDrop_A00390_V02.py` 드래그&드롭 → 셸프 버튼 **`WindToolV2`**
- 근거·측정: [계획서](plans/A00390_ChainWave_no_ik_plan.md)

## 1. 왜 Lite 가 필요했나

기존 Chain Wave 는 체인마다 **커브 + ikSpline 핸들 + 프록시 조인트 체인**을 만든다.
방법 자체는 옳지만 개수가 붙는다 — mayapy 로 실제로 세어 본 값이다.

| 체인 길이 | 체인당 노드 | 루트 100개 환산 |
|-----------|-------------|-----------------|
| 조인트 5개 | 89 | 약 8,900 |
| 조인트 9개 | **141** | 약 **14,100** |
| 조인트 15개 | 219 | 약 21,900 |

아웃라이너에 커브 100개·ikHandle 100개가 쌓이는 것도 문제지만, **노드 14,000개**가
씬 평가에 더 부담이다.

## 2. Lite 는 무엇을 다르게 하나

**정의를 바꿨다.**

| | Chain Wave | **Chain Wave Lite** |
|---|---|---|
| 정의 | CV 를 밀어 만든 커브를 ikSpline 이 따라간다 | **뼈의 월드 방향각이 싸인파를 그린다** |
| 진폭의 뜻 | 미는 **거리**(월드 단위) | **흔들리는 각도(도)** |
| 만드는 것 | 커브 · ikHandle · 이펙터 · 프록시 조인트 · 매트릭스 노드 | **없음** (드라이버 + 조인트별 노드만) |

```
theta_k    = swing · ramp_k · sin( 2π( s_k/λ − phase ) )     ← 뼈 k 의 월드 각도
localRot_k = theta_k − theta_(k−1)                            ← 조인트 k 의 로컬 회전
```

`theta_k − theta_(k−1)` 이 핵심이다. FK 는 로컬 회전이 자손에 **누적**되므로, 차분을 넣으면
누적 결과가 정확히 `theta_k` 가 된다 — 체인이 말리지 않고 파형을 따라간다.
(Sine 탭에서 rotate 축을 골랐을 때 체인이 말려 들어갔던 이유가 이 차분을 안 했기 때문이다.)

**회전축**은 `체인 방향 × 진동축` 으로 구한 뒤 그 조인트의 **rotate 채널 공간**으로 옮긴다
(`world_axis × (jointOrient × parentWorld)⁻¹`). 기본축(±X/Y/Z)과 맞으면 채널에 직결하고,
아니면 `axisAngleToQuat → quatProd(rest) → quatToEuler` 를 쓴다. 그래서 **조인트 오리엔트나
rotateOrder 가 어떻든** 안전하다.

> 조인트든 **FK 컨트롤러**든 같은 경로로 처리한다. 기존 탭에서 컨트롤러 때문에 필요했던
> 프록시 체인이 통째로 사라진다.

## 3. 사용법

1. 체인을 리스트에 담는다(`Bone Chain` = 리스트가 한 체인 / `Bone Root` = 항목마다 체인 루트).
2. **Chain Wave Lite** 탭에서 회전축(`Sway Axis` 또는 `Rotate Axis (object)`, → [8장](#8-회전축을-정하는-두-가지-방법))과
   파라미터를 정한다.
3. **Build Chain Wave Lite**

드라이버 로케이터에 붙는 어트리뷰트를 라이브로 만지면 즉시 반영된다.

| 어트리뷰트 | 뜻 |
|-----------|-----|
| `windSwingAngle` | **뼈가 흔들리는 각도(도)**. 20 이면 끝 뼈가 ±20° |
| `windWavelength` | 한 파장의 월드 길이. **`Auto` 가 켜져 있으면 체인 길이가 들어간다** (→ [12장](#12-auto-period--체인-길이로-파장을-잡는다)) |
| `windPeriod` | 한 주기의 프레임 수 |
| `windSpeed` | 재생 속도(적분되므로 키를 걸어도 위상이 뒤로 안 간다) |
| `windRootRamp` | 0 = 루트부터 같은 각도 · 1 = 루트 고정, 끝으로 갈수록 커짐 |
| `windPhaseOffset` | 그 체인만의 타이밍 차이 |
| `windEnvelope` | **영향력 [0, 1]** — 0 = 영향 없음 · 0.5 = 절반 · 1 = 완전 적용 |

**`Auto`**(`Wavelength` 줄 오른쪽 체크박스, **기본 ON**) — 파장을 손으로 정하지 않고
**체인 길이**에서 받아 온다. 루트에서 끝까지 파형이 **딱 한 주기** 실린다
(→ [12장](#12-auto-period--체인-길이로-파장을-잡는다)).

**Debug Curve**(체크박스, 기본 ON) — 체인이 어떻게 흔들리는지 보여 주는 커브를 체인마다
하나 만든다. 표시 전용이라 아무것도 구동하지 않는다 (→ [10장](#10-debug-curve-흔들림을-눈으로-확인)).
로케이터와 커브는 각각 자기 그룹에 담긴다 (→ [11장](#11-아웃라이너-정리--로케이터-그룹--커브-그룹)).

`Chain Offset` 을 주면 체인 k 가 `windPhaseOffset = k × 값` 으로 시작해, 여러 체인이
한꺼번에 같은 모양으로 움직이지 않는다.

**Output**
- `Node` — 라이브 노드망
- `Curve` — 구간을 회전 키로 굽고 **셋업을 지운다**(씬에 남는 것이 아무것도 없다)

**Remove Chain Wave Lite** 는 이 탭이 만든 것만 지우고 회전을 rest 로 되돌린다.
기존 Chain Wave 셋업은 건드리지 않는다(세트가 다르다).

## 4. ⚠️ 기존 탭과 숫자가 호환되지 않는다

**같은 값을 넣어도 같은 그림이 나오지 않는다.** 진폭의 뜻이 다르기 때문이다(거리 ↔ 각도).
옮겨 올 때는 **눈으로 맞춰야 한다.**

기존 결과를 그대로 재현하려고 시도했다가 접었다. 커브의 접선각을 그대로 쓰면
**일관되게 과대**하다(조인트 9, 뼈 2.0, A 1.5, 파장 10에서 ikSpline `−25.5°` vs 접선식 `−39.7°`).
NURBS 커브가 CV 를 통과하지 않고 안쪽으로 당겨지기 때문인데, **그 비율이 파장에 따라 변한다.**

| 조건 | 실제 / 접선식 |
|------|---------------|
| 진폭 0.5 / 1.5 / 3.0 | 0.653 / 0.657 / 0.646 (**진폭엔 무관**) |
| 파장 6 / 10 / 20 | **0.411 / 0.657 / 0.745** |

상수 보정으로는 못 맞춘다. 그래서 재현 대신 **정의를 각도로 바꿔** 예측 가능하게 만들었다.

## 5. 무엇을 얻었나 (실측)

같은 체인(조인트 9, 뼈 2.0)에서:

| | Chain Wave | Chain Wave Lite |
|---|---|---|
| 생성 노드 | 141 | **95** (−33%) |
| 커브 | 1 | **0** |
| ikHandle · 이펙터 | 1 · 1 | **0 · 0** |
| 프록시 조인트 | 10 | **0** |

지켜지는 것은 그대로다 — **translate 불변 · 뼈 길이 유지 · 루트 고정**.
뼈 각도는 정의식과 최대 **0.015°** 차이인데, 16샘플 싸인 LUT 의 보간 오차다(20° 스윙의 0.07%).

## 7. Envelope (영향력) [0, 1]

세 탭(`Sine` · `Chain Wave` · `Chain Wave Lite`) 전부 **Output = `Node`** 로 만든 드라이버에
`windEnvelope` 어트리뷰트가 붙는다. 디포머의 `envelope` 과 같은 뜻이다.

| 값 | 결과 |
|----|------|
| `0` | 노드가 **아무 영향도 주지 않는다** (셋업이 없는 것과 같은 자세) |
| `0.5` | **절반**의 영향력 |
| `1` | **완전히** 적용 (기본값) |

UI 의 `Envelope` 스핀박스는 **빌드 시 초기값**이고, 만든 뒤에는 드라이버에서 직접 만지거나
**키를 걸 수 있다** — 진폭을 건드리지 않고 바람을 페이드 인/아웃 시키는 용도다.
`Sine` 탭의 스핀박스는 Node 전용이라 `Curve` 출력에서는 `Speed` 처럼 비활성된다.

### 구현 — 노드 하나로 끝난다

파형 값이 **진폭에 정비례**하므로 envelope 를 진폭에 **한 번만** 곱하면 그 아래 조인트·CV 가
전부 같은 비율로 줄어든다. 드라이버당 `multDoubleLinear` 1개 이상은 필요하지 않다.

| 탭 | 실효값 | 만드는 노드 |
|----|--------|-------------|
| Sine | `windAmplitude × windEnvelope` | `<드라이버>_ampEnvelope` |
| Chain Wave | `windAmplitude × windEnvelope` | `<드라이버>_ampEnvelope` |
| Chain Wave Lite | `windSwingAngle × windEnvelope` | `<체인>_liteSwingEnv` |

Chain Wave / Lite 는 이 노드도 제거용 세트에 들어가므로 **Remove 로 함께 지워진다.**

### ⚠️ 알아둘 것

- **범위는 마야가 강제한다.** `addAttr` 의 `minValue`/`maxValue` 때문에 `setAttr` 로 `1.5` 를
  넣으면 잘리는 게 아니라 **`RuntimeError` 가 난다**(`past its maximum value of 1`).
  툴이 넘기는 초기값은 파이썬에서 먼저 클램프하므로 UI 로는 이 에러를 볼 일이 없다.
- **Chain Wave 는 CV 변위가 정확히 절반이지, 회전각이 절반은 아니다.** ikSpline 이 커브를
  푸는 과정이 비선형이라 `0.5` 에서 조인트 회전 비율이 0.47~1.08 로 흩어진다(변위가 0 근처인
  조인트에서 특히 크게). "절반" 은 **파동의 세기**가 절반이라는 뜻이다.
  각도를 직접 다루는 **Lite 탭은 회전각까지 정확히 절반**이다.
- `0` 일 때 rest 자세로 정확히 돌아오는지는 세 탭 모두 실측했다 —
  Lite 는 `1e-8` 미만, Chain Wave 는 `0.000000`(1e-3 기준) 차이.

### 검증

`mayapy` (Maya 2024) 헤드리스 **35항목 통과** (코어 21 + UI 14). 위 표의 값이 그 결과다.

## 8. 회전축을 정하는 두 가지 방법

**Chain Wave Lite** 탭은 체인을 어느 축 둘레로 돌릴지 두 가지로 정할 수 있다.

| | `Sway Axis (world)` (기본) | `Rotate Axis (object)` (신규) |
|---|---|---|
| 회전축 | `체인 방향 × 월드 축` 으로 **계산한 월드 축** | 노드가 **자기 오브젝트 축** 하나 (X/Y/Z) |
| 쓰는 채널 | 세 `rotate` 채널 전부 (축이 기울면) | **고른 채널 하나만** |
| 조인트 orient | 결과가 orient 와 **무관** | orient 를 **그대로 따른다** |
| 만드는 노드 | 노드당 최대 3개(`axisAngleToQuat`/`quatProd`/`quatToEuler`) | 노드당 1개(부호 곱셈) |

`Rotate Axis (object)` 체크박스를 켜면 위의 `Sway Axis` 콤보는 **비활성되고, 계산에서도 완전히
빠진다**(월드 축을 아예 구하지 않는다). 실측으로 확인한 것 —

- `Sway Axis` 를 X/Y/Z 어느 것으로 바꿔도 결과 회전값이 **완전히 동일**했다.
- 고른 축의 `rotate` 채널 **하나에만** 연결이 들어가고 나머지 둘은 비어 있다
  → 애니메이터가 남은 두 축을 계속 쓸 수 있다.
- 비스듬한 체인(조인트 9)에서 노드 수가 **102 → 84** 로 줄었다(쿼터니언 경로가 사라져서).

### ⚠️ 언제 쓰면 안 되나

`theta_k − theta_(k-1)` 차분이 **월드 각도로 정확히 누적되려면 체인의 노드들이 같은 방향으로
orient 돼 있어야 한다.** 보통의 조인트 체인·FK 컨트롤러 체인은 그렇다. 축이 노드마다 제각각인
체인에 쓰면 파형이 아니라 "각자 자기 축으로 흔들리는" 그림이 된다 — 그때는 `Sway Axis` 를 쓴다.

> `Curve` 출력(굽기)에도 똑같이 적용된다. 어느 쪽으로 만들었든 구운 결과는 회전 키다.

### 곁가지로 고친 것

월드 축 경로는 축이 로컬 기본축과 어긋나면 `axisAngleToQuat` / `quatProd` / `quatToEuler` 를
만드는데, 이 노드들은 **`quatNodes` 플러그인 소속**이다. 플러그인이 안 올라와 있으면
`createNode` 가 `No object matches name` 으로 죽는다(헤드리스에서 실제로 만났다).
이제 이 경로에 들어가기 전에 `loadPlugin("quatNodes", quiet=True)` 로 확실히 올린다.

## 9. 드라이버 로케이터를 체인 최상단에 놓고 **따라가게** 하기

`Output = Node` 로 만드는 드라이버 로케이터는 예전에는 **항상 월드 원점**에 생겼다. 체인이
원점에서 멀면 어느 로케이터가 어느 체인의 것인지 찾기 어렵고, 여러 개가 원점에 겹쳐 쌓였다.

**`Place driver at chain root (follow)`** 체크박스(**기본 켜짐**)를 켜면 드라이버를 그 체인
**최상단 노드(루트 본/컨트롤러)의 월드 위치**에 만들고, 그 자리를 **계속 따라간다**.
세 탭 전부(`Sine` · `Chain Wave` · `Chain Wave Lite`)에 있고, `Curve` 출력에서는 셋업이
지워지므로 **비활성**된다.

- `Bone Root` 모드에서는 **루트마다 드라이버가 하나씩** 생기므로, 각자 자기 루트를 따라간다.
- 로케이터는 **어트리뷰트를 담고 있을 뿐**이라 위치가 결과에 영향을 주지 않는다.
  따라가게 하는 것은 **찾기 쉬우라고** 하는 것이다 — 캐릭터를 씬에서 옮기거나 루트
  컨트롤러를 움직여도 드라이버가 뼈 위에 그대로 붙어 있다.

### 어떻게 따라가나 (constraint 없음, 위치만)

```
multMatrix( root.worldMatrix[0] , driver.parentInverseMatrix[0] )
    → decomposeMatrix.outputTranslate → driver.translate
```

- **constraint 를 쓰지 않는다.** 월드 행렬을 드라이버의 부모 공간으로 되돌려
  `translate` 에 그대로 넣는다. 드라이버당 노드 **2개**.
- **위치만이다.** `driver.rotate` 는 연결하지 않는다 — 루트를 회전시켜도 로케이터는 안 돈다.
- 루트 조인트 이동 · 루트 컨트롤러 이동 · **리그 그룹째 이동** 셋 다 따라온다(실측 오차 `< 1e-6`).

### ⚠️ 손으로 옮길 수 없게 된다

`translate` 가 구동되므로 드라이버를 **손으로 옮길 수 없다**. 원래도 위치는 결과에 아무
영향이 없는 "어트리뷰트 홀더" 였으니 잃는 것은 없다. 예전처럼 자유롭게 두고 싶으면
체크를 **끄면** 된다(원점에 생기고 따라가지도 않는다).

### 왜 사이클이 안 나나

`worldInverseMatrix` 를 쓰면 드라이버 **자신의** translate 를 읽어 진짜 사이클이 된다.
**`parentInverseMatrix`** 는 **부모**의 월드 역행렬이라 자기 translate 에 의존하지 않는다.

드라이버 `wind*` → … → `root.rotate` → `root.worldMatrix` → `driver.translate` 경로도
`driver.translate` 로 되돌아오지 않으므로 **닫히지 않는다**.

사이클이 되는 배치는 **하나뿐**이다 — 드라이버가 root 의 **조상**인 경우.
그때는 **연결하지 않고** 로그에 사유를 남긴다:

```
Root-follow skipped (would cycle): <root> (driver is an ancestor of the root)
```

### 검증

`mayapy` (Maya 2024) 헤드리스 — 축/배치 24 + 6 항목(v02.02), 추종·그룹 **코어 43 + UI 22 항목**(v02.04).
`cycleCheck` 가 빌드 직후 · 이동 후 · 컨트롤러 체인 전부에서 **비어 있고**, 씬에 `constraint`
노드가 **0개**임을 확인했다.

## 10. Debug Curve (흔들림을 눈으로 확인)

`Chain Wave Lite` 는 각도만 다루기 때문에 "지금 이 체인이 어떤 파형을 그리고 있는지" 가
눈에 잘 들어오지 않는다. **`Debug Curve`**(기본 ON)를 켜면 체인마다 커브를 하나 그려 준다.
조인트 체인이든 **FK 컨트롤러 체인**이든 똑같이 동작한다.

**Chain Wave 탭이 만드는 커브와 같은 방식**이다 — 체인 노드 위치를 CV 로 하는 **degree 3
NURBS**, CV k ↔ 체인 노드 k. 다른 것은 **구동 방향뿐**이다.

| | Chain Wave | **Chain Wave Lite 의 Debug Curve** |
|---|---|---|
| 방향 | 커브가 ikSpline 으로 체인을 **구동** | 체인이 움직이고 커브가 **따라감** |
| 역할 | 리그의 일부 | **표시 전용** (아무것도 구동 안 함) |
| 선택 | 보통 커브 | 셰이프가 `reference` — 뷰포트에서 **안 잡힌다** |
| CV 수 | 노드 수 **+1** (ikSpline 가상 조인트) | 노드 수 |

```
CV k  ←  multMatrix( node_k.worldMatrix , curve.worldInverseMatrix )
         → decomposeMatrix.outputTranslate → controlPoints[k]
```

`worldInverseMatrix` 로 커브의 오브젝트 공간으로 되돌리므로 **커브나 그 부모를 옮겨도 CV 는
조인트에 그대로 붙어 있다.** `worldInverseMatrix` 는 CV 에 의존하지 않아 **사이클이 없다**(실측).
`Remove Chain Wave Lite` 로 셋업과 함께 지워진다.

### 왜 "Chain Wave 가 만들었을 커브" 를 계산해 그리지 않나

두 모드는 **값이 같지 않다**(§4). 진폭의 뜻이 거리 ↔ 각도이고, 실제/접선식 비율이 파장에 따라
0.41~0.75 로 변해 **상수 보정이 불가능**하다. 그 커브를 계산해 그리면 **실제 흔들림과 다른
그림**을 보여 주게 되어 디버그용으로 오히려 해롭다. 지금 방식은 **실제 결과**를 그린다.

### ⚠️ Chain Wave 의 커브보다 CV 가 하나 적다

조인트 9개 체인에서 **Lite 9 CV / Chain Wave 10 CV** 다. Chain Wave 는 커브를 **프록시
체인**에서 만드는데, ikSpline 이 엔드 이펙터를 필요로 해 끝에 **가상 조인트(dummy tip)** 를
하나 더 붙이기 때문이다. 디버그 커브는 실제 노드만 그리므로 그 하나가 없다.

### 검증

`mayapy` (Maya 2024) 헤드리스 **33항목 통과** (코어 26 + UI 7). 5개 프레임에서 **모든 CV 가
체인 노드 위에 오차 `0.00000000`** 으로 놓였고, 사이클 없음 · 하류 연결 없음 · Remove 후 잔여 0 ·
체크 OFF 면 `nurbsCurve` 0개 · Bone Root 3개 → 커브 3개 · FK 컨트롤러 체인도 동일.
v02.04 에서 **리그를 통째로 옮긴 뒤에도** CV 오차가 `0.0000000000` 임을 다시 확인했다.

## 11. 아웃라이너 정리 — 로케이터 그룹 / 커브 그룹

`Chain Wave Lite` 는 예전에는 체인마다 `(드라이버 로케이터, 디버그 커브)` 를 이어서 만들어,
아웃라이너에 **로케이터 · 커브 · 로케이터 · 커브 …** 로 번갈아 쌓였다. 루트가 수십 개면
읽을 수가 없다.

이제 빌드 하나가 그룹 **둘**을 만들고, 종류별로 나눠 담는다.

| 그룹 | 담는 것 |
|------|---------|
| `<prefix>_liteDriverGrp` | 드라이버 로케이터 전부 |
| `<prefix>_liteCurveGrp` | 디버그 커브 전부 |

- `<prefix>` 는 빌드에 쓴 prefix(기본 `chainWaveLite`)다. 여러 번 빌드하면 `…Grp1`, `…Grp2` 로
  번호가 붙어 **서로 섞이지 않는다**.
- **`Debug Curve` 를 끄면 커브 그룹은 아예 만들지 않는다.**
- 두 그룹 모두 제거 세트에 들어가 **`Remove Chain Wave Lite` 로 함께 지워진다**
  (prefix 별로 자기 것만 지운다).

### 그룹은 원점·단위행렬로 둔다

`parent -relative` 로 옮긴다. 이유가 둘이다.

1. 그룹이 단위행렬이라 로컬을 그대로 둬도 **월드 위치가 변하지 않는다**.
2. 이 시점에 드라이버의 `translate` 는 이미 **연결**돼 있다(§9). 기본 `parent` 는 월드 위치를
   유지하려고 `translate` 를 setAttr 하는데, **연결된 채널에는 쓸 수 없다.**

> 그룹을 나중에 옮겨도 결과는 같다. 드라이버는 `parentInverseMatrix`, 디버그 커브는
> `worldInverseMatrix` 로 부모 변환을 각각 상쇄하기 때문이다.

### 검증

`mayapy` (Maya 2024) 헤드리스 **코어 43 + UI 22 항목** + 이중 빌드 스모크 테스트 통과 —
그룹이 각각 1개씩, 각 그룹에 **자기 종류만** 3개씩, 아웃라이너 최상위에 흩어진
로케이터·커브 **0개**, `Debug Curve` OFF 면 커브 그룹 없음,
prefix 가 다른 두 빌드를 따로 `Remove` 해도 서로 건드리지 않음.

## 12. Auto Period — 체인 길이로 파장을 잡는다

`Chain Wave Lite` 탭 `Wavelength` 줄 오른쪽의 **`Auto`** 체크박스(**기본 ON**).

예전에는 `Wavelength` 에 적어 넣은 숫자를 **모든 체인이 그대로** 썼다. 그래서 체인이 길든
짧든 파형의 주기가 같았고, 짧은 체인에는 파형이 반 토막만, 긴 체인에는 몇 주기가 실렸다.

`Auto` 를 켜면 체인마다 **그 체인의 길이**가 `windWavelength` 로 들어간다.

```
u_k   = s_k / lambda - t          (s_k = 루트에서 노드 k 까지의 누적 거리)
theta = swing * ramp_k * sin(2pi * u_k)

lambda = (체인 전체 길이)
  -> s_k/lambda 가 루트에서 0, 끝에서 정확히 1
  -> 체인 위에 파형이 딱 한 주기 (최댓값 한 번 · 최솟값 한 번)
```

- 켜면 `Wavelength` 스핀박스는 **비활성**된다(쓰이지 않는 값이라).
- 파장은 여전히 드라이버의 **라이브 어트리뷰트**다. `Auto` 는 그 **시작값**만 정한다 —
  빌드 뒤에 `windWavelength` 를 만지면 그대로 바뀐다.
- 길이가 제각각인 체인을 한꺼번에 빌드해도 **각자 자기 길이에 맞는 파장**을 받는다.
- 결과 로그에 실제로 쓴 파장 범위가 찍힌다:
  `Auto Period on: windWavelength = each chain's own path length (8-11) ...`

### "체인의 길이" 는 경로 길이다 (직선 거리가 아니다)

루트와 끝의 직선 거리가 아니라 **노드를 따라 걸어간 거리**를 쓴다
(`wave_manager._arc_positions` 의 누적 거리). 파형의 위상도 같은 누적 거리 `s_k` 로 매기므로,
**굽은 체인이면 굽은 길이 그대로 한 주기**가 된다.

`(0,0,0) → (3,0,0) → (3,4,0) → (3,8,0)` 체인이면

| | 값 |
|---|---|
| 직선 거리 | `sqrt(3² + 8²)` = 8.544 |
| **경로 길이 (쓰는 값)** | `3 + 4 + 4` = **11.0** |

실측으로 이 체인의 드라이버는 `windWavelength = 11.0` 을 받는다.

### 실측 — 정말 한 주기인가

조인트 9개(앞 3칸은 X 로 2씩, 뒤 5칸은 Y 로 2씩 꺾인 체인, 경로 길이 16),
`windRootRamp = 0`, 프레임 0 에서 각 노드의 사인 값:

| | 루트 → 끝 |
|---|---|
| **Auto ON** (λ=16) | `-0.259 +0.499 +0.965 +0.866 +0.259 -0.499 -0.965 -0.866 -0.259` |
| Auto OFF (λ=10) | `-0.259 +0.838 +0.776 -0.359 -0.999 -0.259 +0.838 +0.776 -0.359` |

Auto ON 은 최댓값(**+0.965**)과 최솟값(**-0.965**)이 각각 한 번씩 나오고 **양끝 값이 같다**
— 정확히 한 주기다. OFF 는 파장이 고정이라 1.6 주기가 실린다.
